## Registers: what retail's callers use, and what the emitted body keeps

* `0x0041C290`'s only caller is the naked body at `0x417AD3` in
  `src/game/stage_entry.cpp`: `call 0x41c290`, result in EAX, no argument
  register, plain `ret`. The emitted body is `__cdecl`, argument-free, returns
  in EAX: **kept**. No entry register is live-in (the body starts
  `push esi; push 45Ch; call ??2@YAPAXI@Z`).
* The body keeps the manager in **ESI** for its whole life, parks it in **EBX**
  for the registration call (`push ebx; mov ebx,esi; call; test eax,eax;
  pop ebx; je`) and uses **EDI** for the `rep stosd` clear: **kept**.
* `0x0041C120` receives the manager in **EBX** — the *declaration* is a plain
  `__stdcall(RawManager_0041c290 *)`, so the register is chosen by the
  whole-program pass, not by the source. It keeps the callback under
  construction in **ESI** and the registration priority in **EDI** and returns
  the status in EAX: **kept**.
* `0x0041C030` receives the object in **EDX** with ECX *unused*. That is why it
  is co-compiled: as an external declaration the caller must materialise the
  dead ECX argument (`xor ecx,ecx`, +2 bytes) or use a one-argument prototype
  (`lea ecx,[esi+10h]`, 1 byte wrong). With the callee visible the pass drops
  the dead argument and emits retail's `lea edx,[esi+10h]; call` verbatim.
* The three asm callers of `0x41C030` that are not recovered yet
  (`0x41C104` in `unassigned_0041c0d0.cpp`, `0x41C5B4`, `0x41C684`) call it at
  its address with EDX only; they reference the alias
  `_asm_ScoreObject_Initialize_0041c030`, which the manifest still binds to
  `0x0041C030`, so they keep working unchanged.

## Shapes tried before the merge

1. **Plain translation unit** (`src/game/object_factories.cpp` alone).
   Measured 88 bytes against 91. Emitted `push esi; call` for the
   registration call where retail has `push ebx; mov ebx,esi; call … pop ebx`,
   and `lea ecx,[esi+10h]` where retail has `lea edx,[esi+10h]`. The 3-byte
   extent error is the EBX convention; the register error is the dead ECX slot.
   No MSVC declaration can put a first argument in EBX, and no declaration can
   put the only argument in EDX while leaving ECX alone (tested
   `__fastcall(void*, self)`, `__fastcall(self)`, `__stdcall(self)`,
   `__thiscall` member, and `__fastcall` with a floating first parameter).
2. **Merge into the scheduler cluster** — the shape that landed
   `0x4055C0`/`0x4056B0`/`0x41AD90`. The EBX and ESI/EDI agreements and the
   `TextLog::Append` ECX+varargs convention are all derived by the pass because
   those callees are co-compiled in the same link; `0x41C030` was the one
   remaining external, so the cluster build came out 137 bytes for `0x41C120`
   (missing the `+0x434` store, my model bug, fixed) and 91 bytes for the
   factory with a single wrong `lea` register.
3. **Carve `0x41C030` into its own unit and co-compile it** — the model is moved
   verbatim out of `src/game/score.cpp` into
   `src/game/score_object_initialize_0041c030.cpp` (the same operation
   `matching2/tools/waves/carve_cluster_regions.py` performs for cluster-bound
   regions). Its declared ABI in the source is unchanged, so its symbol and
   every alias stay the same; the pass now drops the dead ECX argument at the
   call site and the region itself still emits its 98 retail bytes.
