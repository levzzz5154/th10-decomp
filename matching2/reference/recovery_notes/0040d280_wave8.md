## The load-bearing model details

The receiver in **EBX** is a whole-program agreement, not a declaration: the host
is live across the parser construction, the parser's virtual call and both
scheduler registrations, while the node under construction takes ESI and the
registration priority EDI — so the pass hands the first declared argument of a
plain `__stdcall(MessageHost *, int)` the only callee-saved register left, EBX,
and keeps the script name (the second argument) on the stack with `RET 4`.
Because `0x0040D280` is co-compiled with `scheduler_tasks.cpp` (already in this
cluster), those two registration bodies keep their retail ESI/EDI receivers.

Four details are load-bearing; each was measured by variant sweep:

1. **`new T` with an inlinable constructor** produces retail's
   `mov reg,result / jmp / xor reg,reg` join at all three allocation sites, and
   the constructor's object stays in EAX/EDX as retail. Hand-written
   `operator new` plus `if (ptr)` emits no join instead (321 bytes, 51 differing).
2. **The parser's two dead tail stores** must go through a pointer local
   (`unsigned int *tail = (unsigned int *)((char *)this + 0x1090); tail[0] = 0;
   tail[1] = 0;`) ahead of the inlined `memset`; the member form lets the
   scheduler sink the second store behind the `rep stosd` setup (40 -> 54
   differing).
3. **The callback node's flag clear needs `_ReadWriteBarrier()`** between the read
   (`unsigned int previous = flags;`) and the clear (`flags = previous & ~1u;`):
   without it the scheduler hoists the `and` onto the load, with it the mask stays
   next to its store exactly as retail. That single intrinsic is what took the
   region from 18 differing bytes to 0. It is declared by hand
   (`extern "C" void _ReadWriteBarrier(void); #pragma intrinsic(...)`) because
   this toolkit ships no `<intrin.h>`.
4. **`update_node_008`, `draw_node_00C` and `timer_flags_050` are `volatile`.**
   Retail stores the draw node before reloading the timer flags word; without the
   qualifiers the scheduler sinks the store (18 -> 6 bytes of delta).

## 0x0040D530 `FUN_0040d530` — model drafted, not landable yet

The model (`/tmp/EnemyPair/best_d530.cpp`, reproduced below) is a member function
`EnemyManager_0040d530::Destroy` compiled inside a **merged cluster** that also
carries the animation-manager cluster
(`layout/ltcg/animation_manager_mark_resource_for_removal_004493e0.json`, five
functions) and `layout/ltcg/bullet_entity_release_resource_0040d680.json` (one
function) — the two clusters that own the EDI/ESI receivers its inlined body
calls into. In that link the receiver really does arrive in EAX (`mov edi,eax` is
emitted), and **all six dependency functions stay byte-exact** (0 differing):

```text

0 diffs  AnimationManager_ClearResourceSlot    0 diffs  BulletEntity_ReleaseResource
0 diffs  AnimationResource_Release             0 diffs  AnimationManager_MarkResourceForRemoval
```

The model's extent is exactly 300 bytes (declared 300) with **244 differing
bytes**, in five groups: `0x00-0x7F` (125), `0xA4` (1), `0xAA-0xDD` (49),
`0xE3-0x11A` (56), `0x11E-0x12A` (13). The instruction-level deltas are:

* **The function reserves no stack slot.** Retail opens `push ecx / push ebx /
  push ebp / push esi / push edi` because its slot-clear loop counter (4) is
  spilled to `[esp+0x10]`; this model has no spilled local, so the prologue is one
  byte short and everything after shifts — that alone is most of the first group.
* **The two remove blocks are not symmetric.** Retail loads the second node into
  ESI and the scheduler into EBX, exactly like the first block; this model's
  second block comes out with the node in EBX and the scheduler in ESI.
* **`blocks_054 = 0` is scheduled after the `data_00474ca0` test** here
  (`mov cl,BYTE PTR ds:0x474ca0; test cl,0x9`) where retail tests the memory
  operand first and stores an immediate `mov [edi+0x54],0`.
* **The slot-clear loop is strength-reduced differently.** Retail keeps the index
  in EBP (`mov ebp,9`), a byte cursor in EBX (`mov ebx,0x3ad090`), the manager in
  ECX reloaded per iteration, a trip counter of 4 in the reserved slot, and
  materialises the slot address (`lea esi,[ebx+ecx]`) before re-reading it for
  the free. This model keeps the byte offset as the induction variable and folds
  the array base into the addressing mode (`mov edi,[edx+esi+0x3ad06c]`), which
  removes the trip counter and with it the reserved slot. Making
  `data_00491c10` `volatile` removes the loop-invariant manager hoist and brings
  the extent to exactly 300 — the current best shape.
* One reload survives at `0xAA`: this model re-reads `[edi+0x54]` for the `free`
  call where retail pushes the live ESI.
