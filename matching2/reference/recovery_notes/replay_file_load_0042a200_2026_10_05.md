# 0x0042A200 replay file load (recovered 2026-10-05)

`src/game/replay_file_load_0042a200.cpp` compiles to the retail 450 bytes in
the `replay_file_load_0042a200` cluster (real archive loader, decrypter and
shared-file reader bodies, so name-in-EAX, key-in-AL and size-in-EDI appear by
themselves; manager in ESI). `make` and `make EXACT=1` pass.

Two source facts were needed beyond the straightforward model:

* **Header checks are two `if`s.** `if (magic != M || version != 5) { close;
  return -1; }` puts the failure block after the success path. Two separate
  checks with identical bodies are tail-merged in place, in front of the
  success path, and the earlier `return -1`s join that block as in retail.
* **The unpacked size is a named local.** `int size = header->size;
  data = malloc(size);`. With `malloc(header->size)` the argument is an
  expression temporary and takes a slot of the temporaries' register rotation
  (EAX, ECX, EDX in turn); every later header reload is then one register
  further on (ECX/EDX where retail has EAX/ECX) and the scheduler hoists the
  reload above the `data` store. A named local is allocated separately and
  leaves the rotation alone.

Tools: `scratchpad/vary.py`-style variant runner over `probe.py`, scheduler
trace of the cluster link (the node sequence numbers showed the store already
preceded the reload, so the residual was register choice, not ordering).
