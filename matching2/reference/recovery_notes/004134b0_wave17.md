## The source — `src/app/fps_counter.cpp` (the whole file; it owns this one region)

```cpp
// 0x004134B0..0x004135C8 (280 bytes): FrameRateCounter::Update.
//
// The counter's per-frame update: clamp the timer delta that
// 0x00439540 `FrameTimer_GetDelta` reports, refuse the frame when less than half
// a second of it elapsed, turn the frame interval into a frame rate, and adjust
// the frame-skip bookkeeping when the rate leaves the 57/65 Hz band.
//
// The counter object arrives in ESI - the dispatcher 0x004135D0 marshals it with
// `mov esi,edi` before the call and overwrites ESI immediately after - which only
// the whole-program pass of a native /LTCG link can select, so this body is a
// single-function cluster (layout/ltcg/fps_counter_004134b0.json).
//
// Three measured shape levers, not recovered style:
//
//   * `__declspec(align(8)) float rate` is the construct that makes MSVC frame
//     this function with `and esp,-8` and a 4-byte 8-aligned local (`push ecx`).
//     The value still lives in an x87 register - the frame slot is never read -
//     so the lever costs no instruction.
//   * the stall guard is spelled `if (delta >= 0.5) { ... return 1; }` with the
//     shared `return 1;` after it. That is the only spelling of the guard that
//     puts its exit block out of line at the end of the function, where retail
//     jumps to it with `test ah,1; jne 0x4135BC` (the natural `if (delta < 0.5)
//     return 1;` inlines the exit and emits the inverted `test ah,5; jp`, four
//     bytes short).
//   * the frame-event counter is cleared inside the `== 4` arm as well as in the
//     `else` arm, so the two arms keep their own timer snapshot. Written with a
//     single `else` the compiler merges the two identical snapshot tails into
//     one and the body shrinks by 15 bytes.

extern "C" double __cdecl FrameTimer_GetDelta(void);   // 0x00439540

// Frame timer state the counter resets (see src/app/frame_clock.cpp for the
// routines that own it).
extern "C" long long data_00492508;   // 0x00492508  QPC ticks per second
extern "C" double data_00492528;      // 0x00492528
extern "C" double data_00492530;      // 0x00492530
extern "C" double data_00492538;      // 0x00492538
extern "C" double data_00492540;      // 0x00492540

// The slot owner whose flags gate the accounting below; the same object
// src/game/fun_004065c0_004065c0.cpp names RecoverySlotOwner_004065c0.
struct RecoverySlotOwner_004134b0 {
    unsigned char pad_00[0x58];
    unsigned int field_58;  // +0x58
};
extern "C" RecoverySlotOwner_004134b0* data_00477810;  // 0x00477810

// 4-byte packing is what puts the two doubles at +0x24/+0x2C: their retail
// offsets are 4 mod 8.
#pragma pack(push, 4)
struct FrameRateCounter_004134b0 {
    unsigned char pad_0000[0x14];
    double time_last;          // +0x14  clamped timer sample
    int frame_events;          // +0x1C  consecutive high-rate frames
    unsigned int frame_count;  // +0x20  game frames inside the interval
    double measured;           // +0x24
    double budget;             // +0x2C
    float fps;                 // +0x34
    __declspec(noinline) int Update();
};
#pragma pack(pop)

#pragma code_seg(".text$01update")
int FrameRateCounter_004134b0::Update() {
    double now = FrameTimer_GetDelta();
    if (now < time_last)
        time_last = now;                 // the clock went backwards: resync
    double delta = now - time_last;
    if (delta >= 0.5) {
        time_last = delta + time_last;
        __declspec(align(8)) float rate = (float)((double)frame_count / delta);
        fps = rate;
        if (rate > 65.0f) {
            if (++frame_events == 2) {
                data_00492530 = data_00492528 = data_00492538 = data_00492540 =
                    FrameTimer_GetDelta();
            } else if (frame_events == 4) {
                data_00492508 = 0;       // give up on the performance counter
                data_00492530 = data_00492528 = data_00492538 = data_00492540 =
                    FrameTimer_GetDelta();
                frame_events = 0;
            }
        } else {
            frame_events = 0;
        }
        if (data_00477810 != 0) {
            if ((data_00477810->field_58 & 0x14) == 0) {
                budget = budget + 60.0;
                if (fps > 57.0f)
                    measured = measured + 60.0;
                else
                    measured = fps + measured;
            }
            data_00477810->field_58 &= ~0x80u;
        }
        frame_count = 0;
        return 1;
    }
    return 1;
}
#pragma code_seg()
```

## The levers, measured

All numbers are the emitted function against retail's 280 bytes, through the
cluster (the plain-flag micro-TU oracle was used only to *find* the constructs,
0.3 s a shape, and agreed with the cluster on every shape it was asked about).

| shape | emitted | differing | what broke |
| --- | ---: | ---: | --- |
| natural reading, `if (delta < 0.5) return 1;`, `float rate` local, one `else` | 238 | 269 | no frame, EDI shrink-wrapped, guard exit inlined, the two snapshot arms tail-merged |
| + `frame_events = 0;` inside the `== 4` arm | 265 | 272 | the two arms keep their own snapshot; frame and guard still wrong |
| + `__declspec(align(8)) float rate` (frame) | 276 | 241 | prologue, EDI save, body and both returns now retail's; only the guard's branch/exit differ (first difference `0x4134D7`) |
| + guard wrapped as `if (delta >= 0.5) { …; return 1; } return 1;` | **280** | **0** | — |

The `frame_events = 0;` in the `== 4` arm is a *block-structure* lever, and the
largest of the three: with a single `else` the two
`FrameTimer_GetDelta`-plus-four-stores arms are byte-equal, so the backend merges
them into one and the second arm becomes a jump back to the first (retail keeps
both copies), which is worth **27 bytes** (238 → 265 on the unframed body). It is
the same "the two arms must stay distinct" effect lever 5/6 of the contract
records for other regions.

The frame lever is the `__declspec(align(8))` local the repository already knows
from `0x0044A190`'s reconnaissance note. On this body nothing else produces it:
a plain `double`/`float`/struct local, `volatile`, an address-taken local, and
the plain build all leave the function frameless, and the pass then saves EDI
mid-body instead of in the prologue. With the aligned local present, MSVC emits
retail's `push ebp; mov ebp,esp; and esp,-8; push ecx; push edi` even though the
frame slot is never read.

The guard lever is a **block-placement** decision, the class wave 15/16 hit on
`0x0042A3E0`. Screened through the micro oracle over eight spellings
(`if (delta < 0.5) return 1;`, `if (0.5 > delta)`, `if (!(delta >= 0.5))`,
braced, through a `bool` local, `switch`, a double test, and the wrapped form):
only the wrapped form emits retail's `test ah,1; jne` to an **out-of-line** exit
block at the end; every other spelling emits the inverted `test ah,5; jp` with
the exit inline. The wrapped form also reproduces retail's shared `frame_events =
0` block at `0x00413565` (reached both by the `rate <= 65` branch and by
fall-through from the `== 4` arm).

## Did the brief's rules predict the codegen?

Partly, and the part they covered they covered *first time*, with no permutation
search — which is exactly what the ticket asked for:

* **The x87 sum rule predicted all three sums.** `measured = fps + measured` is
  retail's `flds 0x34(%esi); faddl 0x24(%esi)` (left operand loaded first, right
  operand as the memory operand); `budget = budget + 60.0` is
  `fldl 0x2c(%esi); faddl 0x470bb0`; `time_last = delta + time_last` is
  `fld st(0); faddl 0x14(%esi); fstpl 0x14(%esi)` (the left operand is the live
  register, so it is duplicated). Writing each with the memory operand on the
  right produced retail's order on the first build of that block — the boundary
  wave 14 measured (`(X + Y) + Z` ascending offsets, linear sums `last, first,
  middle`, source order only as a subtraction's left operand) never came into
  play because none of these is a three-term chain.
* **The pooled-literal rule predicted the constants.** The wave-10 note's rule —
  alias the compiler's `__real@` symbol, never declare an `extern` global — is
  what the layout does; all five literals (`0.5` double, `60.0` double, `2^32`
  double from the `unsigned int` conversion, `57.0f` and `65.0f`) came out as
  retail's own pool slots, mixed precision included, with no `constants` entry.
* **The wave-10 "read it back as a plain lvalue" rule predicted the fps field.**
  `fps = rate;` with the comparison on the local gives retail's
  `fsts 0x34(%esi)` (store, no pop) followed by `fcomps 0x470bb8` on the register
  copy; reading the field back instead, or comparing the double quotient against
  a promoted `65.0` double, moves the constant into the double pool and loses the
  `fsts` shape.
* **What the rules did not predict, and what cost the search:** the *aligned
  frame* (present in neither note — the joystick reconnaissance note has it for a
  local array, not for a scalar) and the *guard's block placement* (the note's
  class of "return-block placement", measured rather than derived), plus the
  tail-merge that the second `frame_events = 0;` suppresses. Each of those was a
  whole-body **+4 / +27 / +42**-byte effect (guard, snapshot arms, both together),
  and each was found by shape screening, not by reading the disassembly harder.

## What this unblocks

* The region: 280 bytes move from `asm` to `semantic`
  (`semantic` 587 → 588 regions, `asm` 1998 → 1997 at the time of landing).
* `0x004135D0` (180 bytes, `src/app/fun_004135d0_004135d0.cpp`) is the only
  caller and stays asm, but it is no longer blocked by an *opaque* callee: its
  call site `push?; mov esi,edi; call 0x004134B0` is now a real body the pass can
  see, so a future cluster for it (its own receiver is in EDI, another private
  convention) can derive the `counter in ESI` convention from the definition
  instead of declaring it — the same mechanism wave 12/13/14 used for the
  dispatcher's cases. Its ESI save/restore (`push esi` at `0x004135D3`,
  `pop esi` at `0x0041367F`) is exactly why this callee must not push ESI.
* Nothing else: the region has no other caller, and `src/app/fps_counter.cpp`
  is its own translation unit with this one region.
