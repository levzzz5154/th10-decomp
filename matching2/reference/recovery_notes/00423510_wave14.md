## What the body is

Retail resets one 0x2C4-byte game-state record: it stamps the state word at
+0x04 with 13, raises the running bit of the curve timer at +0x20 while seeding
that timer (previous 0xFFF0BDC1, current/elapsed 0, speed pointing at the shared
float `data_00476f78`), then rewrites the countdown to its "disabled" form
(previous -1, current/elapsed 0), stops the record's two animation handles and
finally publishes the record's own speed field to that shared float. The timer
block is the same previous/current/elapsed/speed/flags shape
`src/game/score_timer_leaves.cpp` recovered for the score timer, at +0x10
instead of +0x2B0.

Shape: the record arrives in **ESI**, nothing on the stack, plain `RET`. The two
`StopAtFrame1` calls are the cluster's existing `EAX`-receiver convention
(`lea eax,[esi+1D8h]` / `lea eax,[esi+1D4h]`), in that order.

## What it took

1. **A fifth function in the registered cluster.** The nearest suitable callee,
   `AnimationHandle::StopAtFrame1` (0x00409E50), is selected by
   `stop_at_frame_pair_0040c480.json` and its `EAX` receiver is a convention only
   that scope reaches — a plain declaration would have emitted `mov ecx,handle`.
   Adding the body to the same link lets the pass derive the convention from the
   bodies, with no convention written anywhere.
2. **The synthetic caller grew a second array.** `StopAtFrameCompilerContext`
   now also walks an array of these records and calls the added member, which is
   what puts the record in ESI (the callee-saved register the body needs across
   the two calls). Its contribution grew 50 → 65 bytes, so the layout's
   `context.size` and decorated `context.symbol` both changed.
3. **A shared handle type.** The driver includes `src/render/anm_propagate.cpp`,
   so a second private declaration of `AnimationHandle` in the added unit is a
   redefinition. The type now lives in
   `include/th10/render/animation_handle.hpp`, listed in the layout's `headers`;
   `anm_propagate.cpp` includes it instead of declaring it. The driver declares
   the added class (rather than including its unit) because the driver's include
   of an *additional* source makes MSVC emit the body twice and the link fails
   with LNK2005 — only the layout's own `source` is included by a driver.
4. **Two bindings.** `_data_00476f78` (`data`) for the shared speed float, and
   `__fltused` (`metadata`) because the body takes the address of a `float`.
5. **The load-bearing store shape.** With `state = 13;` written directly the
   `movl $0xd,[esi+4]` sinks into the flag load's compare slot — 12 bytes and
   three instructions from retail. Borrowing the trick
   `src/game/score_timer_leaves.cpp` documents for its pair write, the store goes
   through a pointer to the field:

   ```cpp
   int* record = &state;
   record[0] = 13;
   ```

   which keeps it in front of `mov eax,[esi+20h]`. Everything else (the
   `xor ecx,ecx` materialised before the test, the hoisted `lea` for +0x1D8, the
   `ecx` reuse across the four zero stores) then falls out exactly.

**Lever 6 again, in a new place.** This is the second independent confirmation
that a store through a pointer-to-the-field stays put where the direct member
store sinks.

## Why a package rather than a registration tool

`register_cluster.py` refuses this layout outright — four of its five functions
belong to sources other than the layout's own `source` (their records already
carry the right symbol, so the tool's per-function source check rejects the
whole registand). `promote_scratch.py` splits the gap for a new function but
copies the maintained `context` and `headers` verbatim, and this region needs
both. The landing therefore uses the `apply_package.py` form:

```
matching2/build/waves/results14/PoolRegionE_init_timed_state/apply_package.py
```

It edits the maintained layout in place inside the manifest lock (function,
`additional_sources`, `headers`, bindings, gap split, context), copies the header,
the unit and the driver from its payload, and rewrites the region record.
**It has been applied** to `matching2/msvc`; the probe above is the maintained
tree. `git revert` of the landing spans: the header, three sources, one layout,
one driver, one manifest record.

The one edit a branch would have to look for: the gap holding 0x00423510
(`.text$40layout`) is split, and the tail is re-declared as `.text$45timedz`, a
name that sorts between the function's own `.text$45timed` and `.text$50find`.

## Source — src/game/recovery_initialize_timed_state_00423510.cpp

```cpp
// 0x00423510..0x00423568: reset a timed game-state record, point its curve
// timer at the shared speed value and stop both of the animation handles it
// carries.
//
// Retail enters this member with the record in ESI, a receiver no C++
// declaration names, so the body is compiled in the native-LTCG cluster
// layout/ltcg/stop_at_frame_pair_0040c480.json whose synthetic caller
// establishes that register.  The two handles at +0x1D4/+0x1D8 are
// AnimationHandles, so the calls reach the StopAtFrame1 body that same cluster
// already carries with its address in EAX.
//
// The record repeats the score-timer shape (previous/current/elapsed/speed/
// flags, see src/game/score_timer_leaves.cpp) at +0x10 instead of +0x2B0, and
// copies its own speed field out to the shared float the timer reads.
//
// The state store reaches the record through a pointer to that field rather
// than through the member: as ``int* base = &record->state`` the store keeps its
// place in front of the flag load, while the direct member store sinks into the
// compare slot (12 bytes away from the retail schedule).

#include "th10/render/animation_handle.hpp"

extern "C" float data_00476f78;

struct RecoveryTimedState_00423510 {
    unsigned char unknown_00[0x04];
    int state;                                 // +0x04
    unsigned char unknown_08[0x08];
    int timer_previous;                        // +0x10
    int timer_current;                         // +0x14
    int timer_elapsed;                         // +0x18
    float* timer_speed;                        // +0x1C
    unsigned int timer_flags;                  // +0x20
    unsigned char unknown_24[0x1B0];
    AnimationHandle handle_1d4;                // +0x1D4
    AnimationHandle handle_1d8;                // +0x1D8
    unsigned char unknown_1dc[0xE4];
    float speed;                               // +0x2C0

    __declspec(noinline) void InitializeTimedState();
};

typedef char RecoveryTimedState_00423510_size_must_fit[
    sizeof(RecoveryTimedState_00423510) == 0x2C4 ? 1 : -1];

#pragma code_seg(".text$45timed")
void RecoveryTimedState_00423510::InitializeTimedState() {
    int* record = &state;
    record[0] = 13;
    if ((timer_flags & 1) == 0) {
        timer_current = 0;
        timer_previous = 0xFFF0BDC1;
        timer_elapsed = 0;
        timer_speed = &data_00476f78;
        timer_flags |= 1;
    }
    timer_current = 0;
    timer_elapsed = 0;
    timer_previous = -1;
    handle_1d8.StopAtFrame1();
    handle_1d4.StopAtFrame1();
    data_00476f78 = speed;
}
#pragma code_seg()
```

## New shared header — include/th10/render/animation_handle.hpp

```cpp
// The four-byte animation handle shared by the co-compiled animation units.
//
// The handle holds the script id of the animation object it names; the
// StopAtFrame pair resolves that id through the animation lookup and drives the
// object's sprite word.  Declared once so the members of one cluster agree on
// the type, its size and the decorated names of the three entry points.
#ifndef TH10_RENDER_ANIMATION_HANDLE_HPP
#define TH10_RENDER_ANIMATION_HANDLE_HPP

struct AnimationHandle {
    unsigned int value;
    __declspec(noinline) void StopAtFrame1();
    __declspec(noinline) void StopAtFrame2();
    __declspec(noinline) void StopAtFrame3();
};

#endif
```

## Driver — layout/ltcg/stop_at_frame_pair_0040c480_context.cpp

```cpp
// Compiler context only; never selected as recovered game code.
#include "../../src/render/anm_propagate.cpp"

// The timed recovery record the added function initialises.  Declared here so
// this driver can call the member without defining it: its body is compiled
// separately and the whole-program pass still sees it.
struct RecoveryTimedState_00423510 {
    unsigned char unknown[0x2C4];
    __declspec(noinline) void InitializeTimedState();
};

#pragma code_seg(".text$70context")
int __stdcall StopAtFrameCompilerContext(AnimationHandle* handles, int count,
                                         RecoveryTimedState_00423510* states) {
    while (count--) {
        handles->StopAtFrame1();
        handles->StopAtFrame2();
        handles->StopAtFrame3();
        handles++;
        states->InitializeTimedState();
        states++;
    }
    return 0;
}
#pragma code_seg()
```

## What it unblocks

Nothing mechanically: 0x00423510's only caller (a literal `call 0x423510` at 0x00424325) reaches it
through a literal `call 0x423510` in a naked region, and the old
`_asm_Recovery_InitializeTimedState_00423510` name in `main_menu_dispatch.cpp`
still resolves through the manifest's binding at the same address.

The useful spare part is the cluster itself. It now proves, for this record
family, that a **record-in-ESI** member is reachable in a scope whose synthetic
caller also walks handles, and it hands any further unit in that scope a C++
`AnimationHandle` to call. The nearest follow-up is **0x00422C30
(`asm_GameState_Unpause`, 74 bytes, same 0x2C4 record, ESI receiver, writes
+0x1DC and +0x2C0)**: it still needs the bodies of its own callees in the link —
`0x0043E460` (AnimationManager_RegisterResource, 104 bytes of assembly, EAX
manager + EDX name + stack args) and `0x004492A0` (SetFlag, currently a plain
per-unit `semantic_` region with the same dead-ECX/EDX/stack convention as
`Find`) — so it is a job for a scope that carries those two, not a plain unit.
