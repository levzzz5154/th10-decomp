# Growing laser: complete exact C++ at 0x0041E700

The production [laser_grow_update.cpp](../../msvc/src/game/laser_grow_update.cpp)
now owns the complete 832-byte callback as ordinary C++, with no inline
assembly. The region consists of 816 instruction bytes followed by its
16-byte, four-entry phase switch table at 0x0041EA30. Its authoritative raw
SHA-256 is
`661581a56ddbf05ccdb053768dd2bdcf69799d185aefb41a8b5e13ceacde451d`.
The original assembly manifest entry is retained as `previous_record`.

The [native layout](../../msvc/layout/ltcg/laser_grow_0041e700.json) compiles
the actual public member callback and seven complete supporting bodies in
one native /LTCG scope. The selected entry receives the laser in ECX, returns
0 or 1 in EAX and has no stack arguments or callee stack cleanup.

## Complete behavior and source fidelity

The callback grows length toward its target and clamps overshoot, normalizes
the angle after applying angular velocity, optionally follows the stage
target's three-component position, then advances all three position components
by the frame-speed-scaled velocity.

The phase switch preserves every transition and its fallthrough. Waiting
advances to growing after resetting the timer. Growing interpolates width
until its deadline; completion resets the timer, installs full width and
immediately tests the active phase. Active completion resets the timer and
immediately tests shrinking. Shrinking returns 1 at its deadline and otherwise
interpolates back toward zero width. States outside 2..5 bypass these phase
branches without bypassing the later animation updates.

Collision is tested only in growing/active states with length greater than
16. The beam's polar collision origin advances by its own position. The width
branch is `width < 32`, with the other branch also taken for an unordered
comparison. A direct hit calls the existing virtual slot at vtable +0x18 with
the player's position, a 32/32/0 size, and mode zero. Graze effects occur every
fifth timer frame: script 434 uses the player's position, and sound 28 uses
the laser's X coordinate as pan. Ghidra's abbreviated creation call did not
show this position input; retail's EDI load and +0x3C0 adjustment establish it.
The archived environment model's use of the beam collision point here was
therefore corrected.

The primary animation receives width divided by sprite height and length
divided by sprite width, with two original transform-dirty flag updates.
Its VM runs every non-retiring call. The secondary VM runs only when the
secondary gate compares equal to zero, including signed zero and excluding
NaN.

The retail polar boundary at 0x0041F800 writes only X/Y. This caller still
reads the third local stack word before adding position Z. The source
explicitly preserves that observed indeterminate value rather than silently
initializing it. This is fidelity to an original behavior, not a claim of
portable defined initialization or a safe new vector API. The typed creation
formal accepts the actual Point3_OrientedRect object directly, avoiding an
unnecessary cast between unrelated three-float types.

The physical view checks timer +0x10, position +0x24, velocity +0x430, target
width +0x44C, phase deadlines, flags +0x468, and embedded animations +0x61C
and +0x9C8. Six preceding virtual slots are declarations for the existing
vtable; no dummy implementations, constructors or vtables are emitted.

## Matching decisions and verification

Ten complete diagnostic graph controls are retained under
`matching2/build/experiments/laser_grow_native_2026_10_06/`. Their ledger is
`controls.json`. The first complete body was 852 bytes. Scalar motion and the
correct angle stack convention reduced it to 816 but changed x87 scheduling.
Constructing the complete velocity delta, adding it through an inline vector
reference helper, and retaining one local full-width value reproduced the
motion and shrinking arithmetic. Correcting the graze position reproduced
both effect and sound call sites.

Two inline scalar scale setters still duplicated the dirty-flag expression
and yielded 836 bytes. A single component/reference helper with the original
flag update before the component store produces all 832 bytes. A volatile
flag experiment regressed to 840 bytes and was rejected; no such qualifier
is retained. Sharing only an explicit mask did not fix the residual. The
initial diagnostic had erroneously added the table size to an already
complete manifest extent; it was rerun against 832 bytes using the unchanged
native artifact before recording the final control ledger.
