# Audit: `0x00424620` slot mark fan-out

The live Ghidra program `th10.exe` is the x86 PE at image base `0x00400000`.
Ghidra returns no function for `0x00424620` and no xrefs to the entry or any
of its four store instructions. Thus the live database supplies no caller
or prototype for this address. The bytes and the repository's 25-byte region
boundary nevertheless support a standalone leaf: four complete stores,
`RET`, then the recorded `CC` padding through `0x0042463f`.

Exact region bytes (`0x00424620..0x00424638`):

```text
89 81 2c 33 00 00   mov dword ptr [ecx+0x332c], eax
89 81 c4 33 00 00   mov dword ptr [ecx+0x33c4], eax
89 81 5c 34 00 00   mov dword ptr [ecx+0x345c], eax
89 81 f4 34 00 00   mov dword ptr [ecx+0x34f4], eax
c3                  ret
```

The observable operation broadcasts the incoming `EAX` value to four
32-bit fields on the `ECX` object. Those offsets form a `0x98` stride from
`0x332c`, consistent with the slot-mark layout recorded in
[`00428e10_wave14.md`](00428e10_wave14.md). The code has no stack arguments
and does not adjust the stack; `EAX` is left unchanged by the return.

The register pair (`ECX` object, `EAX` value) is not expressed by an ordinary
MSVC x86 free/member prototype. The owned source already records unsuccessful
native-LTCG attempts for free `__stdcall`, member `Set(int)`, and reversed
free-parameter order, each producing zero matching bytes. Without caller
context or a compiler mechanism for this private ABI, a readable C++ body
cannot replace this region byte-for-byte. Keep the naked implementation.

The current manifest owner is
`src/unidentified/FUN_00424620_00424620.cpp` (symbol
`_asm_FUN_00424620_00424620`); the requested `unassigned_00424620.cpp` path
does not exist. No additional symbol alias is indicated. Caller identity
remains unresolved because the live Ghidra database has no xrefs here.
