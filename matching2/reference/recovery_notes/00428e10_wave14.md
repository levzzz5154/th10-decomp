## What the recipe had to add for this region

Nothing about the ABI: the region is a leaf, so there is no callee convention to
co-compile and no anchor, and the array-walking synthetic caller earned retail's
`(EAX state, ECX record)` pair on the **first** probe (the same pair the two
landed 55-90 band precedents earn — `0x00450690` and `0x0042C5C0`).  `roots` is left
empty on purpose: rooting would pin the declared `__thiscall` ABI and lose the
private pair.

What was left was **scheduling**, and it needed two independent source shapes:

1. **The two counters are written through one shared base pointer**
   (`int* counters = &counter_value; counters[0] = ...; counters[1] = ...;`).
   Written as two independent member assignments the backend hoists the first
   `fild` above the second counter store (legal: same base, different offsets)
   and then fills the `fild`/`fmul` latency slot with the second `mov $1,%ecx`
   instead of retail's position — 53 of the 83 bytes.  With the shared base the
   two stores stay adjacent, the `fild` stays after them, and `mov $1,%ecx`
   lands in retail's slot.  This is lever 6 of the brief, and the same lever
   `0x0042C5C0` needed (`timer_owner`/`timer_target` through one base).
2. **The four slot marks are a loop** (`for (int i = 0; i < 4; i++) slots[i].flag
   = 1;`).  MSVC 7.1 unrolls the four iterations into retail's four
   constant-offset stores *after* the whole x87 chain; four explicit assignments
   instead get scheduled into the x87 latency slots (40 differing bytes even
   with lever 1 already applied).

Neither lever alone is enough and both are load-bearing: with lever 1 only, 40
bytes differ (first at `0x1C`); with lever 2 only, 21 bytes differ (first at
`0x08`).

identical either way.  The dead variants are recorded because their **extent**,
not their schedule, rejects them: the four spellings that change the instruction
count (a local pair, interleaving a store with its own conversion, and a real
pointer walk over the slots) all miss retail's 83 bytes, so no statement
reordering inside *those* shapes can land.

## Tooling notes for the next reader

* `matching2/tools/waves/cluster_attempt.py` cannot drive a layout for this
  region as it stands: `_map_offset`/`_map_section` match the **length** column of
  the map's contribution table (`0001:00027e80 0000003cH .text$03context`), so its
  adaptive retry writes a context address of `0x0040103C` and a zero-length gap
  (which then fails C2466).  The iteration here used a local copy of the same
  build/compare loop that reads the `segment:offset` column instead.
* A cluster whose source contains any floating-point code needs
  `{"symbol": "__fltused", "address": "0x00000000", "kind": "metadata"}` in
  `absolute_symbols`; without it the native link fails with
  `LNK2001: unresolved external symbol __fltused`.
* The `0.01f` literal is pooled per translation-unit set, so the layout binds it
  with `constant_aliases` (`__real@3c23d70a` at `0x00470B00`); the manifest
  already carries the same binding in `symbols`, so no new binding was needed.
* The context lands 16-byte aligned 29 bytes past the function
  (`0x428E80`, size 60).  A `search` over layouts with the same shape
  (`score_gauge_publish_00428e10.json`) is a copy-paste template for the next
  leaf: head gap `0x401000..0x428E10`, mid gap `0x428E63..0x428E80`.

// Retail enters this member with the score state in EAX and the two counters in

// src/game/boss_gauge.cpp) reads: it owns the 152-byte gauge slots.  This entry
// parks the record's two counters at +0x3CC/+0x3D0, republishes them as the
// gauge position at +0x3C0/+0x3C4 scaled to playfield units (0.01 per unit) and
// marks the first four slots.

// backend hoists the first `fild` above the second counter store and fills the
// x87 latency slot with its own schedule, moving 53 of the 83 bytes; with it the
