# Score HUD 0x00417040: byte-exact ordinary C++

`msvc/src/game/score_hud_update.cpp` now implements the complete HUD update
in ordinary C++. All 671 retail instruction bytes match, with the native ESI
receiver, no stack arguments, and plain RET. The logical member returns void;
its real caller at 0x004186DD ignores EAX. The selected symbol is
`?Update@ScoreHud_00417040@@QAEXXZ`. No inline assembly, register adapter,
output edits, oracle build input, or comparison masks are used.

The routine eases the displayed score toward the live score using a signed
one-thirty-second step, a maximum step of 0x8D55E, and the existing velocity.
It updates the high score and its continues snapshot, changes the animation
control word when either display crosses 100 million, configures nine decimal
digits for each score, ticks both digit groups, and refreshes their continues
markers. It awards a life when the next difficulty-specific threshold is
reached, unless the HUD suppression flag is set.

## Source and compiler boundary

The checked HUD view contains one contiguous array of twenty animation
objects: a continues marker plus nine high-score digits, followed by the same
layout for the displayed score. Subtracting ten objects from a score digit
therefore stays within the same array. The additional checked fields cover
the life icons, both captions, displayed score, velocity, flags, and resource.
The game-state view also checks the next-extend index at offset 0x5C.

`msvc/layout/ltcg/score_hud_00417040.json` compiles the full HUD with twelve
complete animation, life-stock and support functions. The public resource
initializer is retained through the existing `anchor_roots` mechanism.
All helper owners remain separately selected by their existing production
sources; their context copies receive no additional recovery credit.

The 19-byte `_HudCompilerContext@0` entry is explicitly compiler-only. It
calls the HUD through the global HUD pointer and returns one. This simple
entry lets native LTCG derive the private ESI receiver; it is not presented
as recovered game code or substituted for the still-assembly StageUpdate.
The emitted HUD boundary matches that genuine caller's existing ESI call.
A prior synthetic array-walking context kept its own loop cursor in ESI,
causing a private EAX HUD entry instead. No caller shim is used in the game.

Eleven unselected helpers match their entire raw native retail bodies:
AddLives 141, SetActiveCount 77, animation creation 73, primary-back
registration 118, allocation 161, public resource initialization 217,

The relocated diagnostic model compares all twelve helpers exactly.

## Source-shape evidence

Experiments and full receipts are in
`matching2/build/experiments/score_hud_native_2026_10_06/`.

The high-score update contains a seemingly redundant flag test. A DWORD/byte
union view, copied to a local flag word, ORed with four, and committed after
the high-score and continues stores reproduces the native OR/TEST AL and the
full cold caption replacement branch. Testing the integer field directly
lets the compiler delete that branch. No volatile qualifier or barrier is
needed. The retained cold path releases the secondary caption and creates
script 74 at layer 15.

The extra-life check is expressed as two ordinary difficulty branches, each
with its complete award block. C2 merges those tails and joins the comparison
flags directly at JL. A shared boolean produces SETGE/TEST instead; selecting
a table pointer also changes the observed control flow.

Taking the old displayed-score snapshot inside the easing branch, before
computing its candidate, reproduces the native EBX snapshot and the entire
score arithmetic. Taking it after the candidate leaves it in EDX; taking it
before the branch moves its copy too early.

The final loop counts down from nine and derives the current score digit as
`animations[20 - count]`, then its matching high-score digit as `current - 10`.
This preserves the retail single pointer increment and per-iteration LEA.
A separately advanced score pointer makes C2 create a second induction pointer
and increment both pointers, yielding 677 bytes and four instruction hunks.
That negative source form is retained in `old_before_candidate/`.
The first exact diagnostic source and all whole-body comparisons are in
`remaining_index/`. Unused accessor experiments were removed before promotion.

The fixed-address production probe in `fixed_probe/` passes the unchanged
complete-contribution gate, native address/entry checks, and all selected byte
checks. `fixed-native-helper-audit.json` independently records every full
native helper comparison. The selected body SHA-256 is
