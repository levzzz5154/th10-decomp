# Region 0x004489D0 (118 bytes) — model settled to one register tie-break, NOT EXACT

2026-09-19, agent `RenderBucketPair`. Region `0x004489D0..0x00448A45`, source
`src/render/animation_manager_register_primary_back_004489d0.cpp`, 118 bytes.
Work was done in `/tmp/RenderBucketPair/msvc` (`cp -a matching2/msvc`) and in the
scratch copies `/tmp/RenderBucketPair/msvc{1..6}`. **Nothing was registered and the
maintained tree is untouched**: a non-exact layout must never be registered, so
the region is still `asm` and the 103-byte stand-in anchor still stands in
`layout/ltcg/positioned_primary_00448d50_wave10.json`.

## Disposition

The body is now settled to **the retail instruction sequence, instruction for
instruction**, but with the manager's id counter kept in **EDI** where retail
keeps it in **ESI** (and, as a consequence, `push %edi` in the entry block where
retail shrink-wraps it into the else):

```text
0x004489d0  emitted 118 / want 118   differing 40   first +0x1c  got 57 ("push %edi") want 75 ("jne")
0x00448d50  (the 0x448D50 cluster function) unchanged: 95/95 differing 0
```

The alternative shape that keeps the whole head **and** the else byte-identical
(folded id block, below) emits **117** bytes, 39 differing, first at `+0x4b`.

So the delta is one register tie-break, not a missing convention: the second
candidate's first 0x4B bytes (through `mgr->tail = node`) are retail's own.

## What the region is

`0x004489D0` is a leaf (`ret`, no frame). Retail enters with the entity in
**EBX** (its embedded node lives at `+0x04`, its `id` at `+0x00`), the manager in
**EDX** and the caller's out slot in **EAX**; the body pushes ESI (at entry) and
EDI (inside the non-empty branch), links the node at the tail of the manager's
primary-back list, stamps `entity->id` and `*out` with the manager's next id, and
returns the out slot in EAX.

Retail's own listing of the disputed tail, from the oracle
(`i686-w64-mingw32-objdump -d --no-show-raw-insn --start-address=0x448a14
--stop-address=0x448a46 matching2/build/oracle/th10.exe`):

```asm
448a14: mov    %ecx,0x72dad8(%edx)      ; mgr->tail = node
448a1a: mov    0x732454(%edx),%esi      ; counter
448a20: inc    %esi
448a21: mov    %esi,%ecx                ; a *copy* for the test
448a23: test   %ecx,%ecx
448a25: mov    %esi,0x732454(%edx)      ; the store is scheduled after the test
448a2b: pop    %esi
448a2c: jne    0x448a35
448a2e: inc    %ecx                     ; id + 1 in the tested copy
448a2f: mov    %ecx,0x732454(%edx)
448a35: mov    0x732454(%edx),%ecx      ; entity->id = mgr->next_id  (reload)
448a3b: mov    %ecx,(%ebx)
448a3d: mov    0x732454(%edx),%edx      ; *out = mgr->next_id       (reload)
448a43: mov    %edx,(%eax)
448a45: ret
```

Two things are load-bearing and both are reproduced by the model below:

* The two final stores **re-read** `manager->next_id` instead of storing the id
  register. That is aliasing, not `volatile`: the store to `*(int*)entity`
  precedes the second read and the compiler cannot prove `entity` and `manager`
  disjoint, so the second read is re-issued. (`volatile` also reproduces the two
  reads but costs 8 extra bytes and a different head.)
* The zero case stores `id + 1` computed **in a register** (`inc %ecx; mov
  %ecx,mem`), not the constant 1 — i.e. the branch body must be a store of
  `id + 1`, not `++counter` and not `id = id + 1; store id`. Written as
  `id = id + 1; *next_id = id;` MSVC folds the constant (`movl $1,mem`), and the
  body collapses to the 117-byte folded form.

The byte delta is exactly two artefacts of that one register: `push %edi` lands

### Source (`src/render/animation_manager_register_primary_back_004489d0.cpp`)

```cpp

// to the tail of the animation manager's primary-back list and stamp the object
// and the caller's out slot with the manager's next id.
//
// Retail enters with the entity in EBX (its embedded node at +0x04, its id at
// +0x00), the manager in EDX and the out slot in EAX, pushes ESI at entry and
// EDI inside the non-empty branch, and returns the out slot in EAX with a plain
// RET.
//
// Two statement shapes are load-bearing:
//  * The two final stores re-read manager->next_id.  The store to the entity
//    precedes the second read and the compiler cannot prove the entity and the
//    manager disjoint, so the read is re-issued; keeping the id in a register
//    and storing it twice emits 14 bytes fewer and loses retail's reloads.
//  * The zero case stores `id + 1` computed in a register (retail:
//    `inc %ecx; mov %ecx,mem`).  Written as `id = id + 1; *next_id = id;` MSVC
//    folds the constant to `movl $1,mem` and the whole id block collapses to the
//    117-byte folded form.
#include "asm_symbols.hpp"

extern "C" void* data_00491c10;

#pragma code_seg(".text$03regprimary")
extern "C" __declspec(noinline) void** __cdecl asm_AnimationManager_RegisterPrimaryBack_004489d0(
        void* manager, void** out, void* entity) {
    unsigned char* m = (unsigned char*)manager;
    unsigned char* e = (unsigned char*)entity;
    void** node = (void**)(e + 0x04);
    node[0] = e; node[1] = 0; node[2] = 0;
    if (*(void**)(m + 0x72DAD4) == 0) {
        *(void**)(m + 0x72DAD4) = node;
    } else {
        unsigned char* tail = *(unsigned char**)(m + 0x72DAD8);
        if (*(unsigned char**)(tail + 0x04) != 0) {
            node[1] = *(unsigned char**)(tail + 0x04);
            *(unsigned char**)(*(unsigned char**)(tail + 0x04) + 0x08) = (unsigned char*)node;
        }
        *(unsigned char**)(tail + 0x04) = (unsigned char*)node;
        node[2] = tail;
    }
    *(void**)(m + 0x72DAD8) = node;
    int id = ++*(int*)(m + 0x732454);
    if (id == 0) *(int*)(m + 0x732454) = id + 1;
    *(int*)(e + 0x00) = *(int*)(m + 0x732454);
    *(int*)out = *(int*)(m + 0x732454);
    return out;
}
#pragma code_seg()
```

Naming the counter through a local (`int* next_id = (int*)(m + 0x732454);`) gives
the identical 28 instructions and the identical register choice; it differs from
the text above only by the tail store's slot (41 differing instead of 40), so both

## Can the anchor in the 0x448D50 cluster be dropped?

**Not today, and not by an opaque binding at any time.**

* An `absolute_symbols` `relative_code` binding at 0x004489D0 removes the
  callee's body from the link; the pass then re-decides the convention from the
  caller alone. Measured here: rooting the 0x448D50 function in the same cluster
  (a much weaker disturbance than dropping the body) already cost 78 of 95 bytes
  (`0x00448d50 emitted=95 want=95 differing=78 first=+0x1 got=56 want=55`).
  This is wave 11's finding restated: the caller re-shapes itself around
  whatever the callee wants.
* The anchor *can* be replaced by a **selected function** in the same cluster
  (or by its own cluster, as the standalone run above shows): the recovered body
  carries the same EDX/EBX/EAX triple on its own. That is the only way the
  anchor goes away, and it needs the body to be exact — which it is not yet.

So the 0x448D50 cluster keeps its 103-byte anchor, and `0x00448D50` keeps probing
EXACT with the 118-byte stand-in too (`differing=0` in every run above).

What was *not* reachable: getting the counter into ESI. Every spelling that
produces retail's 50-byte tail — the copy for the test, the deferred store, the
register `inc` in the zero case — puts the counter in **EDI** (the register the
else block's `next` temporary just freed) and puts the tested copy in ECX, which
is retail's `id` register too. Only the folded spellings avoid the second
register, and they collapse the tail to 49 bytes. Forcing ESI would need EDI busy
across the id block; every attempt to hold a second value live there (an extra
use of `next`, a fifth call site, a rooted caller, a second store) either changed
the emitted code or moved the entry convention off EDX/EBX/EAX.

## Effect on other regions

None. `0x00448D50` still probes EXACT with the anchor in place; nothing that
listed `0x004489D0` as its blocker is unblocked by this note. A body whose id
block lands in ESI (28/28 retail instructions) would immediately let the
118-byte anchor be declared as a selected function in the 0x448D50 cluster and
the region registered there.
