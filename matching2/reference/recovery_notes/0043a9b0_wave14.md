## The lever: an anchor's parameter home is a property of the anchor *body*

The wave-13 note read the residual as "the receiver simply follows the caller's
home" and tried sixteen synthetic-caller shapes, an in-link loader, module
arrangements and a three-register anchor without moving it.  The measurement
below says the causation runs the other way: the caller follows the **anchor's**
choice, and that choice is decided by the anchor body's own live-range shape.
Retail's own `0x0043AE20` is the proof of the mechanism — it keeps its receiver
in **EDI unsaved** (`mov eax,[edi+0x138]` before the prologue, `lea ebx,[edi+0x14]`
inside it, `push ebx; push ebp; push esi` and no `push edi`), i.e. EDI is that
callee's *argument* register, and its caller `0x0043A9B0` then has to hold
`this` there.

Six anchor bodies were built into the same link, everything else unchanged:

| anchor body for `0x0043AE20` | receiver home | emitted | differing |
| --- | --- | --- | --- |
| wave 13's: cursor + counter + released count live across the `free` | EBX | 116 | 18 |
| **the 0x004477D0/`0x0041C330` shape**: object reached through a local base pointer that is still live after the loop, cursor a *loaded* pointer incremented inside it | **EDI** | **116** | **0** |
| the same plus an early deref of the object before the loop | EBX | 116 | 18 |
| wave 13's body with the receiver written inside the loop | EBX | 116 | 18 |
| wave 13's body with the cursor read again after the call | EBX | 116 | 18 |
| cursor + counter, no released count (one fewer live value) | EBX | 116 | 18 |

and, as the control, with **no** `0x0043AE20` body in the link at all (declared
`__thiscall`, symbol bound absolutely, as `register_cluster.py` does for opaque
callees) the pass re-chooses the whole private convention and emits 113 bytes:
`cmp [esi+0x10],edi` — the receiver in ESI and the index in EDI, both unsaved.
So the anchor body is what fixes the home, and the *shape* of that body is the
only lever that reached EDI here.  This is the same property the
`0x0041C330` anchor note records ("an anchor whose records object stays live
across a loop that calls out puts it in EDI") and the one the landed
`0x00447810` scaffolding uses; wave 13's own body keeps the object live across
the same call but derives the cursor from the receiver instead of loading it,
and that difference alone is the 18 bytes.

**Lever 1 of the wave-13 note is not what closed this.** The archive loader was
*already* a selected function of the cluster (`Archive_LoadFile`, 360 bytes,
whose private `name in EAX, RET 8` agreement the link earns), so nothing about
the loader changed; what changed is the second anchor.  The loader's own call
site — `push 0; push 0; mov eax,ebp; call 0x44B360` — and the log call
`push ebp; push 46F908h; mov ecx,474F70h; call 0x44B810; add esp,8` are both
reproduced byte for byte, as wave 13 measured.
