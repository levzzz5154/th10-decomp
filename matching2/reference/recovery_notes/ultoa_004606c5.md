# `_ultoa` at 0x004606C5

Live Ghidra disassembly identifies a separate 26-byte function at
`0x004606C5..0x004606DE`, immediately after the recovered `_ltoa` entry.
The wrapper reads `value`, `destination`, and `radix` from three cdecl stack
arguments. It passes `value` in EAX and `destination` in ECX to `_xtoa` at
`0x00460636`, pushes `radix` and a false signed flag, then returns the original
destination pointer. The live Ghidra function was created, typed, documented,
and saved.

The maintained [C++ source](../semantic_candidates/ultoa_004606c5.cpp)
calls a typed semantic `_xtoa` helper and returns the original destination.
The helper emits at least one digit, uses lowercase letters for digits above
nine, NUL terminates, and reverses the generated digits. The `_itoa`, `_ltoa`,
`_ultoa`, and `_xtoa` source bodies now use C++ without inline assembly.

The manifest records the 26-byte wrapper and 62-byte helper as semantic and
keeps their assembly records in `previous_record`. No build, byte comparison,
or test was run for these changes; exact retail bytes remain unverified.
