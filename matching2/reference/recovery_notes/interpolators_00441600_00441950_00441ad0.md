# Interpolator cluster recovery

## Scope and result

This lane covered the live assembly bodies at `0x00441600`, `0x00441950`, and
`0x00441AD0`. No semantic candidate passed the independently focused exact
extent-and-byte gate, so production remains assembly and `regions.json` was not
changed. All temporary interpolator candidates, LTCG layouts, contexts, and
probe specifications were removed.

The maintained-source baseline probes remain exact:

| Region | Live manifest extent | Legacy semantic extent | Baseline result |
| --- | ---: | ---: | --- |
| `0x00441600` | 820 | 848 | EXACT |
| `0x00441950` | 370 | 384 | EXACT |
| `0x00441AD0` | 652 | 896 | EXACT |

The legacy registry extents include adjacent padding/old boundaries and are
not valid promotion extents. Ghidra/live body ends are the current authority.

## Recovered behavior

The three bodies are timer-driven interpolator ticks over the actual retail
blocks (the timer fields begin at `+0x30` for the 3-integer body, `+0x10` for
the scalar integer body, and `+0x20` for the two-float body). Each updates
`previous`, `elapsed`, and fractional progress using the shared speed globals
at `0x00476F78`, `0x00470AFC`, `0x00470B68`, and `0x00470B64`; completion arms
the one-shot reset flag and returns the terminal start/target value. Mode `7`
is additive target integration, mode `17` is additive acceleration
integration, mode `8` is cubic Hermite interpolation, and the default path
uses `0x0044C350` easing. The integer vector body additionally truncates each
scaled component through the existing rounded-vector helper at `0x00441E50`
and `__ftol2`.

## Exact-attempt evidence

- `0x00441600`: the bounded three-body native-LTCG candidate contributed 618
  bytes instead of 820; its first mismatch was at `0x00441600` (candidate
  prologue `55 8B EC ...`, retail `83 EC 48 ...`). The Hermite/default path
  also needs the existing `0x00441E50` custom ABI: input in `EDI`, output in
  `ESI`, scalar on the stack, plain `RET 4`. An ordinary external declaration
  cannot express that edge.
- `0x00441950`: native scalar candidates contributed 390 bytes (first
  mismatch `0x00441953`, an unwanted `push edi`) and 399 bytes (first
  mismatch `0x00441956`, missing the retail `test eax,eax` sequence), versus
  the 370-byte live body. Neither had an exact extent or byte stream.
- `0x00441AD0`: member/free/swapped-object native candidates converged on a
  523-byte contribution, with first mismatch `0x00441AD2` (`18` versus the
  retail stack allocation byte `20`), versus the 652-byte live body. They
  saved/register-shuffled `EBX`/`ESI` where retail uses caller-established
  `ESI` state and `EDI` output, and their x87 Hermite schedule/extent remained
  different.

## Next dependency

Revisit only with a caller-faithful native-LTCG topology that reproduces the
retail caller liveness and internal `ESI`/`EDI` register convention. The
integer vector path additionally requires an explicitly modeled task-local
wrapper/topology for the `0x00441E50` rounded-vector helper. The legacy
semantic source is behaviorally useful but its struct ordering and boundaries
must not be copied into the live sources without this ABI/profile evidence.
