# Fixed-angle step with complete motion callers, 2026-09-28

**Outcome: no promotion.** The complete 335-byte `BulletDeceleration::FixedAngleStep` is C++ without inline assembly, but its normal original-address gate still has four register-allocation byte differences. The result is a measured compiler residual, not a claim of recovered code.

The frozen experiment is `matching2/build/experiments/fixed_angle_real_caller_2026_09_28/`. `terminal_summary.json`, `measured_terminal_input_hashes.json`, and `probe04_original_target_positions.json` identify the exact inputs and final gate. The current maintained source, manifest, backend, and prior checkpoint artifacts were not edited.

Fresh Ghidra readback of the retail image gave the full `0x00406240..0x004065B4` runtime function (885 bytes), the full `0x004065C0` re-arm function (249 bytes), and the full `0x004078E0` fixed-angle function (335 bytes). The runtime tests bit `0x100` in the bullet's flags and calls the fixed-angle method at `0x004063D1` immediately after moving the receiver from EBP to ESI. Its branches also call the complete turn, aim, and bounce methods. The source model retains the runtime state switch, all three position integrations, optional animation/motion dispatch, collision effects and sound, bounds/wrap/removal checks, and terminal timers. The 249-byte re-arm source is the existing complete C++ body; its source copy in the diagnostic link is an honest whole-function anchor. Neither caller is represented by the old synthetic 56-byte pointer loop.

The first strict schema-2 graph selected all nine original extents (including 885-byte runtime and 249-byte re-arm). It compiled nine complete contributions, but the runtime emitted 803 bytes, re-arm 250 bytes, and the fixed-angle body 335 bytes. The normal gate rejected the shifted entry/address, as required. `probe01_headers.json`, its complete native bodies, and `probe01_complete_diagnostics.json` preserve that failed gate. No size field or retail region extent was relaxed to call it exact.

A second, explicitly diagnostic layout left the original 885-byte runtime region and 249-byte re-arm region unpromoted. It linked the **complete** runtime candidate as an unselected 806-byte entry/context and the **complete** re-arm candidate as an unselected 249-byte ABI anchor. The 806-byte context is not a synthetic loop or truncated portion of the retail 885 bytes; it is the whole compiled C++ candidate in this link. This allowed the seven selected methods to be checked at their retail addresses under the normal byte gate. Six match completely: `CanRearm` 40, TurnStep 338, AimStep 431, Bounce 446, ProjectileDeceleration::Update 329, and SoundQueue::Queue 123 bytes. The re-arm anchor's entire 249-byte body also equals retail byte for byte, but contributes no newly recovered bytes. The runtime remains 806/885 with 752 overlapping byte differences. The native report records zero changed instruction bytes, zero masked bytes, and no retail reference bytes used for building.

At `0x004078E0`, the native `.text$09fixed` contribution is the entire **335-byte** function at the exact retail start address. The ordinary gate compares all 335 bytes directly, without relocations or excluded ranges: **331 bytes equal and four differ**, exactly at `0x004079B4`, `0x004079B7`, `0x004079BC`, and `0x004079BD`. The retail sequence loads magnitude into ECX and angle into EDX; the compiler still uses EAX and ECX and correspondingly pushes those two registers. The complete candidate body SHA-256 is `485879c92f05e6c776fedc13765137f2e8c608062c4bec82b39c7c702fde67c3`, identical to the earlier four-byte residual. Its call edge from the genuine runtime candidate is at `0x0040638F`, under the same bit-`0x100` guard; that caller's shorter body shifts the call site from retail `0x004063D1`, but the actual argument receiver is still the retained ESI bullet.

This trial separates the compiler residual from the former synthetic caller. It does **not** establish that the original runtime can be promoted: several real opaque helper functions use EAX/EBX/ESI/EDI parameter conventions that ordinary external C++ declarations cannot express, and their genuine whole bodies were not in this link. In particular the runtime's collision test takes position ECX, player EDX, dimensions EAX; effect creation takes position EDI plus three stack arguments; and the panned sound call takes manager ESI, sound ID EBX, and x position on the stack. Further progress requires those real helper bodies or a source-level lifetime lever grounded in another authentic caller, followed by original-extent whole-function gates. No byte patch, mask, helper-only promotion, or section truncation was used.
