## Semantic and ABI evidence

The archived `legacy_semantic/src/platform/sound_commands.cpp` identifies the
device-command functions as MIDI shutdown, sound-manager shutdown, BGM
preload, BGM start, and sound-worker command draining:

* `0x0043A910` stops MIDI playback and resets its queues, frees 0x20 track
  blocks at `+0x98`, closes the timer event at `+0x13C`, resets/releases the
  MIDI output at `+0x04`, and ends both time periods using the `+0x08` value.
  Retail enters with the manager in `EAX`, preserves `EBX/ESI/EDI`, changes
  vtables at entry/exit, and calls several imported APIs through IAT slots.
* `0x0043D120` releases the track table, releases 0x80 COM buffer slots,
  frees 0x25 BGM headers, then conditionally kills the update timer, stops
  MIDI, releases the DirectSound chain, destroys the streamer, releases the
  notify event, and clears the name slots.  The retail manager is in `EAX`;
  each COM release is a vtable `+8` call and the branch layout is part of the
  live extent.
* `0x0043D7D0` compares the requested name against the selected slot's
  0x100-byte name, stores a changed name, and on file-streaming mode releases
  the old buffer, opens/locates the archive entry, reads its header/data, and
  publishes the per-track pointers.  It uses the incoming name in `EAX`, the
  sound manager in the nonstandard `ESI` context, and the slot index as a
  stack argument with `ret 4`.
* `0x0043D950` rejects an uninitialized/disabled manager, routes archive
  tracks through the archive-entry helper, or computes an aligned streaming
  buffer, starts the worker, and calls `0x0044CBF0`.  It carries the manager in
  `ESI`, the track in `EBX`, and returns the retail `-1/0` status shape.
* `0x0043DDF0` drains the queue at `ctx+0x1F88`, dispatches the indexed command
  jump table at `0x0043E37C`, advances multi-stage stop/shutdown commands, and
  flushes pending SFX slots.  Its entry has an explicit `sub esp,0xC`, puts the
  context in `EBP` from `[esp+0x14]`, and returns with `ret 4`; the callbacks
  and jump-table cases are therefore not ordinary hook calls.

The streamer functions cover the DirectSound buffer lifecycle:

* `0x0044CBF0` creates and initializes the streamer record, builds the
  description/format block, invokes the device vtable, allocates the supplied
  count of notification pairs, and publishes a stream over the supplied PCM.
  It has SEH plus the stack
  cookie, receives a mixed `ECX`/`EDX`/stack custom ABI, and has COM calls at
  vtable offsets `+0x0C` and `+0x00`.
* `0x0044CF20` releases every existing buffer, frees/reallocates the buffer
  pointer array, creates each buffer, builds the 0x10 notification records,
  and installs them. Partial creation/query/allocation failures retain objects;
  only the notification interface/table are cleaned up after a failing Set.
  The
  streamer object is implicit in `ESI`; its buffer count is at `+0x10`, array
  at `+0x04`, and notification state begins at `+0x34`.
* `0x0044D110` restores and locks the playback buffer, resets the reader,
  reads PCM, optionally repeats positive short reads, pads with 8-bit silence
  `0x80` or zero for other sample widths, and unlocks. It enters with the
  streamer in EAX and buffer/repeat on the stack (RET 8). Negative read/rewind
  leaves the buffer locked; repeated zero reads have no progress guard. See
  the current cursor/refill note for exact callback and partial-copy behavior.
* `0x0044DAD0` validates the first buffer/reader, clears four playback fields,
  restores the buffer, optionally refills through `0x0044D110`, resets the
  reader and returns SetCurrentPosition(buffer, 0). Negative restore/refill
  returns before SetCurrentPosition. Its context is EDI, the result flag is
  a stack local rather than inherited ECX, and the entry returns plain RET.

The historical pass used maintained retail disassembly and archived semantic
sources. Saved Ghidra C and full-instruction exports are now available under
`decompiled/ghidra_augmented/functions`; the linked follow-up notes use them
with retail differential execution. The dispatcher has no local SEH frame;
its nested factory calls can establish their own frames.

## Conversion attempts and mismatch matrix

The device and streamer attempts used task-local raw-offset layout sketches,
readable semantic helpers, and a minimal naked bridge only where required to
carry the retail entry register into the helper.  This makes the ABI failure
measurable without leaving an invalid production candidate.

| Address | Required | Candidate extent | First mismatch/evidence | Result |
| --- | ---: | ---: | --- | --- |
| `0x0043A910` | 156 | 10 | extent mismatch at region entry; bridge is `push eax / call helper / add esp,4 / ret`, while retail starts `push ebx; push esi; mov esi,eax; push edi` | rejected |
| `0x0044DAD0` | 213 | 10 | extent mismatch at region entry; bridge is `push edi / call helper / add esp,4 / ret`, while retail starts `push ecx; mov eax,[edi+4]; mov ecx,[eax]; push ebp` | rejected |
| `0x0043D120` | 301 | — | not independently attempted after the EAX-entry/native-COM bridge failure; restored baseline exact | no promotion |
| `0x0043D7D0` | 369 | — | shared ESI manager plus stack-name/`ret 4` ABI still unresolved; restored baseline exact | no promotion |
| `0x0043D950` | 298 | — | shared ESI manager plus nested streamer custom ABI still unresolved; restored baseline exact | no promotion |
| `0x0043DDF0` | 1452 | — | command jump table, callback register setup, and SEH-shaped dispatcher remain unresolved; restored baseline exact | no promotion |
| `0x0044CBF0` | 651 | — | mixed register/stack arguments, SEH/cookie, and DirectSound COM vtable ownership remain unresolved; restored baseline exact | no promotion |
| `0x0044CF20` | 338 | — | implicit ESI object plus COM/allocation unwind paths remain unresolved; restored baseline exact | no promotion |
| `0x0044D110` | 483 | — | EAX/stack byte-count ABI and reader/DirectSound callbacks remain unresolved; restored baseline exact | no promotion |

The two bridges compile, but their ten-byte extents prove that a readable
helper plus a normal call bridge cannot be promoted as the retail body.  The
other functions share the same issue with additional COM/vtable and callback
state, so speculative bodies were not retained.

## Best next dependency

Build one bounded native-LTCG context around the DirectSound/streamer object
that preserves each live entry register (`ESI`, `EAX`, or `EDI`) across COM
calls and callback calls, while separately modeling the stack cleanup (`ret`,
`ret 4`, and the mixed 44CBF0 argument positions).  The high-payoff leaves are
the exact vtable adapters for buffer `Restore`, `Lock`, `Unlock`, `SetCurrent-
Position`, `GetCurrentPosition`, and `Release`, plus the reader callback and
`0x0044D300` interface runner.  On the device side, the next dependency is the
0x0043DDF0 command jump-table/callback ABI together with the exact ESI manager
context used by `0x0043D7D0` and `0x0043D950`; only then should the larger
SEH-bearing `0x0044CBF0` and dispatcher bodies be retried.
