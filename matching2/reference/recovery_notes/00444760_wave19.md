## Group A (1 byte): the sync callee must take the manager in EAX

Retail marshals `mov eax,ebp; call 0x4423e0` with no push; the wave-17 anchor made
the pass put the manager *on the stack* (`push ebp`, and the frame slot moves from
`[esp+0x48]` to `[esp+0x4c]`). Group A is not a source property of 0x444760 at
all: it is the callee 0x4423E0's derived convention, and only a *compiled* anchor
can set it.

The winning anchor shape keeps the entity live across a call (so it earns EBX,
which is what pulls the **caller's** entity home to EBX — the two are one
fixpoint, see the failure table) *and* ends the manager's parameter live range
before any call. The mechanism that does the second half is a call to a cluster
function that wants the manager in a fixed register: `manager->Flush()` takes its
`this` in **ESI**, so the pass passes the manager in **EAX** and copies it to ESI
at entry — exactly retail's `mov esi,eax` at 0x4423E2.

```cpp
#pragma code_seg(".text$04ap")

        AnimationManager_00442F50* manager, RenderEntity* entity) {
    int a = (int)entity->flags;
    entry_free_004524a1((void*)1);
    if (manager->quad_count) manager->Flush();
    a += (int)entity->strip_count;
    entry_free_004524a1(entity->texture);
    entry_free_004524a1((void*)(size_t)a);
}
#pragma code_seg()
```

Thirty-five further bodies were measured in the cluster this wave (on top of wave
17's thirty), each reporting the anchor's earned parameter registers, the
caller's prologue bytes and the region's raw byte difference:

| anchor body family | anchor entity | caller entity | caller | region |
| --- | --- | --- | --- | --- |
| manager live across the calls (wave-17 family) | EBX | EBX | 928, retail head | −1 (group A) |
| manager consumed by the *first* call (21 bodies: `free(manager)` first, accumulators from the entity or the manager, 1–4 accumulators, both declaration orders, entity used before/after) | ESI or EDI | **EBP** | 930, head `55 8b ac 24`, `ret 8` | −860…−890 |
| manager read early, manager written later, entity read-only across a call | ESI | EBP | 929 (coincidence), head `55 8b ac 24` | −870 |
| `manager->Flush()` inside the body | **EBX** | **EBX** | **929, retail head `53 8b d8`** | **0** |

The second and third families are the trap: once the anchor's entity misses EBX
the *caller* re-homes its entity to EBP, its ABI collapses to `RET 8` and ~870
bytes of the region change — so an anchor that "almost" works costs far more than
the byte it was meant to save. Two of the 35 (`u01`, `u06`) reached exactly 0
differing bytes; `u01` is the one landed.

## Group B/C (4 bytes each): the case-1 sum is the *left* operand

Wave 17's model had the mirrored case as `fabsf(w*s*0.5f) - (ro + pos + base)`.
Retail's bytes say the opposite operand order — it loads the position sum first,
then the `fabsf` chain, then `de e9` (`fsubp st(1),st`) with the sum in st(1) and
the extent in st(0), i.e. **`sum - extent`**:

```text
4448df: fld [ebx+0x34c] ; fadd [ebx+0x340] ; fadd [ebx+0x334]   ; sum
4448f1: fld [ebx+0x4c]  ; fmul [ebx+0x3c] ; fmul ds:0x470b0c ; fabs
4448ff: fxch st(1) ; fxch st(1)                                 ; d9 c9 d9 c9
444903: fsubp st(1),st
```

That also explains the gratuitous `fxch st(1); fxch st(1)` pair: with the sum
evaluated first, MSVC has to swap the operands for `fsubp` and its scheduler
leaves the cancelling pair in. Spelling the sum on the left reproduces all four
bytes with no other lever:

```cpp
case 1:
    world.m[12] = (entity->render_offset.x + entity->position.x + entity->base_position.x)
                - fabsf(entity->sprite_width * entity->scale_x * 0.5f);
    break;
```

(wave 17 tried four spellings of the *sign it had*, all of which emit the `fabsf`
chain first; the plain `/O2` oracle reproduces retail's order and the `fxch` pair
in 0.4 s, so the sign was the whole blocker for B/C.)

## Group D (18 bytes): the guard needs the redundant third test

Retail emits the `uv_scroll_x` comparison **twice** — `jp update` after the first,
then an identical `fld 0.0f; fld uv_scroll_x; fucompp; fnstsw ax; test ah,0x44`
and `jnp skip`. `||`-shaped sources (26 spellings over waves 16–17, plus five more
tried here: `&&`, negation, ternary, bitwise/int materialisation, locals) always
produce one comparison. A source with the redundant comparison spelled out does:

```cpp
if (*(void**)((unsigned char*)manager + 0x3ADA70) != entity->texture) goto update_stage;
if (entity->uv_scroll_x != 0.0f) goto update_stage;
if (entity->uv_scroll_x == 0.0f) goto skip_stage;
update_stage:
    { /* the texture-stage block */ }
skip_stage:
```

The third test is unreachable-when-false (the second only falls through when the
value is exactly `0.0f`), so the spelling is semantically identical to the `||`
form; MSVC 13.10 emits retail's `jp` + duplicated-block + `jnp` for it, 18 bytes.
