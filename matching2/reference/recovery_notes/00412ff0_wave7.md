## What the region is

The run-score state (`0x00474C40`, `ScoreState`) embeds a five-word `FrameTimer`
at `+0x14` (`gauge_timer`, `th10/game/score.hpp`).  Every retail caller pushes a
frame count and loads EDI with that global, then calls `0x00412FF0`: the gauge is
raised by `SetGauge`/`AddGauge`, `DecayGauge` (0x00418A00, same cluster) runs the
timer down by `-1.0f` per frame and only bleeds the gauge itself once the timer
has run out.  This entry adds a hold of `frames` frames to the timer and clamps it
to the end of its 130-frame animation:

* if `gauge_timer.current < 130`: advance the timer by `(float)frames`;
* if the advance overshot (`gauge_timer.current > 130`), clamp: lazily register the
  timer against the script-time frame delta (`g_score_default_speed`, 0x00476F78)
  when the `flags` bit 0 is still clear, then set `current = 130`,
  `elapsed = 130.0f`, `previous = 129`.

The lazy-registration block is the same five stores as the sibling
`ScoreState::SetGauge` (`src/game/score_bookkeeping.cpp`, 0x00418B80) and
`PlayerSchedulerRecord::SetSchedulerValue` (0x00405410) — `current = 0`,
`previous = -999999` (0x0xFFF0BDC1), `elapsed = 0.0f`, `speed = &g_score_default_speed`,
`flags |= 1` — in that source order, which is the order retail emits.

## Registers retail's callers use, and whether the emitted body keeps them

All nine retail call sites are the same protocol: `push <frames>` and
`mov edi,474C40h` before `call 0x412FF0` (frames 0x3C, 0x64, 0x78, 0x14 and 3 in
`manager_factories.cpp`, 0x0A in `boss_overlays.cpp`), and the callee returns
with `RET 4`.  So the convention is **score state in EDI, frame count at
`[ESP+4]`, `RET 4`** — neither expressible as a C++ declaration (`this` would be
ECX) nor bindable opaquely, because the callee the body must reach,
`FrameTimer::Advance`, keeps *its* receiver in ESI (a whole-program choice, see
`frame_timer.json`).  That is why the region merges into the frame-timer cluster
instead of getting a layout of its own.

The emitted body keeps the whole protocol: EDI holds the receiver from the entry
`cmp [edi+18h]` through the post-call `cmp [edi+18h]`, ESI is materialised with
`lea esi,[edi+14h]` as the advance call's receiver and is still the base of the
whole clamp block afterwards, and the only save/restore is `push esi`/`pop esi`.
`fild dword [esp+4]` converts the stack argument in place, and the call is the
plain `call 0x44BF40` (no indirection, because `FrameTimer::Advance` is defined in
the same `/LTCG` link).  EBX, EBP and EDX are never touched, so the callers'
registers survive.

## The load-bearing model details

1. **The guard keeps the member spelling and the clamp goes through an alias.**
   Retail addresses the two guards through the receiver (`cmp dword [edi+18h]`,
   `83 7F 18 82`) but the advance and every store of the clamp block through the
   timer pointer in ESI (`mov [esi+4]`, `mov dword [esi],0xFFF0BDC1`,
   `mov [esi+8]`, `mov [esi+0xC]`, `mov [esi+0x10]`, `mov dword [esi+4],130`,
   `mov [esi+8],130.0f`, `mov dword [esi],129`).  Writing the block through
   `gauge_timer.` (plain member access) makes the pass address it through EDI and
   the body differs in 14 bytes; `FrameTimer& timer = gauge_timer;` inside the
   first guard reproduces retail's split exactly.  No other shape of the *body* is
   needed — the alias is the whole difference.
2. **The alias has to be taken before the advance call.**  Its value is what the
   callee receives in ESI, and because the block after the call reads it again the
   pass keeps it in the callee-saved ESI rather than rematerialising EDI+0x14 —
   which is exactly what retail's uniform `[esi+…]` addressing shows.
3. **`__declspec(noinline)` on `Advance`** (already in `th10/math/timer.hpp`) is
   what keeps the call a call; the whole clamp then lives in the 93-byte
   contribution, and `#pragma code_seg(".text$04mreplay")` places it between the
   `.text$04layout` gap and the `.text$04zdecay` clamp sibling (`04l` < `04m` <
   `04z` in link name order).
4. **`previous = -999999`** is emitted as the immediate `0xFFF0BDC1`, the same
   sentinel the other two register blocks in this file family store; `-999999` is
   what the sibling `SetGauge` model writes.

void ScoreState::AdvanceGaugeTimer(int frames) {
    if (gauge_timer.current < 130) {
        FrameTimer& timer = gauge_timer;
        timer.Advance(float(frames));
        if (gauge_timer.current > 130) {
            if ((timer.flags & 1) == 0) {
                timer.current = 0;
                timer.previous = -999999;
                timer.elapsed = 0.0f;
                timer.speed = &g_score_default_speed;

            timer.elapsed = 130.0f;
            timer.previous = 129;
