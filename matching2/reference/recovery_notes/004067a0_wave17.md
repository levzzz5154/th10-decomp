# 0x004067A0 — 44/44 bytes, **EXACT**, landed (wave 17)

2026-09-19, agent `PoolShapeD`.  The per-frame animation-slot advance: the leaf
that walks the six entity slots of the animation manager and advances each slot
chain.  It reaches the per-slot advance through a bare `call`, so the register
pair that call uses — **owner in EAX, slot number in ECX** — is chosen by a callee
no declaration names.  Compiling that callee's body into the same link as an ABI
anchor is what fixes the pair, and the anchor's *clobber* shape is what fixes the
caller's own home (EDI) and its slot register (ESI).

## Retail, and the register the caller has to keep

```
4067a0  a1 10 78 47 00     mov  eax,[477810h]        ; the published slot state
4067a5  85 c0              test eax,eax
4067a7  57                 push edi

4067b7  8b c7              mov  eax,edi              ; -> the callee's owner register
```

Two things are fixed from outside this body.  `ECX` at entry is the declared
`__thiscall` receiver, and rooting the symbol is what pins it (measured below).
The pair the `call` uses is not: `0x004066E0` is still assembly, so no
declaration names EAX or ECX, and the whole-program pass has to derive the pair
from a body it can see.  The caller then follows that body: it keeps the owner in
**EDI** (callee-saved, because the anchor writes EDX and calls out) and the slot
number in **ESI**, copying `mov ecx,esi / mov eax,edi` at every iteration.

## The lever: the anchor's clobber shape picks the caller's homes

Six links were built with the *same* modelled caller, the same layout and the
same anchor address; only the anchor body (or its presence) changed.  Everything
else — context, gaps, bindings — was identical.

| anchor body for `0x004066E0` | caller's owner home | emitted | differing |
| --- | --- | ---: | ---: |
| **the retail body: x87 field pairs, an EDX field copy, the angle call and the dispatch call (landed)** | **EDI, slot in ESI** | **44** | **0** |
| cursor loop that only adds a float per entity (clobbers neither EDX nor ECX) | EDX, slot in ECX | 38 | 37 |
| the same plus `entity->motion_z = entity->source_z` (the `mov edx,…` field copy) | ESI, slot in ECX | 40 | 29 |
| the same plus the two x87 field pairs (no calls) | ESI, slot in ECX | 40 | 29 |
| the landed body, **no** whole-program root | **EDI as the incoming register** (unsaved), slot in ESI | 40 | 37 |
| **no anchor body** — callee declared `__thiscall`, symbol bound absolutely | EDI home, `push esi / mov ecx,edi / call` | 43 | 22 |

Read together the six rows say three separate things.

* **The argument pair is the anchor's, and it is earned from the first body on.**
  Every variant that has an anchor body, including the trivial cursor, emits the
  callee with the owner in **EAX** and the slot number in **ECX**.  The property
  is in the signature of the body: the owner is read exactly once, through the
  slot subscript `slots[index]` at `+0x14`, and the slot number only supplies
  that subscript.  No declaration can name that pair, which is why the callee has
  to be a compiled body in the link; the emitted anchor reproduces retail's own
  first two instructions — `push esi / mov esi,[eax+ecx*4+14h]`.
* **The caller's homes are the anchor's clobber set, not the caller's spelling.**
  With an anchor that writes no EDX (row 2) the pass parks the owner in the
  volatile EDX and keeps the loop counter in ECX — which is exactly the anchor's
  slot register, so no per-iteration copies are needed and the function shrinks
  to 38 bytes.  One `mov edx,…` in the anchor (row 3) evicts the owner to ESI;
  the x87 pairs add nothing (row 4 is byte-identical to row 3 — x87 never touches
  a GPR).  Only the landed body, whose loop also *calls out twice*, makes the
  caller reach past ESI for **EDI** and move the counter into ESI so the pair can
  be rebuilt per call: 44 bytes and zero differing bytes.  The 4-byte difference
  between row 5 and the landed row is exactly `push edi / mov edi,ecx / pop edi`.
* **Rooting is not decoration here, it is the entry convention.**  Row 5 is the
  same body with `roots` emptied: the pass then re-chooses the whole private
  convention and the owner arrives in **EDI as an argument, unsaved** (`mov
  eax,edi` with no `push edi`), 40 bytes and 37 differing.  That is the same
  register `0x004066C0` — the *other* caller of `0x004066E0` — uses in retail,
  and it is lever 4 of the wave contract: without the root nothing pins the
  declared `__thiscall` agreement.
* **Without a body the call shape is different, not merely mis-allocated.**  Row 6
  keeps the same source but strips the anchor: the callee becomes an opaque
  `__thiscall` binding, the receiver goes in ECX and the slot number is *pushed*
  (`push esi / mov ecx,edi / call`), 43 bytes / 22 differing, and the two ends of
  the call no longer agree with retail at all.  That is the control the task asked
  for: an opaque assembly callee cannot express retail's pair, and the anchor is
  what does.

## Full source text

`src/unidentified/FUN_004067a0_004067a0.cpp` (the landed file — the body plus the

```cpp
// 0x004067A0..0x004067CB (44 bytes): the per-frame animation-slot advance.
//
// Retail enters with the owner in ECX (a plain __thiscall receiver), keeps it in
// EDI across the calls and leaves with a plain RET after returning 1.  The
// per-slot advance it reaches through a bare `call` takes the owner in EAX and
// the slot number in ECX - a register pair no declaration names - so that
// callee is compiled into this same link as an ABI anchor (bottom of this file)
// and the whole-program pass derives the pair from that body, and the caller's
// own home from the registers that body clobbers.
extern "C" {
// 0x0044BC10: the signed-angle normaliser (stdcall, two floats, result in ST0).
float __stdcall Angle_NormalizeSum_0044bc10(float value, float limit);
// 0x004451C0: the per-entity animation dispatch.

// 0x00491C10: the loaded animation manager pointer.
extern void* data_00491c10;
}

struct Enemy_004067a0;

struct SlotOwner_004067a0 {
    unsigned char pad_000[0x0014];
    Enemy_004067a0* slots[6];                 // +0x0014, indexed by the slot number
    __declspec(noinline) int AdvanceSlot(int index);
    __declspec(noinline) int AdvanceAllSlots();
};

// Only the fields the slot walk touches; every offset is the retail one.
struct Enemy_004067a0 {
    unsigned char pad_000[0x0034];
    float angle;                              // +0x0034
    unsigned char pad_038[0x033C - 0x0038];
    float motion_x;                           // +0x033C
    float motion_y;                           // +0x0340
    int motion_z;                             // +0x0344

    float source_x;                           // +0x03B4
    float source_y;                           // +0x03B8

    SlotState_004067a0* state = data_00477810;
    if (!state || !(state->flags & 4)) {
        for (int index = 0; index < 6; ++index) AdvanceSlot(index);
    }

// ABI anchor for 0x004066E0.  This body is not recovered game code: the layout
// places it at the retail address so the bare `call` above bakes retail's own
// displacement, and export_bodies never selects it.  What it earns is the
// argument pair the caller above must use, and - through the registers it
// clobbers in the loop - the caller's own live-across-call homes.
#pragma code_seg(".text$01anchor")
__declspec(noinline) int SlotOwner_004067a0::AdvanceSlot(int index) {
    Enemy_004067a0* entity = slots[index];
    while (entity) {
        entity->motion_x = entity->source_x + 224.0f;
        entity->motion_y = entity->source_y + 16.0f;
        entity->motion_z = entity->source_z;
        if (entity->flags & 0x08000000u) {
            entity->angle = Angle_NormalizeSum_0044bc10(entity->spin, 1.5707963f);
            entity->flags |= 4;
        }
        DispatchAnm_004451c0(data_00491c10, (char*)entity + 8);
        entity = entity->next;
    }
    return 1;
}

```

The modelled body is the whole of `0x004067A0`.  The control flow is retail's:
the published state at `0x00477810` (a pointer whose bit 2 at `+0x58` suppresses
the advance) is tested first, the six slots `+0x14 … +0x2C` are advanced when it
does not, and 1 is returned either way.  The state read is a *pointer* load
(`mov eax,ds:0x477810` is `A1`), so the declaration is a pointer to a state
record, not a byte array.

## The 0x004066E0 anchor

The anchor carries retail's own shape — `push esi / mov esi,[eax+ecx*4+14h]`,
then per entity the two x87 field pairs (`+0x3B4 + 224.0f` into `+0x33C`,
`+0x3B8 + 16.0f` into `+0x340`), the `+0x3BC → +0x344` integer copy, the
conditional angle normalise into `+0x34` with the `| 4` flag, the dispatch on
`entity+8` with the manager from `0x00491C10`, and the `+0x44C` cursor advance.
Its argument pair is retail's, which is the whole point:

```text
4066e0: 56                   push esi
4066e1: 8b 74 88 14          mov  esi,[eax+ecx*4+14h]   ; owner in EAX, slot in ECX
...
406756: 8b b6 4c 04 00 00    mov  esi,[esi+44Ch]
40675c: 85 f6                test esi,esi
40675e: 75 90                jne  4066f0
406760: b8 01 00 00 00       mov  eax,1
406765: 5e                   pop  esi
406766: c3                   ret
```

Two measured differences from retail's own `0x004066E0` body, neither of which
matters because the anchor is never exported (only `export_bodies` output enters
the outer link):

* the anchor emits **135** bytes against retail's 134, because the model reads
  `entity->flags` twice (the test and the `|= 4`) and c2 keeps it in a register
  (`mov eax,[esi+364h] / test eax,8000000h` = 8 bytes) where retail tests the
  memory operand (`test dword [esi+364h],8000000h` = 7);
* the dispatch is declared `__fastcall`, so it emits `lea edx,[esi+8]` where
  retail has `lea eax,[esi+8]`, and the angle constant was written `1.5707963f`
  (`3FC90FDAh`) where retail pushes `3FC90FDBh`.  The float pool is the cluster's
  own `.rdata`, at `0x408000`/`0x408004`.

## What it unblocks

* **`0x004066C0` (25 bytes, `src/unidentified/unassigned_004066c0.cpp`)** is the
  other caller of the anchored `0x004066E0`, with the same 0..5 loop and the
  same `return 1`, but its owner arrives in **EDI unsaved**.  The row-5 control
  above is that exact convention, measured: dropping the root on this cluster's
  body emits `mov eax,edi` with no `push edi`.  So `0x004066C0` is now a shape
  question with a measured answer rather than a convention guess, and it can
  reuse this cluster's anchor verbatim.
* **`0x004066E0` itself (134 bytes, `src/game/fun_004066e0_004066e0.cpp`)** is
  now bounded from both sides: the anchor here is its argument pair and its
  register usage, and the only remaining dependency is `0x004451C0` (the
  dispatch it calls with the manager in ECX and the entity in EAX — LEVER 5 of
  the wave-11 note, now with the second call site in this model).  Recovering it
  needs one more anchor for that callee, not a new convention.
* **`0x00405E20` (163 bytes, `src/game/fun_00405e20_00405e20.cpp`)** is the
  region that publishes this function: `push 4067A0h` at `0x00405E8F` stores the
  address into a scheduler/task node.  This landing names the callback's
  convention (ECX receiver, plain RET, 1 in EAX) and the field layout the task
  node's callback reaches (`owner+0x14` slots, `owner+0x2C`, entity `+0x44C`
  chain, state `+0x58` bit 2), which is the scaffolding that region needs.
