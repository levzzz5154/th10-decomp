## Identity

Retail 0x00409E50 is byte-for-byte the same function as 0x0040C480
(`AnimationHandle::StopAtFrame2`) except for the stored constant: it loads the
script id out of the animation handle, resolves it through the animation lookup,
and stores the 16-bit value **1** into the object's +0x304 slot, then into every
direct child's object unless the object is already flagged at +0x18. It is the
frame-1 member of the StopAtFrame2 / StopAtFrame3 family, so it is modelled as
`AnimationHandle::StopAtFrame1`. The legacy readable reference at
`reference/legacy_semantic/src/render/anm_propagate.cpp` called the same body
`Anm_MarkHandleAndChildren` with the same offsets (+0x14 children, +0x18 solo /
children-flagged, +0x304 propagated value).

## Registers

Retail's callers put the **handle address in EAX** and nothing else; every call
site is `lea eax,[reg+disp]` or `mov eax,reg` immediately before the call
(e.g. `src/game/spell_card_end.cpp: `lea eax,[esi+768h]; call`; `src/game/
effect_pool_update.cpp: `lea eax,[edi+24h]; call`; `src/game/stage_background.cpp:
`mov eax,esi; call`). ECX and EDX are live-in dead: the body sets EDX itself from
`data_00491c10` before the lookup, and only defines ECX at 0x409e67. The lookup
0x004491C0 receives its context in EDX and its four-byte script id on the stack
(its receiver register is never written by any retail caller).

The emitted body keeps exactly that: EAX holds the handle address on entry, EDX
is loaded from `_data_00491C10`, the id is pushed, `call` reaches the co-compiled
0x4491C0, ECX is materialised with `mov $1` only after the call, and the body ends
in a plain `ret`. Nothing is pushed or popped by the function itself. Callers may
treat EAX, ECX and EDX as clobbered; EBX/ESI/EDI/EBP are untouched.

## Source (src/render/anm_propagate.cpp)

```cpp
// 0x00409E50 - resolve the animation object behind an animation handle and set
// its sprite word to 1, propagating that value to the object's direct children
// unless the object is already flagged as having processed them.
//
// The handle is the receiver and the only input: retail's callers put its
// address in EAX and nothing else, and the animation lookup never reads its own
// receiver, so the whole-program pass leaves EAX holding the dereferenced
// pointer and hands the lookup's id back on the stack.  Both are conventions
// only a native-LTCG cluster reaches; this unit is co-compiled with the
// StopAtFrame pair that owns 0x004491C0 (layout/ltcg/stop_at_frame_pair_0040c480.json).

struct AnimationLookupContext;

// The script id is a four-byte record so the lookup reads it from its stack
// slot; see the note in animation_manager_find_004491c0.cpp.
struct AnimationScriptId {
    int value;
};

struct AnimationTreeNode {
    AnimationTreeNode* object;              // +0x000
    AnimationTreeNode* next;                // +0x004
    unsigned char reserved_008[0x0C];
    AnimationTreeNode* children;            // +0x014
    int children_flagged;                   // +0x018
    unsigned char reserved_01c[0x2E8];
    unsigned short stop_frame;              // +0x304
};

class AnimationManager {
public:
    void* __fastcall Find(AnimationLookupContext* context, AnimationScriptId id);
};

struct AnimationHandle {
    unsigned int value;
    __declspec(noinline) void StopAtFrame1();
    __declspec(noinline) void StopAtFrame2();
    __declspec(noinline) void StopAtFrame3();
};

extern "C" AnimationLookupContext* data_00491c10;

#pragma code_seg(".text$05propagate")
void AnimationHandle::StopAtFrame1() {
    AnimationScriptId id;
    id.value = (int)value;
    AnimationTreeNode* node = reinterpret_cast<AnimationTreeNode*>(
        reinterpret_cast<AnimationManager*>(data_00491c10)->Find(data_00491c10, id));
    if (node != 0) {
        node->stop_frame = 1;
        if (!node->children_flagged) {
            for (AnimationTreeNode* child = node->children;
                 child != 0; child = child->next)
                child->object->stop_frame = 1;
        }
    }
}
#pragma code_seg()
```

## Driver (layout/ltcg/stop_at_frame_pair_0040c480_context.cpp)

The old driver only exercised the pair. The frame-1 entry point must be called
too, or the whole-program pass has no caller to derive its EAX convention from.

```cpp
// Compiler context only; never selected as recovered game code.
#include "../../src/render/anm_propagate.cpp"

#pragma code_seg(".text$70context")
int __stdcall StopAtFrameCompilerContext(AnimationHandle* handles, int count) {
    while (count--) {
        handles->StopAtFrame1();
        handles->StopAtFrame2();
        handles->StopAtFrame3();
        handles++;
    }
    return 0;
}
#pragma code_seg()
```

## Integration

`register_cluster.py` cannot express this landing: it requires every function's
region to be owned by the layout's single `source`, and the cluster is
multi-source. `promote_scratch.py --scratch /tmp/AnmPropagate/msvc --address
0x409E50 --apply` was used instead; it copies the source, the layout and the
driver, then rewrites the one region record (0x00409E50 flips asm -> semantic
with symbol `?StopAtFrame1@AnimationHandle@@QAEXXZ`). The manifest's `symbols`
map still binds `_asm_FUN_00409e50_00409e50` to 0x00409E50, so the ~30 assembly
callers that spell that name keep resolving to the same address.
