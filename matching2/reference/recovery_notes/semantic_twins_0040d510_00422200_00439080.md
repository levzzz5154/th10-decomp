# Exact semantic twins at 0040D510, 00422200 and 00439080

The three remaining 28-byte regions reuse already exact native-LTCG models.
The fresh scratch links and the maintained-source probes compare all 84 bytes
against retail. The selected code contains ordinary C++ and no inline assembly.

| Retail entry | Model reused | Registered layout |
| --- | --- | --- |
| 0040D510 | SetFlags at 00418EC0 | `layout/ltcg/cl_0040d510.json` |
| 00422200 | SetFlags at 00418EC0 | `layout/ltcg/cl_00422200.json` |
| 00439080 | Deletable_Delete at 0040D710 | `layout/ltcg/dtor_delete_00439080.json` |

Both flag setters receive the owner in EAX and return with plain RET. They
conditionally set bit 1 at offset +4 of the two objects at owner offsets +8
and +C. Their entire retail bodies equal the body at 00418EC0, including
registers and branch encodings. The existing array-walking compiler context
can therefore be renamed and positioned without changing the semantic model.

Fresh Ghidra decompilation confirms 0040D510's operation. The real call at
0040A667 is preceded by MOV EAX,ESI. Ghidra has no Function object or xrefs for
the 00422200 fragment; read-only assembly-context and memory queries confirm
its complete matching 28-byte body and plain RET instead.

00439080 receives the object in ESI, passes it in EAX to 0043A910, tests bit 0
of the stack flags, conditionally calls free at 004524A1, and returns the
object in EAX with RET 4. Fresh Ghidra assembly-context evidence shows every
instruction, while its decompilation of 0043A910 identifies the receiver as
in_EAX. The selected model is the existing 0040D710 destructor with the cleanup
target rebound from 0040D530 to 0043A910. The compiler-only cleanup anchor
models the real cleanup's first derived-vtable store, receives the object in
EAX, and is excluded from recovered code. Its vtable symbol binds to 0046F80C.

Scratch evidence is retained under:

- `matching2/build/experiments/rank_twins_setters_find_semantic_twins_20260928a/`:
  `summary.json`, the two `probe_*.json` files, and `ghidra-evidence.json`.
- `matching2/build/experiments/rank_twins_439080/`: `measurement.json`,
  `ghidra_evidence.json`, and `probe/report.json`.

The maintained probes are under
`matching2/build/experiments/rank_twins_maintained/`, with their JSON summaries
beside that directory. The probes require each complete selected contribution
at its retail address; they do not mask instruction bytes or rewrite address
operands. Registration uses the atomic cluster-registration tool, which keeps
the prior assembly rows and existing address aliases.
