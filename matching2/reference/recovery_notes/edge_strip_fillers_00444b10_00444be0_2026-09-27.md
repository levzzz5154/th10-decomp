## Geometry and source shape

The vertex type is 28 bytes: XYZ, reciprocal W, color, U, and V. The fillers
write reciprocal W at +0x0C, color at +0x10, U at +0x14, and V at +0x18;
XYZ remains untouched. Each pass visits alternate vertices with a 56-byte
stride. The horizontal leaf interpolates U from right to left and supplies
top/bottom V in its even/odd passes. The vertical leaf interpolates V from
bottom to top and supplies left/right U. Both return -1 for count < 3 and
otherwise return zero.

The exact source uses natural signed index loops starting at zero and one,
with index += 2. The compiler derives retail's unsigned half-count trip
counters and retains the count > 0 and count > 1 loop guards. Writing the
moving coordinate, subtracting the step, then writing the fixed coordinate,
color, and reciprocal W reproduces the x87 store/subtract schedule. The
integer denominator ((count + 1) / 2 - 1) produces retail's FIDIV sequence.
The second pass accesses the receiver's rectangle again, preserving its
observed reload after the first loop.

An explicit remaining-count model had the correct 201-byte extent but eight
byte differences in each leaf. Placing reciprocal W and color before the
coordinates changed fifty bytes in each leaf. The natural loop and ordered
writes solved both bodies without assembly, byte injection, opaque barriers,
or instruction rewriting.

## Private ABI and native context

The ordinary member declarations take count and vertices. Native LTCG
assigns count to EAX, the receiver to ECX, and vertices to EBX. Both return
with a plain RET. A small stdcall conditional context calls either member
with the same arguments and establishes the tuple. It is compiler context,
not recovered game code.

The horizontal source is included in the context driver. The vertical source
is a separate /GL input declared by additional_sources. The native map proves
that each whole function is emitted by its declared compiler input. The
shared header defines the vertex, rectangle, and receiver fields. No extra
source flags or runtime bindings are required; __fltused is the sole metadata
binding and neither selected function contains a relocation.
