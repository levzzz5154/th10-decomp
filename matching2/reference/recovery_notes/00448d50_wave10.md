## What the region needed beyond the wave-8 model

Wave 8 left the body settled and 2 bytes short with the entry convention already
exact. Everything that remained was the **entry-register agreement with the four
functions in the link** - one of them this region itself, three of them its
callees - and only a native `/LTCG` link that can see the callees' bodies assigns
it. The layout therefore carries a compiled anchor for each callee: a C++ body
selected into the link, placed at the retail address by the gaps (so the calls
bake retail's displacements and the object needs no relocation), declared in
`anchors` and never exported as recovered code.

The two measured effects, in the order they had to be earned:

| # | register home | how it was earned |
|---|---|---|
| 1 | `0x004489D0` manager in **EDX**, entity in **EBX**, handle in **EAX** | The leaf body keeps the entity as a long-lived base (`lea 0x4(%ebx)`, used again at `entity->id` at the very end) *and* stops reading the manager after its last list store: the id is carried in a local (`int id = ++manager->next_id;`) so `entity->id = id; *(int*)out = id;`. With the manager read again at the end of the body the pass gave it **ECX** and the node temp EDX (the wave-8 arrangement); shortening the manager's live range moved the manager to EDX and left the entity in EBX - retail's pair. |
| 2 | `0x0043E710` resource in **ECX**, object in **EAX**, index in **EBX** | This was the hard one. A faithful three-parameter body whose resource, object and index are all live across the internal `Entity_Init` call gets **(ESI, EAX, EBX)**: the pass gives the first crossing parameter a callee-saved entry because it is free in the caller. Adding a *fourth* value that crosses the same call - a derived pointer `entries = *(uchar**)(res + 0x11C)` used before and after it - takes ESI out of the entry set and yields **(ECX, EAX, EBX)**, with the body's prologue then reproducing retail's own shape (`push ebp / push esi / mov esi,ecx / push edi / mov edi,eax`). Every lighter perturbation was measured and did not move it (see the shapes table). |
| 3 | `0x00449950` manager in **ESI** | The allocator's body holds the manager around the allocation and entity-initialisation calls, which is the callee-saved shape `AnmAllocSlot`'s landed `anim_pool_alloc_00449950.json` uses; this cluster carries its own equivalent anchor, `roots` stays empty. |
| 4 | this region's **position in EDI**, resource/out/index on the stack, `ret 0xC` | The pass picks it; the wave-8 model already reproduced it and the anchors did not disturb it. |
| 5 | this region's **out in EBP** | The model must *read* the out slot after the registration call - `RegisterPrimaryBack(manager, out, object); return out;`. Returning the call's result directly (`return RegisterPrimaryBack(...)`) lets the pass drop the EBP home and reload the slot from its stack slot at the call: 91 bytes, 4 short. With `return out;` it emits retail's `mov ebp,[esp+10h]` prologue and `mov eax,ebp`. |
| 6 | the caller's **move order** at the registration call | 2 bytes: retail emits `mov esi->ebx` before `mov ebp->eax`, the natural parameter order. Declaring the registration with the handle record *second* and the entity *third* (`RegisterPrimaryBack(manager, out, entity)`, called with `(... , out, object)`) makes the pass emit that order. Nothing here needs a `roots` entry, and no declaration names a register: every
one of these is the whole-program pass's choice over the bodies in the link.
