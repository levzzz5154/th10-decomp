### What the shapes taught

* The recoverable structure is real: the object has **three 0xD8-byte
  subsystems** at +0x3C, +0x114, +0x1EC whose five stored fields sit at
  +0x00, +0x08, +0x8C, +0xD0, +0xD4 with values 0, 0x3E7, 0, 1, 0. That was
  derived from retail's store list (five perfect arithmetic chains of stride
  0xD8) and it reproduced retail's fifteen stores exactly.
* Retail's element order is `[f8C f00 fD4 fD0 f08]` for element 0 and
  `[f08 f8C f00 fD4 fD0]` for elements 1 and 2 - the first block is the source
  order, the later blocks are that order rotated right by one. A plain loop
  reaches the correct *extent* but not the order.
* **Store form is what decides the CLF/const placement.** With a 15-statement
  scalar version the pass groups stores by value (all 1s, then all 0s, then all
  0x3E7s) and the extent balloons to 252-295 bytes. A three-iteration loop that
  the unroller rotates keeps the regs right (1 -> ESI, 999 -> ECX) but regroups
  the 999 store. Only *volatile* field stores (or a barrier after every store,
  which stops unrolling) pin retail's order.
* `_ReadWriteBarrier()` is the lever that fixes the *clear* shapes: with a
  barrier between the nine clears the pass emits retail's one load/and/store
  followed by eight `and [esi+off],eax`; without them it hoists each load and
  splits all nine (+61 bytes).
* The first clear must be read through `self` (an `[edx+0x334h]` load) and only
  stored through the pool register: `unsigned int first = ((unsigned int *)self
  ->pool)[0x6C/4]; pool[0x6C/4] = first & ~1u;`; a plain `pool[0x6C/4] &= ~1u`
  lets the compiler materialise the pool base first and costs 3 bytes.
* The pool pointer must stay live across the first `memset` (store the `0xFFFF`
  word through `pool`, not through `self->pool`) or the pass homes it in EDI and
  the 1 constant falls back to immediates (+7 bytes, and ESI is lost).
* The remaining 25 bytes are scheduler placements of *non-memory* instructions -
  the two callee-saved pushes, the `xor` for the 0 constant, the `~1` mask and
  the `lea` - which no source spelling tried (volatile/barrier/preamble variants,
  symbol vtable, mask variables, pointer forms, peeled and unrolled loops,
  loop-start variants) moved. A 120-permutation sweep of the loop body order and
  a 32-combination sweep of barrier placements both peaked at the shapes above;
  v_r2 was 45 differing, the volatile-element variant 29, the current one 25.
