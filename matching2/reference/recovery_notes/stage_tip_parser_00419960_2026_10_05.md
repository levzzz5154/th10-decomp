# Stage-tip parser 0x00419960 — recovered 2026-10-05

`ParseStageTips` (1498 bytes) is byte-exact in cluster `stage_reader_parser`,
source `msvc/src/game/stage_tip_parser.cpp`. The cluster context holds the `Tip`
constructor and `FindNamedValue` as anchors plus a synthetic address-taking root.

## What the source had to look like

- `Tip` has a real constructor (`new Tip`), and `TipNode::Unlink()` is an inline
  member (`next = 0; previous = 0;`). The duplicate record is `*other = *tip`,
  then `owner = other`, then `Unlink()`.
- `FindNamedValue(name, table, count)` is a plain out-of-line loop.
- The splitter is `void Split(char* key, char* value, char* line)`. The
  parameter order decides the argument load order at the non-inlined inner-loop
  call (line first, then key shared with the first `strcmp`).
- The outer loop calls the splitter twice in a row (both inlined); the inner loop
  is `if (remaining > 0) do { ... } while (remaining > 0);`, which keeps the
  splitter out of line there.
- Every line read goes through an inline four-argument forwarder
  `ReadScriptLine(cursor, out, remaining, capacity)`.
- `Scale`: `float scale = (float)atof(value); tip->scale = scale;` then compare
  with the `4.0f` / `-4.0f` literals (`fcom m32`).
- `Color`: `char* green = second; second = strchr(second, ',');`.
- String and float literals are bound to retail addresses with `data_aliases`
  and `constant_aliases`.

## Mechanism: which pointer an inlined `strcpy` walks

Retail's first inlined `strcpy(key, line)` walks the destination
(`mov cl,[esi+eax]; mov [eax],cl`), the second walks the source. The data/line
register assignment (ESI/EDI) follows from this.

- `MscStrcpy` gives each `strcpy` two argument temporaries (`RdrArgument`). The
  loop optimizer keeps the one with the lower symbol id as the walked pointer:
  fresh (ascending) ids give the source-walked form, descending ids the
  destination-walked form.
- Ids are recycled LIFO from a per-function free list. While inlining,
  `ActualsToFormals` frees the call site's argument temporaries in argument
  order, and `InlineInlinee` then frees the callee's unused return-value
  temporaries. The next inlinee read pops them in reverse.
- The read of the splitter pops two temporaries before the `strcpy` arguments.
  So the `strcpy` arguments are the 3rd and 4th pops:
  - nothing freed before: both fresh, source walked;
  - an inlined call with four or more arguments just before (the line-read
    forwarder): descending pair, destination walked;
  - after a three-argument `void` inlinee: 3rd pop recycled, 4th fresh, source
    walked. A `char*`-returning splitter frees two more temporaries and flips
    the second site instead, which is how the return type was pinned to `void`.
