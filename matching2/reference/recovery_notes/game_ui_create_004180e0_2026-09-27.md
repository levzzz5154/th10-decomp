# UI creation and publication, 0x004180E0

> Integration status (2026-09-27): the exact routine(s) described here are now integrated in the maintained project. The combined 487,936-byte executable matches retail byte for byte. See [the fourth checkpoint](native_recoveries_2026-09-27_fourth.md) for current proof and remaining work. Scratch-only and promotion instructions below describe the original recovery handoff. Unmatched candidates remain in scratch.

The complete **107-byte** routine is recovered as readable typed C++ without
inline assembly, naked bodies, encoded instructions, masking, or instruction
rewrites. It extends the registered native-LTCG worker family. All six earlier
selected functions remain exact in the fresh maintained probe.

The entry takes its one argument on the stack, returns the allocated UI pointer
in EAX, and ends with RET 4. The UI occupies 0x60 bytes: configuration begins at
+0x24, the started flags are at +0x58, and the supplied argument is stored at
+0x5C. Retail clears a flag, runs configuration initialization, and then clears
the entire object; the constructor preserves that order and the allocation-null
branch. It then evicts the device's managed resources through COM slot +0x14,
publishes the UI pointer at 0x00477810, raises flag 4, and starts the worker.

The genuine configuration initializer is included from the maintained
`game_config_defaults.cpp` under a separate code section and remains an
unselected compiler anchor. All **125 anchor bytes** independently equal
retail. The native compiler knows its unused fastcall argument and supplies the
configuration pointer in EDX. No argument adapter supplies recovered code.

`GameUiThreadHost::Spawn` supplies the previously recovered EDI receiver and
two stack arguments at 0x00420EA0. The selected caller passes the no-argument
thunk at 0x00417C70 through an explicit function-pointer cast to the worker's
entry type, preserving the retail address. This address-of binding uses the
full VA; a relative-code binding supplies only an RVA to this absolute pointer
use. Correcting that binding fixes the first candidate's sole differing byte.
