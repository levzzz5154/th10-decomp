# Recovery emitter decision: measured native residual at 0x0040B9F0

This experiment does **not** authorize promotion of the decision routine. Its whole native C++ body is 111 bytes, but the fresh normal probe reports 48 differing bytes. Maintained inputs were not changed. The old candidate note is historical: it describes an unbuilt member cutover and reverses the divisible-by-12 return condition.

Fresh live Ghidra MCP decompilation/disassembly of th10.exe was retained in `matching2/build/experiments/emitter_decision_0040b9f0_2026_09_27/ghidra_decompile.txt` and `ghidra_wrapper.txt`. The body receives the emitter in EDI, calls the existing tick helper with the tick state in ESI, returns its result in EAX, and uses plain RET. Callback 0x0040BA70 receives ECX, saves EDI, assigns the emitter to EDI, calls the decision, restores EDI and returns.

If TickRecoveryState_0040bd20 reports completion, the decision writes 2 to 0x00491FB8 when input bit 0x1000 at 0x00491FF4 is set and writes 15 otherwise; it returns 1. Otherwise it increments the signed counter at emitter +0x24 with 32-bit wrapping. Eligible nonzero remainders modulo 12 return 6; multiples of 12 and all ineligible paths return 1. Eligibility requires tick +0x74 bit 2 clear, emitter +0x20 bit 1 clear, tick +0x74 bit 1 set and 0x00474E30 bit 8 set. The tick-state pointer is at emitter +0x18.

The scratch cluster extends the current `recovery_tick_state_0040bd20.json`, compiles the genuine existing Tick source with its **unchanged global stdcall signature**, and compiles the complete new decision and complete callback. The original synthetic Tick walker remains unchanged. A root preserves the callback's public ECX receiver. The new header checks the 0x28 emitter extent and relevant member offsets, and provides a read-only view of the separately recovered tick flag word. The scratch source is ordinary C++, without inline assembly, naked functions, emitted opcodes or encoded instructions.

Fresh final normal proof: `matching2/build/experiments/emitter_decision_0040b9f0_2026_09_27/probe_final.json`. The native decision has its full 111-byte extent and the actual EDI ABI. Its first 46 bytes match; the first difference is the counter-load operand at 0x0040BA1E. The 10-byte callback and all 93 previously selected Tick bytes are exact. The original maintained Tick source is byte-for-byte unchanged. The normalization records zero instruction-byte changes, zero address-operand changes, zero masks, and no reference bytes used to build the native image.

The complete residual is recorded in `measured_residual.json`, with native/retail bytes in `probe_final_native.bin` and `retail_decision.bin` and the native disassembly in `probe_final_disassembly.txt`. Native SHA-256: `0447ceab9578d8cde00110a70cf7cd178b16cef19b5811736660f20216504b84`. Retail decision SHA-256: `a1ee8ee5591b88230179011d2cd15a5d3636fc40dfda2ef504d1e9b92b0ffdc4`.

The remaining mismatch is local lifetime allocation. Retail keeps the counter in ESI and copies it to EAX immediately after testing the first flag. Its divisor is ECX and result is EAX. The native model holds the counter in EAX, uses ESI for the divisor, and carries the final result through ECX before moving it to EAX. Other source forms yield a branchless constant-selection tail or initialize the result too early. The bounded trials covered direct return, shared result, nested eligibility, result initialized from the counter, comma assignment, a genuine inline eligibility helper, a free stdcall decision, and a signed/unsigned alias increment; the free-function ABI form did not change the 48-byte residual. Invalid extents were not treated as byte measurements.

A concrete untested next lever is replacing the flag overlay with a shared full tick-object declaration, while retaining the existing global Tick body/signature and verifying all 93 bytes again. That gives the optimizer direct member access and different alias information without changing the operation or adding a register hint. Co-compiling the genuine 1568-byte script executor at 0x0040BD80 would also expose real call clobber information; that is a substantive future recovery, not a placeholder anchor. The full goal remains active.
