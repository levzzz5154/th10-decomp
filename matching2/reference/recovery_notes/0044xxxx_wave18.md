## What decided these bytes

1. **The whole block is dead code.** A scan of the image finds no `call`, `jmp` or
   four-byte pointer to any of the 95 addresses; the only two references at all are
   the intra-block loop jumps `0x449506 -> 0x449510` and `0x449776 -> 0x449780` (both
   from a fragment to its own tail). They are the out-of-line copies of helpers whose
   call sites were all inlined, so nothing outside a region constrains its ABI: the
   byte gate is the only oracle, and a shape that reproduces the extent usually
   reproduces the whole body.

2. **A leaf with no live-in register simply compiles.** `/Gz` (the project default)
   makes every free function `__stdcall`, so `ret N` in retail is the normal
   declaration, not a private convention. `0x441F10/30`, `0x4452D0` are the MSVC x87
   intrinsic expansions of `atanf`/`cosf`/`sqrtf` (the argument stays on the stack),
   `0x441F20` is `asinf`, which has no single FPU instruction and therefore calls the
   CRT helper `__CIasin` on the x87 stack. The four one-byte regions are empty
   functions (`void f() {}` emits exactly `ret`).

3. **A region that reads a register before writing it needs the receiver moved.**
   Almost all of the block reads its object from EAX (some from ESI/EDI), which no
   declaration can name. The recipe that landed 22 of them is the one in
   `ltcg_cluster_landing_procedure.md`, unchanged: model the function as a **member**
   of its data type, put each body in its own `#pragma code_seg(".text$NN")` section,
   and drive the whole family from one **array-walking context** - that context shape
   is what makes the `/GL` pass pick the retail register (usually EAX).

4. **A family is one build.** Four layouts carried 6, 10, 3 and 3 functions. The
   context calls every modelled function through its own loop, so `/OPT:REF` keeps
   each complete contribution alive *through a call* (lever 9) and each function's
   convention is chosen in the same whole-program pass that retail's link ran.

5. **Reusable shapes measured this wave.**
   - A whole-record copy through a computed base is what emits retail's
     `add ecx,18h` + `[ecx]` form: `*(Triple*)((char*)dest + 0x18) = *this;`. The
     field-by-field spelling compiles to the same size but with direct `0x18(%ecx)`
     displacements (18 vs retail's 20 bytes) - the classic lever-2 sink.
   - Two early `return 0` statements (not `||`) are what emit retail's
     `je bad / cmp / jb good / bad: xor eax,eax; ret / good:` layout
     (`0x44D3E0`, `0x4493C0` needed the `if/else` with one result).
   - The float wrapper `0x443680` computes the **first** output as `a*d - b*c + e`:
     the multiply operand order is observable, so the formula, not the algebra, is the
     model.
   - `(char*)this + frame_base + offset` adds the *pointer* first in every spelling
     tried; retail's offset-first order is unreachable (see `0x44DF20` below).

## Layout rules a later wave needs

- **Section names sort the link order.** The linker lays `$`-suffixed sections out in
  *name* order, so every extent - gap, function, context - must take the next index in
  address order (`.text$00gap`, `.text$01`, `.text$02gap`, ...). Naming a gap after
  the function it follows (`03` + `03gap`) puts the gap after the function and drifts
  the whole span by its size.
- **The context symbol goes to `/ENTRY` verbatim.** A C++ free function needs its
  mangled spelling (`?NameCompilerContext@@YGHPAPAXH@Z`); an `extern "C" ...
  __stdcall` needs `_Name@8`. Passing the source name leaves LNK2001 against a
  double-underscored name.
- **A float-bearing cluster must bind `__fltused`** (`kind: metadata`), and a call
  through an import slot from a cluster must bind the pointer symbol
  (`_data_00466130`) as `data` in the layout's `absolute_symbols` - the outer fixed
  link is `/NODEFAULTLIB`.
- **A constant argument in the context lets the pass specialise.** `0x44C6E0` was
  8 bytes short until the context passed `index + n` instead of literals; if a
  function's extent is short, look at the context's argument values first.
- The emitted size of every function and the context is read back from
  `cluster.map` (`build_cluster` fails with a size report) - two of the four layouts
  needed only the context size corrected (137, 309, 76, 87 bytes).
