# Scheduler callback allocation with complete callers, 2026-09-28

**Unpromoted:** the selected callback allocator at 0x00449ED0 remains 74 bytes with 22 byte differences. The maintained body retains its inline assembly. This experiment tests the new complete actual caller graph; it does not reclassify the allocator as assembly-free or exact.

Fresh live Ghidra MCP decompile/disassembly reads for 0x00449ED0, 0x004089C0 and 0x0043C970 are retained in `matching2/build/experiments/callback_create_full_callers_2026_09_28/`. They establish the original allocator's callback stack parameter, EAX result and RET4; the callback routine itself uses the canonical fastcall TaskRoutine context ABI.

The isolated native link contains the full recovered player-manager task initializer (211 bytes at 0x004089C0), full screen-effect selector and nine-way switch (396 bytes at 0x0043C970), complete allocation factory C++ model (77 native bytes; the retail function is 82 bytes at 0x0043C8B0), complete primary/secondary callback creation and registration wrappers (43 bytes each at 0x0044A000/0x0044A030), and genuine primary/secondary registration bodies (131 bytes each). Only the original 74-byte 0x00449ED0 allocator is selected. A 100-byte compiler context calls the full screen-effect factory and full player-manager initializer; it is synthetic and never exported as recovered game code. The selected allocator's linker root retains its public stdcall ABI.

Two complete-source representations were measured with standard native probes. `typed_private_node_valid.json` uses the genuine 36-byte typed constructor previously recovered from the MessageHost callback allocation pattern. Its return is exposed as canonical SchedulerTask*. `canonical_task.json` instead wraps one actual SchedulerTask member at offset zero, names the canonical callback and linked-list fields, and uses a whole-word +4 flags view to retain all flag bits. Both preserve the complete success constructor, null branch, and unconditional tail. Effect callers' void* routine carrier is converted to TaskRoutine at the call boundary; their code and meaning are otherwise retained. Both variants emit all 74 bytes with the same 22 differences.

Retail keeps zero in ECX and the constructor's captured flags in EDX. Native C++ exchanges those two roles. The retail tail loads callback in EDX, clears register/remove fields through zero ECX, reads and sets flags in ECX, and then publishes callback and flags. Both C++ representations publish callback earlier and clear the other two routine fields later. Caller owners and priorities occupy EBX/ESI/EDI as expected, but their live ranges do not determine this allocator's internal ECX/EDX coloring.

Independent complete-byte comparisons of the native image show both requested callers exact (211 + 396 bytes), both registrations exact (131 + 131 bytes), and both create wrappers exact (43 + 43 bytes). The genuine full factory C++ model compiles to a complete 77-byte contribution. Fresh Ghidra and maintained manifest evidence establish that retail is 82 bytes through RET20 at 0x0043C8FF. Its 77-byte overlapping prefix differs in 60 bytes and the native contribution is five bytes shorter. The native model folds the timer flag clear into a memory AND, schedules the zero EAX later, and differs in argument/store scheduling. That factory is unselected and remains assembly in the maintained project. Both anchor comparison files explicitly record compiled versus retail extent; `factory_disassembly_comparison.txt` and fresh factory Ghidra evidence document the residual.

The first layout guessed an 85-byte synthetic context; MAP evidence showed 100 bytes and the loader rejected it before body comparison. The corrected context extent yielded the first valid measured source representation. This layout adjustment is not an additional source experiment.
