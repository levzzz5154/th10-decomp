## Semantic and ABI model attempted

The archived semantic family in `matching2/reference/legacy_semantic/src/render/camera_setup.cpp` and `include/th10/render/camera_setup.hpp` was used as the behavioral basis:

* camera setup flushes pending animation work, derives the viewport aspect, builds look-at and perspective matrices, applies device transform states 2 and 3, and publishes the manager clip words;
* default viewport writes the fixed `640x480`, `min_z=0`, `max_z=1` six-word block, calls device `SetViewport`, and resets device streams;
* the 0x00448270 path obtains the back buffer and level-zero destination surface, copies with point filtering, then releases both COM surfaces;
* the 0x00448450 path clears an existing indexed resource, obtains the back buffer, records dimensions, creates the texture/plain surfaces through raw device vtable slots, seeds them with surface copies, and releases the back buffer.

Retail disassembly and the `0x00438A60` caller were used to preserve the custom manager/slot/rectangle register-and-stack shape in the disposable model. The model called the existing flush, indexed-resource-clear, matrix, surface-copy, and stream-reset boundaries as absolute retail dependencies and used raw D3D vtable slots for device operations.
