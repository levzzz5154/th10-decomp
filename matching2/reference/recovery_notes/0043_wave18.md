# Block 0x0043xxxx — wave 18 sweep (78 candidate regions, 1,971 bytes)

2026-09-19, wave 18, agent `VeinBlock43`.  The block is the still-`asm`,
`owner: null` slice of 0x00430000..0x0043FFFF: 78 regions of 64 bytes or fewer
from 0x00434B50 to 0x0043E580.  **55 landed (1,270 bytes), 23 dropped.**  (A 56th exact region in the range, `0x0043E500`, was landed by wave 17 and is not part of this block.)

Every landing is a byte-exact region in the maintained tree, verified with
`probe.py` against `matching2/msvc`.  The two probes below are the gate that was
run for each entry; the whole block re-probes `EXACT` 78/78 (the 22 dropped ones
are still the original `__declspec(naked)` bodies, which are exact by
construction but carry no readable C++).

```
python3 matching2/tools/matching/probe.py --source <src> \
    --project matching2/msvc --output /tmp/VeinBlock43/probe --show 30
```

34 of the 55 needed the native-LTCG cluster path (their entry register is not
one a C++ prototype can name: object in EAX, or a parameter in EAX/ESI/EDI).
Each cluster is a `layout/ltcg/region_<addr>.json` plus its `_context.cpp`
driver, both registered.  The other 21 are ordinary translation units.

## What moved the regions

1. **A plain unit with the right calling convention.**  Eight one-byte `ret`
   bodies, `return -1;`, a `strlen` leaf, two `LegacyString::AssignRange`
   callers and the two `int3`-free leaves landed as written.  The one recurring
   trap was `/Gz`: the project compiles `__stdcall` by default, so every region
   whose retail epilogue is a plain `ret` (or `ret 8`) has to be declared
   `__cdecl` explicitly — that was the single byte that cost `0x00436780`,
   whose `ret 4` spelling differed from retail only in the epilogue.
2. **The cluster driver is the register chooser.**  The synthetic array-walking
   caller (`while (count--) (*items++)->Method(args);`) reproduces retail's
   private conventions without any declaration: object in EAX for the small
   leaves, in ESI when the record must survive a call (`0x00436900`,
   `0x00439xxx` destructors), in EDI when the record stays live across a loop
   that calls out (`0x00438910`, `0x004390A0`).  `__declspec(noinline)` on the
   modelled function is mandatory; without it a small free function is inlined
   into the driver and its section comes out empty.
3. **A cluster layout is also the only way to bind names `bind_relocations.py`
   refuses.**  `0x00439350` calls the local `WINNLSEnableIME` thunk at
   `0x0045232C` (`call rel32`, not the IAT) and reads three globals; in a
   cluster both are `absolute_symbols` entries, which is a route the manifest
   `symbols` map does not offer for a decorated local name.
4. **Struct padding has to be written out.**  `0x004369E0` stores seven words in
   ascending order but skips `+0x10C` and `+0x110`; a struct without those two
   reserved words shifts every store after the third.
5. **Statement order is load-bearing in both directions.**  `0x0043C930` had to
   be re-ordered so the flag load follows the `+0x2C` store (and still differs —
   see the dropped list), while `0x0043CBF0` needed the `memset` first and
   `return 0;` last to earn retail's trailing `xor eax,eax`.

## The 23 dropped regions

All 23 are still the original `__declspec(naked)` assembly in the maintained
tree and the manifest still records them as `asm` with a null owner, so nothing
half-converted is registered.  The delta below is measured against retail with
`probe.py`; where a model was never emitted the delta is the reason it was not.


### `0x00434B50` (16 bytes) — dropped

**Dropped — 3 differing bytes of 16.**  All nine spellings of `*this > other`
emit `mov ecx,[ecx] / mov edx,[esp+4] / cmp ecx,edx` where retail has
`mov edx,[ecx] / mov ecx,[esp+4] / cmp edx,ecx`: the loaded field takes ECX and
the argument EDX, retail the other way round.  Member, `__fastcall` with an
unused second parameter, `__stdcall` with the pointer on the stack, negated
comparisons, a named temporary, a pointer local, a `reinterpret_cast` and the
`? 1 : 0` spelling all emit the same pair; the all-stack `__stdcall` form has
retail's EDX/ECX assignment but a `ret 0xC` and three stack arguments.  A pure
allocator tie-break inside one function; a cluster driver would only re-roll the
same choice.

### `0x00434B80` (15 bytes) — dropped

**Dropped — no model emitted.**  The region reads EAX and never writes it
(`push 0; push 8; mov edx,0x46ECE8; call 0x43E460`), and the callee `0x43E460`
starts `push esi; mov esi,eax`, i.e. it takes its object in EAX as well.  Both
ends of the call site need an EAX convention no declaration can name, so this is
an anchor-body job: a compiled `0x0043E460` body in the same native link whose
shape makes the pass hand it EAX.

### `0x00434BA0` (17 bytes) — dropped

**Dropped — 4 differing bytes of 17.**  The cluster puts the object in EDX and
the mask in ECX (`mov ecx,[edx+0x60] / shl eax,4 / xor ecx,eax / ... /
mov [edx+0x60],ecx`); retail has the object in ECX and the mask in EAX
(`mov edx,[ecx+0x60] / shl eax,4 / xor edx,eax / ...`).  The driver shape did
not move either home; two registers to fix in a 17-byte leaf.

### `0x00435270` (12 bytes) — dropped

**Dropped — emitted 10 bytes against retail 12.**  Retail re-materialises the
advanced cursor (`mov ecx,[eax]; add ecx,4; mov [eax],ecx; mov eax,ecx;
mov eax,[eax]; ret`); every spelling tried (`return *advanced;`, `cursor =
advanced; return *cursor;`, raw `unsigned int*` arithmetic) emits the load
without the `mov eax,ecx`, so the extent gate rejects the model.

### `0x00435280` (51 bytes) — dropped

**Dropped — emitted 52 bytes, first difference at `+0x00`.**  The rounding
comes out one byte long: the `% 4` is taken in ECX (`81 e1 03 00 00 80`) where
retail takes it in EAX (`25 03 00 00 80`).  Separately, the inlined `strlen`
keeps the text pointer in ESI and adds a `push edi`, while retail keeps it in EAX
with a single `push esi`; the manual-loop and `*cursor += size` spellings are
59–64 bytes.  Retail's own shape (`mov eax,[edx]; push esi; lea esi,[eax+1]`) is
the inline `strlen` of a value that is *reloaded* for the final `+=`.

### `0x004357D0` (36 bytes) — dropped

**Dropped — no model emitted.**  EAX is live-in and feeds `0x434C30`'s second
parameter, which that callee also takes in EAX (`mov esi,ecx; mov edi,eax`);
the region itself writes only ECX (`mov ecx,ds:0x477850; shl ecx,4;
add ecx,0x4923B0; call`).  Both ends of the call need an EAX convention.

### `0x00435FA0` (36 bytes) — dropped

**Dropped — emitted 30 bytes against retail 36.**  Retail's index argument
arrives in EAX (`mov ds:0x48F860,eax; lea eax,[eax+eax*2]; shl eax,2`); the
cluster's `while (count--) Init(count);` driver left it elsewhere, so both the
first store and the `lea/shl` pair differ.

### `0x004367D0` (5 bytes) — dropped

**Dropped — emitted 26 bytes against retail 5.**  Retail is a single
`jmp _memmove` (`e9 …`), the tail call the compiler makes when `return
memmove(d, s, n);` is the whole body.  This toolkit emits the explicit
`mov/mov/mov; push; push; push; call; add esp,0xC; ret 0xC` sequence for every
spelling measured (including explicit `__cdecl` prototypes of `memmove`), so the
5-byte thunk is not reachable from source here.

### `0x00436D60` (55 bytes) — dropped

**Dropped — no model emitted.**  Three pointers are live at entry: EAX (the
three counters), EDX (the packed nibble pair) and ESI (the trip counter), and
the body reads all three before writing anything.  No declaration names EAX/EDX
together with ESI, and a driver would have to reproduce all three homes.

### `0x00438ACF` (1 bytes) — dropped

**Dropped — a bare `int3`.**  Alignment padding emitted by the linker, not a
function body; it has no C++ spelling and belongs to whatever region the padding
sits after (the manifest records it as its own `asm` region).

### `0x00439080` (28 bytes) — dropped

**Dropped — no model emitted.**  The region calls `0x43A910` with the object
in EAX (`mov eax,esi; call 0x43A910`) and that callee's body starts
`mov esi,eax`, so an anchor body for `0x0043A910` is the prerequisite.

### `0x004392DC` (4 bytes) — dropped

**Dropped — four `int3` bytes.**  Alignment padding between functions; not a
function body.

### `0x00439700` (45 bytes) — dropped

**Dropped — emitted 41 bytes against retail 45.**  `Direct3DCreate9` and the
`TextLog_0044B8E0::AppendLine` failure report are reachable (the device global
and the import both bind), but `AppendLine`'s registered convention puts the log
object in **EDI** (`mov edi,0x474F70; call`), which a declared call site can
only reproduce by pushing it; the closest plain model is 41 bytes and differs
from the third instruction on.  Needs the `0x0044B8E0` body in the same native
link (anchor).

### `0x0043A590` (47 bytes) — dropped

**Dropped — the cluster accessor emits 52 bytes against retail 47.**  The
three status bytes are packed into `[esp]` before `midiOutShortMsg`; the driver's
three scalar arguments did not land in retail's homes (status ECX, first EDX,
second at `[ESP+4]`), and the packing sequence differs from the second
instruction.  The 47-byte form was not reached in five driver/body shapes.

### `0x0043A700` (37 bytes) — dropped

**Dropped — best spelling 34 bytes, shift spelling 41, retail 37.**  Retail
keeps the argument in EAX and builds the result from its sub-registers
(`mov ecx,eax; mov edx,eax; shr ecx,0x18; shr edx,0x10; mov [esp],cl;
mov [esp+1],dl; mov [esp+2],ah; mov [esp+3],al; mov eax,[esp]`); the union and
byte-array spellings either reload the argument for the `ah`/`al` stores (41
bytes, first difference at `+0x06`) or skip the `mov ecx,eax`/`mov edx,eax`
copies (34 bytes).  The library spelling `_byteswap_ulong` is not in this
toolkit's headers.

### `0x0043B890` (33 bytes) — dropped

**Dropped — emitted 31 bytes against retail 33.**  The declared extent contains
retail's *second* `ret` (`…mov [esi+4],0 / ret / ret`): the source's own epilogue
is the first one, so a single modelled function is 31–32 bytes.  This is a split
extent (two adjacent 1-byte `ret` stubs), i.e. a `merge_parts`/`carve_region`
job, not a source-shape residual — the same pattern as the standalone
`0x0043B8C0` one-byte region that did land.

### `0x0043BC20` (23 bytes) — dropped

**Dropped — emitted 28 bytes, 22 differing bytes, first at `+0x00`.**  Retail
clears the flag with the memory form `and DWORD PTR [edx+0x40],0xFFFFFFFE`;
every spelling measured — `object->field &= ~1u`, the same through a raw
`unsigned int*` cast, `volatile`, a one-bit bitfield, a two-bitfield pair and a
literal `0xFFFFFFFE` — emits load/and/store (`8b 4a 40; 83 e1 fe; 89 4a 40`),
three bytes longer, and everything after it shifts.

### `0x0043C910` (18 bytes) — dropped

**Dropped — emitted 14 bytes against retail 18.**  Retail opens with
`test esi,esi; je` and takes the object in ESI: the helper is a null-tolerant
free function.  A cluster member cannot express it — `if (this)` is unreachable
and the compiler drops the test (14 bytes) — and modelling it as a free function
moves the argument home off ESI.

### `0x0043C930` (57 bytes) — dropped

**Dropped — emitted 57 bytes, 14 differing bytes, first at `+0x00`.**  The
statement order was already matched to retail (store `+0x2C` first, flag load
second, `flags = current | 1` last) and the `0x00476F78` data address binds
correctly; the backend still hoists `mov ecx,[eax+0x40]` above the
`mov DWORD PTR [eax+0x2C],1` store, where retail keeps the store first.
Scheduling, not source shape.

### `0x0043D640` (37 bytes) — dropped

**Dropped — no model emitted.**  EAX is live-in and its value is the name that
`0x44B360` takes in EAX (`push 0; push 0; call`, two further stack arguments for
this region, `ret 8`).  Needs an anchor body for `0x0044B360`; the declared
`__stdcall` form would push the name and lose the whole call shape.

### `0x0043D670` (32 bytes) — dropped

**Dropped — no model emitted.**  Same shape as `0x0043D640` one field
different: EAX holds the name `0x44B360` consumes, with a single stack argument
and `ret 4`.  Same anchor prerequisite.

### `0x0043DA80` (44 bytes) — dropped

**Dropped — no model emitted.**  The call `push 1; push 0; call 0x44D440`
leaves the stream pointer in EAX (`0x0044D440` starts `mov edi,eax`), so the
region reads EAX at entry through the `mov eax,[esi+0x5208]` chain.  An anchor
body for `0x0044D440` is required.

### `0x0043DDB0` (52 bytes) — dropped

**Dropped — no model emitted.**  Four registers are live at entry: ESI (the
record), EDI (the value being inserted), ECX (the running slot pointer, built by
`lea` from ESI) and EAX (the loop index written first).  The body is a 12-slot
search with two exits and a bounds-checked store; reproducing it needs a driver
that fixes ESI+EDI together, which the two-argument shapes tried elsewhere did
not deliver for the neighbouring regions.

## Integration statement

* **55 regions** flipped to `semantic` in `matching2/msvc/regions.json` with the
  emitted (decorated) symbol, plus the one `symbols` binding
  `__imp__CreateThread@24 = 0x00466118` that `0x0043D0F0`'s call site needs
  (added with `bind_relocations.py --apply`, 5,285 → 5,287 entries).
* **35 cluster layouts** registered (`layout/ltcg/region_<addr>.json` with its
  `_context.cpp` driver), all under `matching2/msvc/`; every one is a
  single-function schema-1 cluster whose driver is a synthetic caller and is
  never exported as recovered code.

  `0x00435FA0`, `0x0043A590`, `0x0043B890`, `0x0043C910`, `0x0043C930`): they were
  copied in by the bulk behaviour of `promote_scratch.py`, which registers every
  cluster layout the scratch manifest lists, not only the promoted region's.

  `register_cluster.py --unregister --apply`; the seven region records are back
  to their pre-registration state in the manifest.

  The gate used throughout is `matching2/tools/matching/probe.py` against
  `matching2/msvc`, which compiles the unit (or the cluster) and compares the
  emitted bytes with the retail `.text`.
