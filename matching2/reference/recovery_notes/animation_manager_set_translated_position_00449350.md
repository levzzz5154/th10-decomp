# `AnimationManager_SetTranslatedPosition` (`0x00449350`)

## Current status

Keep this 111-byte region in its retail assembly source until an exact C++
whole-call-cluster route is available. Live Ghidra confirms that the ordinary
behavior is simple, but the fixed entry consumes the position record in ESI;
no standalone MSVC x86 function declaration assigns an argument there. Earlier
standalone and bounded LTCG candidates did not match, so this is a compiler
ABI blocker rather than a claim that the behavior is not understood.

## Live Ghidra evidence (`th10.exe`)

`get_function_by_address(0x00449350)` reports body `0x00449350..0x004493BE`
(111 bytes) and an autogenerated `__fastcall` view with ECX, EDX, and one
stack argument. The disassembly shows the actual data flow:

```text
00449350  mov eax,[esp+4]       ; script id from the one stack slot
00449354  push eax
00449355  call 004491c0         ; Find(manager in EDX, id on stack)
0044935a  test eax,eax
0044935c  je   004493bc
0044935e  fld  dword ptr [esi]  ; position pointer is a private ESI live-in
00449360  fadd dword ptr [470b4c] ; +224.0
00449366  fstp dword ptr [eax+340]
0044936c  fld  dword ptr [esi+4]
0044936f  fadd dword ptr [470b48] ; +16.0
00449375  fstp dword ptr [eax+344]
0044937b  mov ecx,[esi+8]
0044937e  mov [eax+348],ecx     ; copy z bits directly
00449384  mov ecx,[eax+18]
00449387  test ecx,ecx
00449389  jne  004493bc
0044938b  mov ecx,[eax+14]      ; first child-list node
0044938e  test ecx,ecx
00449390  je   004493bc
00449392  ...                   ; write the same +340/+344/+348 record
004493b5  mov ecx,[ecx+4]      ; next child-list node
004493b8  test ecx,ecx
004493ba  jne  00449392
004493bc  ret  4
```

The output is the animation object's translation record at `+0x340`: x is
offset by 224, y by 16, and z is copied. If the object's `+0x18` child flag is
zero, it walks child-list nodes at `+0x14`; each node's first dword points to
the child object and its second dword links to the next node. A null lookup is
a no-op. The only callee is `0x004491C0`, the primary/secondary script-id
lookup; its body compares the requested id against the first dword of each
node's object and returns that object.

Ghidra reports four caller functions and five callsites:

| Caller | Callsite(s) | Live setup before call |
| --- | --- | --- |
| `0x00408D60` | `0x00409170` | ESI points to `[EDI+0x379C]`; EDX is the global animation manager; the script id at `[EDI+0x774]` is pushed. |
| `0x00409280` | `0x00409772` | ESI points to `[EBP+0x379C]`; EDX is EDI (the animation context); the script id is pushed. |
| `0x0040DC80` | `0x0040E39D` | ESI points to `[EBP+0x2C]`; EDX is the global animation manager; the id from the current list entry is pushed. This call is in a loop. |
| `0x004250B0` | `0x004256B9`, `0x004256C4` | ESI points to a stack position record; EDX is the global animation manager; each site pushes a different animation id. |

The ESI live-in survives into the function while ECX is an unused/passthrough
fastcall slot, EDX holds the manager, and the script id remains on the stack.
`RET 4` removes exactly that one stack argument.

## Failed exact-output route and next dependency

The earlier D2702 sweep tested readable member forms with by-value and
reference position arguments, parameter order changes, explicit x87
temporaries, and a bounded native-LTCG context with `Find` and the
`0x00449470` stop-frame member. The closest 111-byte candidate differed in
63/111 bytes from offset `+0x03`; it used `RET 8` instead of `RET 4`, emitted
the x87 load/add sequence in the opposite order, and had different branch
layout. No semantic candidate was retained.

The next useful experiment must make the private input flow visible across
the call graph: compile semantic forms of the four direct callers (or
equivalent compiler-driving contexts that actually hold the position in ESI)
with this setter, `0x004491C0` (`Find`), and the sibling `0x004492F0`
(`SetPosition`). Preserve the manager in EDX, the id as the sole stack
argument, the position pointer in ESI, and the retail x87 operand order. The
fixed contribution must remain exactly 111 bytes before any manifest change.
