# Animation handle release: `0x00421300`

`src/render/anm_handle_release.cpp` now gives this region an ordinary C++
model. The connected Ghidra `th10.exe` project provides enough evidence for its
behavior and public entry contract.

## Ghidra evidence

Ghidra lists one direct caller, `FUN_00417870`, at `0x00417B4C`. Its disassembly
pushes `0x00491C28` and calls `0x00421300`. At the callee entry, the prologue
reads that argument from the stack; the function ends with `RET 4`. The caller
does not prepare an ECX argument, and the callee does not read ECX. Ghidra's
initial `__thiscall` label is therefore not the observed boundary contract.
A one-pointer `__stdcall` C++ function expresses the stack argument and callee
cleanup.

The decompilation and disassembly show this behavior:

1. If the control block's dword at `+0x6FC` is `1`, load the lookup context
   pointer from `0x00491C10` and process the three handles at
   `0x00477824`, `0x00477828`, and `0x0047782C` in that order.
2. For each nonzero handle found in the primary bucket, then the secondary
   bucket, write `2` to the matching animation object's word at `+0x304`.
   When its dword at `+0x18` is zero, also write `2` to `+0x304` for each
   object referenced by its child list at `+0x14`.
3. Clear the three handle globals and set the control block dword to `2`.
4. Independently, clear `0x00491BEC` if it is nonzero.

The search behavior comes from Ghidra's `FUN_004491C0` decompilation and
disassembly: handle zero returns null; otherwise it compares the first dword
of each registered object while walking the primary list, then the secondary
list. The C++ model spells out that read-only walk, avoiding the helper's
private call shape (context in EDX, handle on the stack, unused ECX input).

## Symbol and limits

The entry implementation exports the x86 C-linkage symbol
`_ReleaseAnimationHandles_00421300@4` and has an `/alternatename` fallback from
the existing assembler call name `_asm_FUN_00421300_00421300`. The manifest
now identifies the decorated C++ symbol as the semantic region entry while
retaining the old name as the caller's link alias.

This is a semantic source model, not a byte-equivalence claim. Directly
expressing the lookup and child loops changes register allocation, instruction
selection, branch layout, and likely the function extent. The Ghidra behavior
and caller contract are represented, but no build, probe, or test was run, so
the linker fallback and generated bytes remain unverified here.
