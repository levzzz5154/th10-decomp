# `__ArrayUnwind` at `0x004525A1`

`ArrayUnwind_004525A1` is represented as ordinary C++ that calls the supplied
element destructor in reverse construction order.

## Ghidra evidence

Live Ghidra identifies the function as `void __stdcall __ArrayUnwind(void *,
unsigned int, int, void (__thiscall *)(void *))`, spanning
`0x004525A1..0x004525CF`. The entry uses a standard EBP frame via the CRT SEH
prolog helper, and the return instruction is `RET 0x10`, so the callee removes
the four argument words.

The body decrements the count at `[EBP+0x10]` before its signed-negative test.
For each remaining element it loads the cursor from `[EBP+8]`, subtracts the
stride at `[EBP+0xC]`, stores the decremented cursor back, then calls the
callback at `[EBP+0x14]` with that cursor in ECX. It repeats until the decremented
count is negative. Ghidra lists two callers: the vector-constructor exception
cleanup helper at `0x00452577` and another cleanup helper at `0x00452647`; both
pass the four stack arguments in this order.

The C++ model retains the count's decrement-before-test behavior, uses unsigned
32-bit wrap plus the sign bit to express the x86 signed test without signed
overflow, subtracts one stride before each callback, and declares the callback
as `__thiscall`. The SEH prolog and epilog are compiler/runtime frame machinery,
not part of the element traversal.
