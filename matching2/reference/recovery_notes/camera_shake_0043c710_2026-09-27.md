# Camera-shake callback 0x0043C710: first native measured model

The required retail body is 349 bytes, ending with RET at 0x0043C86C. The
bounded fresh native search produced a useful complete 344-byte C++ callback,
not an exact recovery. The final normal focused probe rejects the unchanged
349-byte target because it is outside the callback's complete MAP contribution.
There is no promotion recommendation or maintained source/manifest change.

## Retail evidence and typed model

The live Ghidra function API has no function at this address. A bounded live
read_memory request obtained all 349 bytes; these exactly match the stable
retail PE oracle. They decode the public ECX callback, integer EAX status,
plain RET, and only these calls: FrameTimer::Tick at 0x00404ED0 (ESI receiver),
and two NextRandomModulo calls at 0x0043CB80 (ECX state 0x004918B0, EDI modulus3).
Registration data at 0x0043CA64 supports preserving the callback as a public
root rather than transforming its own ECX entry.

The record contains signed strength at +0x1C, signed attack/sustain/release
at +0x20/+0x24/+0x28, and an embedded FrameTimer at +0x30. It returns7 while
0x004918A4 is set, returns1 without advancing when the scene pointer0x00477810
is null or its +0x58 flags fail the two masks, then advances the timer. The
ratio ramps during attack, stays1 during sustain, and decreases during release;
expired envelopes return7. Release conversion is unsigned even though the
frame comparisons are signed. Each modulo3 choice writes shakeX0x00491E64 or
shakeY0x00491E68 to zero, positive amount, or negative amount. Unexpected
values leave that coordinate untouched. Active updates return1.

## Genuine compiler ABI anchors

The scratch driver includes the actual maintained frame_timer.cpp and a copy
of the actual prng.cpp with only its code-section tag changed. Both helpers
stay unrooted. A dynamic timer loop and runtime-modulus array loop prevent
constant-divisor specialization; the callback itself is a root. Tick's native
ESI convention and the RNG's native ECX/EDI convention are correct. Independently
comparing complete native helper contributions against retail gives exact
72-byte timer and exact88-byte RNG bodies in every measured model. Only the
callback is selected by the new scratch cluster, so existing helper ownership
remains separate.

## Resolved source-shape evidence

The baseline ordinary amount local kept the result on the x87 stack across
both genuine RNG calls and emitted300 bytes. The correct multiply/materialize
shape requires an explicit float strength conversion and one volatile
write-through of an otherwise ordinary amount local:

```cpp
float amount;
*(volatile float*)&amount = (float)strength * ratio;
```

That emits retail's FILDstrength, FMULST,ST1, FSTP[ESP+8], FSTPST0 before the
first RNG call. A double cast or implicit integer multiply instead uses FIMUL;
volatile compound assignment adds unwanted stores/reloads. The amount's later
positive reads use ordinary integer dword copies, and negative reads use FLD
and FCHS, matching retail's shapes.

A typed scene record and direct global member access recover the retail scene
pointer in ECX and its flags in EAX. Per-operand unsigned casts in the release
ratio recover retail attackEAX/currentEDX/sustainECX homes and the repeated
release conversion. Casting only the finished signed sum lets the compiler
reuse the comparison sum, removing the retail seven-byte repeated calculation.

## Remaining measured differences

The final344-byte callback first differs at +0x1D (0x0043C72D): it saves ESI
before the scene gate, while retail delays the save until the gate succeeds.
During the release comparison it saves EBX transiently and computes a+s with
LEA before adding release, costing three extra bytes versus retail's
load-release-into-ESI and two ADDs. The second switch's negative case shares the
scene-gate return instead of emitting retail's separate return. These control
and register-allocation differences account for the net five-byte deficit.
The raw aligned comparison reports249 differing overlapping bytes; shifted
instruction blocks inflate that count, so it is not a recovered-byte metric.

Eight main source variants plus four independently isolated multiplication
variants were bounded. Tests included early-return versus nested scene gates,
ordinary and volatile amount locals, per-operand unsigned conversions,
selective release read, volatile durations, explicit second-switch returns,
and a release-total local. The348-byte volatile-duration model is structurally
worse: it changes branch structure, reloads all durations, and restores ESI
immediately after Tick. Source sum reordering alone emits an identical344-byte
model. No broad context sweep was performed.
