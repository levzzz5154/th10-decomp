# 0x004267F0 rotated region classifier (recovered 2026-10-05)

`src/game/trigger_region_004267f0.cpp` compiles to the retail 471 bytes in the
`trigger_region_004267f0` cluster. `make` and `make EXACT=1` pass. This
supersedes `trigger_region_004267f0.md` (the 483-byte attempt).

The instruction stream was right early on; what differed was which vector got
which stack slot (retail: copy/lower at ESP+0, offset/upper at ESP+0xC, the
operator temporary at ESP+0x18).

## How c2 lays out aggregates in the frame

Traced with `reference/compiler_traces/stackpack/trace_stackcolors_cl.py`
(plain `cl /O2`, prints every stack element with name, size and weight, the
colour it receives, and the allocation order).

* Every stack symbol is an element with a weight = number of references.
  Elements are processed by size, then by descending weight.
* `colorElemental` tries the existing colours from the newest to the oldest
  and takes the first one whose members do not interfere; otherwise it opens a
  new colour.
* Colours are allocated from the newest to the oldest, so colour 0 (the one
  opened by the heaviest element) gets the lowest offset.
* `QSortColors` (weight*1000/size) only runs for more than 0x80 colours or
  when optimising for size.

So the heaviest variable sits at the bottom of the frame, and a lighter
variable can only get there by sharing a colour with it.

## Applied here

Retail needs the colour {copy of the offset, lower corner} to be heavier than
{offset, rotated x, upper corner}. With separate variables the in-place rotated
offset (11 references) is the heaviest and lands at ESP+0. Reusing one variable
for the copy and the lower corner makes it 15, and a separate `upper` (6) then
shares the offset's colour:

    Point3 rotated = position - *origin;
    Point3 lower = rotated;          // copy used by the rotation
    rotated.x = ...; rotated.y = ...;
    lower = rotated - half_size;     // assignment: goes through a temporary
    Point3 upper; upper = rotated + half_size;

Also: a declaration with initialiser builds the operator result in place; an
assignment builds it in a temporary and copies it with integer moves (the
`fstp [esp+18h] / mov edx,[esp+18h] / mov [esp],edx` pattern).
