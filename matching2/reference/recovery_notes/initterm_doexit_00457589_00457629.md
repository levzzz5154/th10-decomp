# `__initterm` / `_doexit` ABI audit

## Result

The live Ghidra program is `th10.exe` (`x86:LE:32`, image base `0x00400000`).
The disassembly establishes the behavior of both CRT routines, but neither
current body can yet be replaced by an ordinary MSVC C++ definition while
preserving its observed entry/return behavior. `__initterm` has a private
EAX-plus-stack argument convention. `_doexit` has an ordinary three-argument
`__cdecl` surface but installs and removes a caller frame through the VC7.1
SEH prolog/epilog sequences; it also calls `__initterm` using that private ABI.
The two naked bodies remain in
[`initterm_00457589.cpp`](../../msvc/src/unidentified/initterm_00457589.cpp)
and [`doexit_00457629.cpp`](../../msvc/src/unidentified/doexit_00457629.cpp).

No manifest or symbol-header changes were made. No build, probe, or test was
run, so no source-level replacement or code-generation equivalence is claimed.

## `__initterm` at `0x00457589`

The function walks an array of four-byte initializer pointers over the
half-open interval `[begin, end)`. It skips null entries and invokes every
non-null entry with no arguments. The live instruction sequence is:

- Save ESI, copy EAX to ESI, then compare ESI with `[ESP+8]` after the push.
- Load each pointer, skip zero, otherwise `call eax`; advance by four bytes.
- Return without removing the single stack argument.

The caller at `0x00457629` confirms the private ABI twice. For the first
range, it pushes `0x00473058`, places `0x00473050` in EAX, calls `0x00457589`,
then pops the upper-bound word. For the second range, it pushes `0x00473064`,
places `0x0047305C` in EAX, calls, and pops the word. Thus the callee receives
the lower bound in EAX and the upper bound at `[ESP+4]` on entry. Its own
`push esi` makes that upper bound appear at `[ESP+8]` in the loop. The
initializer callbacks are called as no-argument function pointers.

Ghidra's signature and variable listing represent the stack-resident upper
bound as one `__cdecl` parameter; its pseudocode separately exposes the lower
bound as `in_EAX`. The call sites confirm both values, but the one-parameter
prototype is not a complete ordinary C++ declaration of the entry ABI. The
disassembly is authoritative for the EAX lower bound and stack upper bound.
MSVC 13.10's ordinary `__cdecl`, `__stdcall`, `__fastcall`, and `__thiscall`
forms do not name this EAX/stack pair. A semantic C++ function with a normal
prototype would therefore be called with the wrong ABI.

## `_doexit` at `0x00457629`

Ghidra recovers `void __cdecl doexit(UINT code, int quick, int
return_to_caller)`. Its function-variable listing places these values at
`Stack[0x4]`, `Stack[0x8]`, and `Stack[0xc]`. The wrappers and their call sites
agree on their meanings:

- `_exit(code)` calls `doexit(code, 0, 0)`.
- `__exit(code)` calls `doexit(code, 1, 0)`.
- `__cexit()` calls `doexit(0, 0, 1)`.
- `FUN_0045771d()` calls `doexit(0, 1, 1)`.

The body locks CRT lock 8 and checks the global at `0x004774B0`. If that value
is already one, it stages the requested code on the stack, calls
`GetCurrentProcess`, pushes the returned handle, then calls `TerminateProcess`.
This is the normal Win32 pair: `GetCurrentProcess` is `WINAPI`/`__stdcall` with
no parameters; `TerminateProcess` is `WINAPI`/`__stdcall` with `(HANDLE,
UINT)`. The code is staged before the zero-argument call so that it is already
in place as `TerminateProcess`'s second argument. The latter callee removes
both arguments.

The function then writes one to `0x004774AC` and stores the low byte of
`return_to_caller` at `0x004774A8`. If `quick == 0`, it pops the on-exit table
from `0x0049930C` downward in four-byte steps until it is below the lower
bound at `0x00499310`, skips null slots, and calls each callback with no
arguments. It then calls `__initterm` on `[0x00473050, 0x00473058)`. The
second range `[0x0047305C, 0x00473064)` is processed for both quick and normal
exit.

After the initializer ranges, the call to `FUN_004576D8` is not an ordinary
zero-argument helper even though Ghidra lists it as a separate function. Its
six-byte body compares `[EBP+0x10]` with EDI, which `_doexit` set to zero, and
calls `FUN_00453B3F(8)` only when `return_to_caller` is nonzero. That unlock
helper is `__cdecl(int)`, with the caller removing its argument; it calls
`LeaveCriticalSection`, a `WINAPI`/`__stdcall` function. The split `FUN_004576D8`
body depends on the active `_doexit` frame, so a standalone ordinary C++ call
would not preserve its observed behavior.

For `return_to_caller == 0`, `_doexit` writes one to `0x004774B0` and calls
`___crtExitProcess(code)`, a `__cdecl(int)` helper whose implementation ends
in `ExitProcess(code)` and does not return in the normal case. For a returning
call, control branches to `0x004576E6` and invokes the frame epilog before
returning to the caller.

## Helper ABI and frame evidence

| Call | Evidence-backed ABI/behavior |
| --- | --- |
| `__SEH_prolog` at `0x00454BBC` | The caller pushes frame size `8` and handler value `0x0046AB18`. Its disassembly establishes the EBP frame, saves EBX/ESI/EDI, links the registration record through `FS:[0]`, and returns to the next `_doexit` instruction with the transformed frame active. This is a frame-building prolog sequence, not an ordinary helper returning with a normal caller stack. |
| `__lock` at `0x00453C0C` | `__cdecl(int)`. `_doexit` pushes `8` and removes that one word with `pop ecx`. |
| `GetCurrentProcess` via IAT slot `0x00466144` | `WINAPI`/`__stdcall(void)`, returns a process handle in EAX. |
| `TerminateProcess` via IAT slot `0x00466148` | `WINAPI`/`__stdcall(HANDLE, UINT)`. The call sequence supplies the handle and staged code, and the callee removes both. |
| On-exit entries and `__initterm` entries | Called indirectly with `call eax` and no pushed arguments; the observed callback shape is `void callback(void)`. |
| `__initterm` at `0x00457589` | Private convention: begin in EAX, end on stack at `[ESP+4]` on entry; caller removes the stack word after return. |
| `FUN_004576D8` at `0x004576D8` | Six-byte shared block reads `_doexit`'s `[EBP+0x10]` argument and EDI directly. Do not model as an ordinary external zero-argument helper. |
| `FUN_00453B3F` at `0x00453B3F` | `__cdecl(int)` unlock helper; `_doexit`'s shared block pushes `8` and uses caller cleanup. Internally calls `LeaveCriticalSection` through its IAT slot. |
| `___crtExitProcess` at `0x00457547` | `__cdecl(int)`, normal behavior does not return because it ends in `ExitProcess`. `_doexit` pushes the code immediately before calling it. |
| `__SEH_epilog` at `0x00454BF7` | No explicit parameters; uses EBP and `FS:[0]` to unlink the active SEH record, restores saved registers and the prior frame, and returns to the original caller. This is the matching frame epilog, not a standalone semantic helper. |

## Remaining limit

The behavioral pseudocode is recoverable, but source conversion is blocked on
an ordinary C++ expression of the EAX/stack `__initterm` convention and a
compiler-generated SEH frame that preserves the exact `_doexit` exception and
return paths. Replacing either with a normal prototype or turning the
frame-dependent `FUN_004576D8` block into a regular helper would be an
unsupported ABI guess. The inline assembly is retained until that boundary is
modeled without losing the observed call and frame behavior.
