# 0x00408880 and 0x00408860 landed plain; 0x00437160 held at 156/157 by register assignment

2026-09-19, wave 17. Two untouched assembly regions are recovered as ordinary C++
and one attempt is recorded at a measured one-byte delta. **The plain path sufficed
for both landings**: neither region calls anything, neither needs a symbol
binding, and neither needs a cluster layout, a context driver or an anchor.

`src/unidentified/unassigned_00408880.cpp` (the whole change to that unit):

```cpp
// 0x00408880..0x00408894: saturating tick of one counter field.
//
// The body is a plain member: `this` arrives in ECX, the field at +0x84 is
// read, incremented while it is below 99999 and written back. The image leaves
// the resulting value in EAX, which a void member reproduces exactly; the
// region has no caller and no pointer to it anywhere in the executable, so the
// result register is dead.
//
// 0x00408860 is the same body one field lower at +0x80 and stays assembly.

struct CounterState_00408880 {
    char pad_000[0x84];
    int field_084;
    __declspec(noinline) void Tick();
};

void CounterState_00408880::Tick() {
    if (field_084 < 99999)
        ++field_084;
}
```

`src/unidentified/unassigned_00408860.cpp` is the same source with `0x80` for
`0x84` and `CounterState_00408860` for `CounterState_00408880`.

```
retail 0x408880: 8b 81 84 00 00 00  3d 9f 86 01 00  7d 07  40  89 81 84 00 00 00  c3
                 mov eax,[ecx+84h]  cmp eax,1869Fh    jge    inc  mov [ecx+84h],eax  ret
```

Facts behind the model: the compare is `jge` against `0x1869F` (99999), so the
guard is `field < 99999` with a signed field; both regions end in a plain `ret`
(no stack arguments), so the receiver is `__thiscall` and `this` is the only
entry register; there is a `CC` pad on both sides, so each region is a complete
aligned function and not a fragment of a larger one. No `E8` call and no 32-bit
reference to either address exists anywhere in the executable, so the value the
body leaves in EAX is dead — a `void` member is the honest model, and `int`
would emit the same bytes.

Rollback state: `previous_record` is retained by the package (the records were
`asm_unassigned_00408860/00408880`, `kind: asm`, `owner: null`). The rewritten
manifest passes `build_msvc.validate_project` (4,425 regions, 2,394 units).

**Staged, not landed**: `matching2/build/waves/results17/PoolShapeE/`

## Why these regions were still untouched: the pools cannot see them

`plan.py` (`candidates`), `screen_regions.py` and `carve_region.py` all require
`owner == address`. Both regions carry `"owner": null`, so no wave was ever
dealt them and no screen ever listed them. Measured across `.text`: **848 asm
regions with `owner` null or pointing elsewhere, 33,162 bytes** — 598 regions /
18,298 bytes inside the game range (below `0x0044D000`), the rest in the CRT
block; **569 of them contain no call at all** (416 in the game range), and many
of the small ones are complete functions with `CC` pads on both sides (spot
checked: `0x0044C670`, `0x004126D0`, `0x0042A870`). That family is a pool of its
own and it is invisible to every existing screen.

## Attempted, not landed: 0x00437160 (`Image_InvertAlpha`)

`src/render/image_alpha_transform.cpp`, 157 bytes, `__thiscall`, **no calls**,
so the plain path applies and was used. Every instruction *shape* is reproduced;
what differs is which register the allocator picked, and that costs the last
byte. Best model (kept at `/tmp/PoolShapeE/best437160.cpp` in the wave scratch):

```cpp
struct Surface {
    char pad_000[0x100];
    int format;
    char pad_104[0xC];
    int pitch;
    char pad_114[0xC];
    unsigned char* pixels;
    __declspec(noinline) char InvertAlpha(int row_count);
};

char Surface::InvertAlpha(int row_count) {
    int byte_count = pitch * row_count;
    unsigned char* bytes = pixels;
    switch (format) {
    case 0x1A:
        for (int i = 1; i < byte_count; i += 2)
            bytes[i] ^= 0xF0;
        return 1;
    case 0x19:
        if (byte_count <= 0) return 1;
        {
            unsigned short* p = (unsigned short*)bytes;
            unsigned int count = ((unsigned int)byte_count - 1) / 2 + 1;
            do {
                unsigned short v = *p;
                unsigned int r = ((~v ^ v) & 0x7fff) ^ ~v;
                *p = (unsigned short)r;
                if (!(r & 0x8000)) { r &= 0x8000; *p = (unsigned short)r; }
                ++p;
            } while (--count);
        }
        return 1;
    case 0x15:
        for (int i = 3; i < byte_count; i += 4)
            bytes[i] = ~bytes[i];
        return 1;
    }
    return 0;
}
```

emitted **156** bytes against the declared **157**; 61 instructions against 61;
first differing byte at `+0x01`. The whole delta is register naming plus the one
alignment byte retail carries:

| site | emitted | retail |
|---|---|---|
| prologue | `mov edx,[ecx+110h]` … `push esi` … `mov esi,[ecx+120h]` … `imul esi,[esp+8]` | `mov eax,[ecx+110h]` `mov edx,[ecx+120h]` `imul eax,[esp+4]` |
| case `0x1A` index | `mov $1,%eax` / `cmp %eax,%esi` / `xorb $0xf0,(%eax,%edx,1)` | `mov $1,%ecx` / `cmp %ecx,%eax` / `xorb $0xf0,(%ecx,%edx,1)` |
| case `0x19` guard | `test %esi,%esi` (byte_count in ESI) | `test %eax,%eax` |
| case `0x19` count | `push %edi` / `lea -1(%esi),%edi` / `shr $1,%edi` / `inc %edi` | `lea -1(%eax),%esi` / `shr $1,%esi` / `inc %esi` |
| case `0x19` pixel | `movzwl (%edx),%esi` / `mov %esi,%ecx` / `not %ecx` / `mov %ecx,%eax` | `xor %ecx,%ecx` `mov (%edx),%cx` / `mov %ecx,%eax` / `not %eax` |
| case `0x15` index | `mov $3,%eax` … `(%eax,%edx,1)` | `mov $3,%esi` … `(%esi,%edx,1)` |
| loop alignment | absent | `nop` before the `0x19` loop at `0x004371AF` |

So the byte_count home is the single lever: with byte_count in **EAX** (retail),
ECX is free for the case-`0x1A` index, ESI for the case-`0x19` count and the
case-`0x15` index, EDI is never pushed, and the `0x19` loop body lands on the
16-byte boundary that emits the `nop` — the last byte. Twelve source shapes
were swept for it and every one put byte_count in ESI (or EDX) instead:

| shape family | variants | result |
|---|---|---|
| declaration order | `byte_count`/`bytes` exchanged, `this->pitch` spelt out | 156/157, byte_count in ESI |
| value types | `int`/`unsigned int` product, `(int)`/`(unsigned)` casts, `short`/`unsigned char*`/`char*` pointer, `unsigned short`/`unsigned int` pixel local | 156/157, ESI (the `unsigned int` pixel local even costs the `movzwl` form) |
| statement spelling | `byte_count` computed inline in each case (GVN folds it), `int stride = pitch;` hoisted | 166/205 bytes |
| switch case order | all six permutations of the three cases | identical output: the compiler canonicalises case order |
| case-`0x19` guard | `if (bc > 0) {…}`, `if (bc <= 0) return 1;`, `if (bc < 1) return 1;` | `<= 0` needed for `test eax,eax; jle`; `<= 0` with an enclosing brace block gives the 157-byte extent |
| case-`0x19` count | `((unsigned)bc - 1) / 2 + 1`, `((unsigned)bc - 1) >> 1 + 1`, signed | unsigned shift is required (`shr`, not the `cdq`/`sar` fixup) |
| loop spelling | `for`, `while`, index declared at function scope, `bc > i` instead of `i < bc` | 156 bytes, index stays in EAX |
| pixel view | union with a 16-bit `w` (gives `test ah,ah`), separate `unsigned short*` local, member access inline | inline member access moves byte_count to EAX but then keeps `this` in a *pushed* EDI: 189–208 bytes |

Findings worth keeping for the next attempt:

1. `test ah,ah; js` is the `!(value & 0x8000)` spelling on a 16-bit value, while
   `(short)value < 0` emits `test ax,ax; jl`. Retail's form pins the condition.
2. `unsigned short v = *p;` (a 16-bit local, not `unsigned int`) is what emits the
   two-instruction `xor ecx,ecx` / `mov (%edx),%cx` load retail uses — a load
   MsVC only chooses for a 16-bit variable, never for a widened one.
3. The case-`0x19` value expression must be spelt `((~v ^ v) & 0x7fff) ^ ~v`; the
   algebraically equal `~(v ^ 0x7fff)` compiles to `xor ax,0x7fff; not eax` and
   never to retail's five-op block.
4. The `char` return type is load-bearing for the extent: with `int` the three
   `return 1` sites emit `mov eax,1` and the region grows to 168 bytes.
5. Adding **either** index loop to the shape is what evicts byte_count from EAX
   (verified by bisection: the same body survives in EAX while only the `0x19`
   case exists, and moves to ESI the moment the `0x1A` or `0x15` loop appears).
   The allocation order, not the body, is the residual — the natural next lever
   is the LTCG cluster path, where a synthetic caller can change that order.

Nothing outside the two landed regions, their package and this note was changed;
no layout, driver or manifest symbol table entry is involved.
