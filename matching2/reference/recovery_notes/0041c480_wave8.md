## The one load-bearing detail: EDI reaches no declaration

`0x0041C330` — this region's only callee, and its only caller is this region —
reads its records object from **EDI** (`mov 0x18(%edi),%eax` in its own listing).
Measured, in this order:

* as a plain translation unit with the callee declared `__fastcall(records)`,
  `__thiscall`, `__cdecl(records)` or argument-free, the emitted body is 62-79
  bytes: the receiver lands in EAX/ECX or the argument is pushed, and the
  argument-free form loses `mov edi,ecx` and `push edi` entirely.  No
  declaration names EDI.
* the declarations were also checked in the native link, unmodified from the
  procedure: an external symbol bound absolutely is compiled with its declared
  convention, so the call sets ECX/EDX instead of EDI (the same measurement the
  `render_stage_select_00405300_wave4.md` and
  `animation_manager_clear_resource_slot_004477d0_cluster.md` notes record).
* only a body the /LTCG pass can see earns EDI, because only then can the
  pass move the parameter into a callee-saved register: an anchor whose records
  object stays live across a loop that calls out puts it in EDI, a body without
  such a loop puts it in EAX/ESI/EBX.

This region therefore needs **compiled IL for its callee**, which is what the
cluster's `anchors` list declares: a C++ body for `_asm_FUN_0041c330_0041c330`
selected into the native link at the retail address `0x0041C330` (validated:
symbol, address and exact 48-byte contribution), placed there by the layout's
gaps, and **never exported as recovered code** — `export_bodies` writes only
`functions`, so the image receives the maintained assembly region's bytes at
`0x41C330` and only this region's 91 bytes from the cluster.

The alternative — recovering `0x0041C330` itself (274 bytes, region
`0x0041C330`, still `asm_FUN_0041c330_0041c330`) as a *selected* C++ function
in the same cluster — would make the anchor unnecessary and would convert a
second region; it is a separate job (it was assigned as `C1007` in wave 10) and
nothing in this landing depends on it.
