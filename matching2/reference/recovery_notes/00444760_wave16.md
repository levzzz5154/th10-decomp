# 0x00444760 (929 bytes) modelled to the byte — wrong private convention, wave 16

2026-09-19, worker `DispatchCase8`. Work was done in `/tmp/DispatchCase8/msvc`
(`cp -a matching2/msvc`); the maintained `regions.json`, sources and layouts were
never touched. **The region is not landed**: the model emits **894 of the
declared 929 bytes** and, more importantly, the whole-program pass derives a
*different private calling convention* for the region than retail's, which also
pulls the already-EXACT dispatcher `0x004451C0` off retail by 172 of its 216
bytes. A staged layout must never be registered when it is not exact, so no
package was produced.

## The answer in one paragraph

The body is modelled completely and structurallly: the three-way guard, the
`if (quad_count) Flush()`, the rotation block (copy `local_transform` into
`world_transform`, scale `m[0]`/`m[5]`, three guarded D3DX rotations, clear flag
bits 3 and 4), the world-matrix copy whose translation is the three position
layers with the two `(flags >> 18) & 3` / `(flags >> 20) & 3` anchor switches
over `fabsf(extent * scale * 0.5f)`, the mid-body `0x004423E0` render-state sync,
`SetTransform(D3DTS_WORLD, &world)`, the `cached_texture` set, the
`backup_transform` texture-stage matrix (`m[8]`/`m[9]` biased by the entity's uv
scroll) behind a texture/uv-scroll test, the `cached_format`-gated
`SetStreamSource`/`SetFVF(0x102)`/two `SetTextureStageState` block, and the final
`DrawPrimitive(TRIANGLESTRIP, 0, 2)`. Even the *redundant* `m[14]` store survives
(the two assignments around the sync call both emit, because the matrix's address
escapes into the later `SetTransform`). **What does not reproduce is the entry
convention.** Retail enters with the entity in **EAX** and the manager on the
**stack** (`RET 4`), keeps the entity in **EBX** and the manager in **EBP**; the
pass that models this body instead passes **both** parameters on the stack
(`RET 8`), homes the entity in **EBP** and the manager in **EBX**, and — because
the dispatcher's case-8 call site then needs two pushes — re-homes the
dispatcher's own entity from EAX to ESI, which is what moves 172 of the
dispatcher's 216 bytes off retail.

## The convention is the blocker, with measurements

The maintained anchor at 0x444760
(`entry_free_004524a1(entity); return (int)(size_t)manager;`) *does* earn retail's
pair `(entity EAX, manager stack, RET 4)`, so the dispatcher's case 8 is
`push ecx; call 0x444760` exactly today. Replacing that anchor body with the real
body re-solves the whole-program convention, and every body shape tried lands in
a *different* fixpoint:

| body handed to the pass | derived entry |
| --- | --- |
| the anchor body (`entry_free(entity); return manager;`) | entity EAX, manager stack, RET 4 (retail) |
| guard + flush + rotation block only | entity EBX, manager EAX, RET 0 |
| + world copy, x/y switches, sync, `SetTransform(WORLD)` | entity EBX, manager EAX, RET 0 |
| + `SetTransform(TEXTURE0)` texture-stage block | entity EBX, manager EAX, RET 0 |
| + the final `DrawPrimitive` | entity EBX, manager EAX, RET 0 |
| **+ the `if (cached_format != 2) { ... cached_format = 2; }` block** | **both on the stack, RET 8** |
| the whole model (same as the row above plus nothing else) | both on the stack, RET 8 |

The last two rows are the same model; the single `cached_format` compare/store is
what flips the fixpoint, and moving that block earlier in the body does not
change the outcome. Twelve declaration and structure variants were tried on the
complete model, each a full cluster build (~12 s), and none reaches retail's
pair:

* free `extern "C" int EntityDraw_00444760(RenderEntity*, AnimationManager*)`
  with the definition carrying `__declspec(noinline)` and without it;
* a member of the entity, `RenderEntity::DrawTransformedQuad_00444760(manager)`
  (declaration pressed into `include/th10/render/render_batch.hpp`'s
  `RenderEntity`), reached from the dispatcher as `entity->...` — the *member*
  `this` also lands on the stack;
* the member form **plus** a synthetic array-walking caller added to the
  cluster's compiler context (`render_batch_context.cpp`), exactly the shape
  `layout/ltcg/entity_quad_projection_00444240_context.cpp` uses to pin the
  entity-in-EAX convention for 0x00444240 — no change;
* the same, with the dispatcher's `case 8` call removed so only the synthetic
  caller reaches the body — no change, so the dispatcher is not the cause;
* the same, with the mid-body `0x004423E0` call removed (its declaration has no
  parameters, so the pass sees an opaque call that does not name the manager) —
  no change;
* the parameter order swapped to `(manager, entity)` on both the definition and
  the dispatcher's declaration (and call) — the pass then emits `RET 8` with the
  *entity* as the first stack slot;
* the source placed first in `additional_sources` instead of sorted — no change.

Conclusion `[INFERENCE]`: retail's pair is a *path-dependent* LTCG fixpoint of the
whole original program (whose translation-unit set and call graph this 35-source
cluster cannot reproduce); the local body shape does not select it. The
2026-09-19 wave-15 result for 0x00443080 (514/515 with the correct entity-in-ESI
entry) shows the pass *can* reach retail's conventions for this cluster's case
bodies, so the difference is specific to this body.

## The remaining instruction-level deltas (register roles normalised, LCS-aligned)

With the entity's register renamed to ENE and the manager's to MGR on both sides,
the emitted stream is retail's except for these groups:

| # | retail | emitted | bytes |
| --- | --- | --- | --- |
| 1 | `mov ebx,eax` / `ret 4` x3 | `mov ebp,[esp+0xc8]` / `ret 8` x3 | the convention |
| 2 | `fmul [ebp+0x0]` + `fstp [ebp+0x0]` (explicit disp8) | `fmul [ebx]` + `fstp [ebx]` (no disp) | +2 retail |
| 3 | `fld [ebx+0x3c]` hoisted above `lea`/`rep movs` | after the `rep movs` | 0 (scheduling) |
| 4 | x/y `case 1`: `fld C; fadd; fadd; fld H; ...; fabs; fxch st(1); fxch st(1); fsubrp` | `fld H; ...; fabs; fld C; fadd; fadd; fsubp` | +4 retail |
| 5 | `mov eax,ebp` before `call 0x4423e0` | absent (the declaration takes no arguments) | +2 retail |
| 6 | second `fld 0.0f; fld [ebx+0x54]; fucompp; fnstsw; test; jnp skip` after the first `jp body` | one comparison only | +18 retail |
| 7 | `mov al,[ebp+0x3ada6a]; mov ebx,2; cmp al,bl` | `cmp byte [ebx+0x3ada6a],2` | +6 retail |
| 8 | `mov [ebp+0x3ada6a],bl` / `push ebx` | `mov byte [..],2` / `push 2` | -2 retail |

Groups 2, 4, 5, 6 and 7 account for the 929-894 = 35 byte gap almost exactly
(2 + 4 + 2 + 18 + 6 - 2 = 30, with the `ret`/stack-offset encodings making up the
rest). Each has a known or probable cure:

* **#2** is a source-shape artefact: retail reaches the stored matrix through a
  *member* expression (`world_transform.m[0]`, the compiler emits `lea` plus an
  explicit `+0x0`), the model reaches it through a `RenderMatrix4x4&` cast (no
  displacement). Modelling `world_transform`/`local_transform`/`backup_transform`
  as *members* of a local struct (as `src/render/fun_00444240_00444240.cpp` does
  for 0x00444240) should reproduce the disp8 form.
* **#4** is the x87 evaluation order of the mirrored `case 1`: retail evaluates
  the *right* operand (the position sum) first and subtracts with `fsubrp`; the
  model evaluates the left (`fabsf`) first and uses `fsubp`. Same value, different
  bytes. The redundant `fxch st(1); fxch st(1)` pair is retail's.
* **#5** needs the callee's own body in the link: 0x004423E0 is assembly in
  `src/render/anm_blend_state.cpp` and its only caller is this region, so it must
  be brought in as a *compiled anchor* at 0x4423E0 whose body earns
  `(manager EAX, entity EBX)` — the convention the real body has (its prologue is
  `push ecx; push esi; mov esi,eax`, it reads `[ebx+0x35c]` and
  `[esi+0x3ada68]`). With an anchor the call site becomes `mov eax,ebp; call`.
* **#6**: no shape found. A plain `/O2` TU was used as the oracle for eight
  spellings of the condition — `A || uv != 0.0f`, `!(A == tex && uv == 0.0f)`,
  a nested `if`/`else if`, an explicit empty `else`, extra parentheses,
  `! (uv == 0.0f)` as the second term, a `while` with `break`, and a guard-return
  — and *every* one emits a single `fucompp` with `jnp skip` (or `jnp body`),
  never retail's `jp body` followed by a second identical `fld 0.0f; fld uv;
  fucompp; test; jnp skip`. `[INFERENCE]` retail's duplicate comparison is an
  artefact of the original whole-program build rather than of a source spelling.
* **#7/#8** follow from the register assignment: retail materialises the shared
  constant `2` in EBX (which the entity's death frees) and reuses it for the
  `cached_format` store and the `DrawPrimitive` count; the model's EBX is the live
  manager. This should fall out once the convention matches. Writing the three
  `2`s as one `const unsigned char format = 2;` does not change the model's bytes
  (measured, 894 both ways).

## What would unblock this region

1. The **convention**. Either find the body shape that makes the pass pick
   `(entity EAX -> home EBX, manager stack -> home EBP)` for a 929-byte body (the
   bisection above says the `cached_format` block is the switch, so start there),
   or co-compile the region in a *separate* single-source cluster whose synthetic
   context is the only caller, the way `entity_quad_projection_00444240.json`
   does for 0x00444240 — which requires bringing 0x00442F50 (`Flush`) and
   0x004423E0 in as compiled anchors, since neither can be owned by two clusters.
2. The five instruction-level items above; #2 (member-shaped matrix access), #5
   (the 0x4423E0 anchor) and #7/#8 (which follow from the convention) look
   mechanical.
3. #4 and #6 may simply be unreachable from any source spelling of this compiler;
   if so the region can never be byte-exact and should stay `asm`.
