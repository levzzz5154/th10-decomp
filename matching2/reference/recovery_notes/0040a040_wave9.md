## The remaining 14 bytes

Everything else - the vtable store, the four header zeros, all fifteen
subsystem stores (including retail's rotation), the nine clears, both `rep
stosd` runs, the `0xFFFF` word, the read/or/write on `self->flags` and the
publish - is byte-identical. Two placements are left:

| # | retail | model | bytes |
| --- | --- | --- | ---: |
| 1 | `mov ecx,[edx+334h]` `lea esi,[edx+2c8h]` `push edi` | `push edi` `lea esi,[edx+2c8h]` `mov ecx,[edx+334h]` | 11 (offsets 0x74..0x80) |
| 2 | `or eax,2` `pop edi` `mov [edx],eax` | `or eax,2` `mov [edx],eax` `pop edi` | 3 (offsets 0xDD..0xDF) |

Both are pure placements: the instruction multiset of the whole function is
already retail's, and the clear-block *registers* are retail's too
(`mov ecx,[edx+334h]` / `and ecx,eax` / `mov [esi+6Ch],ecx` / `and
[esi+off],eax`). Delta 1 is the order of the first three instructions of the
clear block; delta 2 is the `pop edi` one slot late.

## What this wave bought

The three wave-8 deltas were (a) `xor eax,eax` hoisted above the vtable store,
(b) `push edi` plus the clear block's temporary in EDI, (c) the `pop edi`
position. Device per device, measured on the whole 234 bytes:

* **(a) is a loop.** Writing the four header zero stores as
  `for (int index = 0; index < 4; ++index) ((unsigned int *)self)[5 + index] = 0;`
  makes the compiler materialise the zero in the **loop preheader**, i.e. right
  after the vtable store - exactly retail's `mov [edx+10h],4703E4h` /
  `xor eax,eax` pair. With four explicit statements the pass hoists the `xor`
  above the vtable store (9 bytes); **no** statement order (120 permutations
  swept), no `volatile` on the vtable store, no header helper, no scope/`goto`/
  folded `if`/`do-while`/`switch` and no folded branch changes it. A loop (or a
  loop for the *elements*, or `volatile` on **all** fifteen element stores)
  is the only device found that pins it. The header loop is byte-neutral
  everywhere else and costs nothing.
* **(b) splits into two coupled halves.** The clear block can be written so that
  the `push edi` lands *after* the load and the `lea` (retail's place) or so
  that the load's temporary is `ECX` and the mask `EAX` (retail's registers) -
  never both, because the same barrier position decides both:
  * "family X" - `[pool decl][_ReadWriteBarrier()][load][store]`: registers
    right (`mov ecx` / `mov eax,~1`), 11 differing + the pop = **14**;
    but the `push edi` is pinned to the region start, so the order is
    `push, lea, load`.
  * "family Y" - `[pool decl][load][_ReadWriteBarrier()][store]`: the `push edi`
    lands at 0x40A0C0, i.e. retail's `load, lea, push` order, **15**; but the
    load takes `EAX` and the mask `ECX` (the two registers swap).
  * Both barriers at once (`[pool decl][bar][load][bar][store]`) gives
    `push, lea, load EAX, mask ECX` = 25. A leading barrier (before the pool
    declaration) does not change either family.
* **(c)** the `pop edi` sits after `mov [edx],eax` in every variant built (tail
  helpers, `volatile` load/store splits, barriers before/after the flags
  update, folded-branch block boundaries, memset/`0xFFFF` order and barriers):
  its region evidently ends one slot later than retail's.

## Shapes tried for the clear block (all measured)

Barrier layouts: all 8 combinations of {leading, between pool-decl and load,
between load and store} x {pool decl then load, load then pool decl}; double and
triple barriers. Statement forms: `pool[i] &= ~1u`, `pool[i] = pool[i] & ~1u`,
`pool[i] = first & ~1u` (with `first` loaded through `self`, through `pool`,
through a `char*` cast and through a separate `flag` pointer at +0x334),
`first &= ~1u; pool[i] = first;`, `mask = ~1u; pool[i] = first & mask;` with the
mask declared before/after the load, `pool[i] = ((unsigned int *)self->pool)[..]
& ~1u`, literal index `pool[27]`, `*(pool + 27)`, `*(char*)+0x6C`, bit-field-free
`const volatile` loads, volatile loads and volatile stores, and the RMW form.
Inlined helpers: load helper, store helper, masked-store helper, word/mask pair
helper, `__fastcall`/`__stdcall`/`__cdecl` parameter orders, a helper returning
the masked value, a pool-pointer helper - all inlined to the same bytes and the
same registers. The wave-8 devices were kept where they are load-bearing: the
`volatile` cast on elements 1/2 (a plain statement order re-groups the fifteen
stores by value) and the `_ReadWriteBarrier()` between the nine clears (without
them every clear loads and splits, +61 bytes); the first clear must be read
through `self` so the load is `[edx+334h]`.

The element block was also re-derived: producing retail's
`[f08 f8C f00 fD4 fD0]` rotation for elements 1/2 needs either fifteen explicit
statements with the `volatile` cast or element 0 explicit plus a two-iteration
loop (which is what the rotation really is). Both are byte-identical here, but a
loop, or an inlined `InitSub` called twice, drags the `push edi` to its
preheader (0x40A078 / 0x40A096), so the explicit form is the one that keeps
`push edi` at 0x40A0C0.
