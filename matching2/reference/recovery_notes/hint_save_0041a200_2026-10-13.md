# Append to `matching2/reference/recovery_notes/hint_save_0041a200_2026-10-13.md`

## 2026-10-18: byte-exact — walked-pointer loop + `rows == 0` guard + zero-test skip arm

Region is now **byte-identical** (741/741 instructions, 0 differing code bytes,
0 tail bytes; `equivalence.py` reports `differences: []`, `not_equivalent: []`,
`base_index_order: 0`, `frame_offset: 0`). Three levers closed the residual, in
this order:

1. **Walked-pointer loop (`next` is the cursor, `entry` the per-step alias).**
   The old spelling (`ChainNode* entry = slot->head; … next = entry->next;
   … entry = next; } while (entry != 0);`) gave the walk cursor a weight-2
   stack element. c2 `ColorStackElements` processed it *after* the 15 inlined
   `written` homes, so the cursor took a late slot (`[esp+0x50]`) and the time
   scratch coalesced into `slot`'s home (`[esp+0x14]`) — the recorded
   walk-cursor/scratch residual. Spelling the walk so `next` carries **three**
   surviving references (cursor init from the head read, per-path advance, loop
   test) moves it to weight 3: processed right after `slot` (weight 4), it opens
   the 4th colour and `aclock` (weight 2, conflicts with nothing but the
   `manager` parameter) joins it — retail's shared `[esp+0x18]` home. The
   frame, the cursor store at 0x41a40a and the reload at 0x41a9ea then match.

2. **Semantic fix: the `rows == 0` guard covered two lines, not one.** Retail
   writes both the `# ====` banner and the `Stage : %d` line only for the first
   shown tip of a stage (Ghidra: `if (local_50 == 0) { rule-short; stage }`;
   the `jne` at 0x41a41d skips to 0x41a4e0, the `Tips` sprintf). The model
   guarded only the sprintf and wrote both lines unconditionally. Guarding the
   whole two-line block fixed the `jne L+0x2e0`-vs-`jne L+0x22a` hunk and the
   three register-choice hunks behind it.

3. **Skip arm as the `if` arm with a zero test.** With `if (tip->selection != 0)
   { body } else { entry = next; }` c2 laid the body out as fallthrough and the
   skip arm out of line at the end of the function, and rematerialised the loop
   test's `next` read as a reload (`mov ecx,[esp+18h]`). Retail keeps the skip
   arm inline as the branch target (`jne BODY / mov eax,ecx / jmp TEST`), with
   the test's value a forwarded copy (`mov eax,[home]; mov ecx,eax`). Writing
   the skip as `if (tip->selection == 0) { entry = next; } else { body; }` makes
   it the branch target (reverse post-order lays the target out first) and the
   per-path `entry = next` sites give the phi-copy tail. The name-table
   out-of-line blocks and the alignment paddings then fall into retail order.

Ruled out (with evidence):

- Test-operand changes on the loop condition (`while (next)` vs `while (entry)`)
  alone: byte-identical to the baseline — c2 CSEs the two reads of the cursor
  into one (weight stays 2).
- Reading the cursor back through `__forceinline` pointer helpers
  (`HintWalk(&next)`, by pointer and by reference) and a volatile-cast read at
  the test: helper forms keep weight 2; the volatile cast does give weight 3
  and the right colour order but forces a real second load (`mov ecx,[home]`)
  instead of retail's forwarded copy — 1,672 differing bytes.
- `entry = next` written twice in sequence: merged early, weight 2.
- Plain-while vs `if (t) do … while (t)` loop forms and the split/top advance
  spellings: canonicalized — every form reproduces one of three byte shapes
  (baseline 1,676 / cursor-init walk 577 / per-arm advance 550) regardless of
  the loop spelling.
- The overnight candidates (cursor without initializer, `long`-typed cursor)
  remain dead: they were probed 2026-10-17 and do not change the element
  weights.

Mechanism notes worth keeping: c2 stack colours are chosen by
`ColorStackElements` (weight = surviving reference count, ties in element-list
order ≈ live-range end order; each element takes the newest colour it does not
interfere with). The `aclock`/cursor share falls out of the weights alone once
`next` outranks the `written` homes — no union, cast or volatile is needed.
