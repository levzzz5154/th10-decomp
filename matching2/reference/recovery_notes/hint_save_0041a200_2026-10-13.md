## Residual class (closest state)

Body 2229/2247 bytes; instruction-level diff ~113 events, all in three
classes:

1. **Walk-cursor stack home.** Retail shares ONE home at [esp+0x18] (4th
   home) between the `time32/localtime` scratch and the loop walk cursor
   (`next` stored at 0x41a40a, reloaded at 0x41a9ea). In every spelling
   tried, the local build either coalesces the time scratch into the slot
   pointer's home (3rd slot, all written homes shift -4) or gives the cursor
   its own late slot above the written homes (frame +8). ~30 variants tested:
   declaration orders/scopes, initializers, volatile, union
   (`{time_t aclock; ChainNode* next;}`) forcing the share by construction
   (share works, but the union lands in the 3rd home, swapping with slot),
   scalar reinterpret_cast reuse (correct homes, but the register copy on the
   selection==0 path becomes a memory reload, changing the tail shape).
2. **Per-block register assignments.** The inlined write blocks single-read
   the handle correctly, but the backend picks different registers than
   retail at two spots per block: the `&written` temp lands in EAX where
   retail uses ECX, and the short-write close reloads the handle into ECX
   where retail uses EDX (block 1; later blocks vary in retail too). These
   follow from the frame-home placement in (1).
3. Knock-on jump-target offsets and `lea ecx,[ecx]`-style padding flavors.

## 2026-10-13 resume: decisive experiments (both negative)

1. **c1 vs backend.** The full SaveHints TU compiled twice: non-/GL /FAs
   (c1's own home table) and the /GL cluster (LTCG backend output). BOTH show
   the identical pattern — `stage/rows/slot` in declaration order, `aclock`
   coalesced into the slot pointer's home, `next` in the trailing temp slot
   above the written homes. The cursor/scratch merge is therefore decided at
   c1 (or earlier IL), not by a whole-program frame reorder, and it never
   fires for this TU shape at either level. Since retail's binary HAS the
   merge, retail's TU must differ in some IL-visible way from every spelling
   tried, or the merge is driven by a c1 frame-pass ordering rule keyed on
   the twelve inlined write blocks that minimal TUs cannot reproduce.
2. **Type-identical homes.** Declaring the walk cursor as `time_t next` (the
   same type as the scratch) with `reinterpret_cast` at the two walk
   accesses — cluster size 0x8b5, `next` still in the trailing temp slot.
   Type identity alone does not enable the merge.

## Empirical c1 rules established (for the next attempt)

- /FAs listings show c1 assigns homes in declaration order and gives
  address-taken variables a pre-pass home that always lands BEFORE every
  RA-managed variable home, regardless of declaration position
  (E12/E24: cursor declared 4th still took the 3rd home). The LTCG backend
  preserves the c1 order.
- The retail layout therefore requires the walk cursor to be pre-pass
  (address-taken) AND declared after the slot pointer, while remaining
  register-copyable on the selection==0 path — contradictory under MSVC's
  address-taken-means-memory rule, unless the address-taken variable is the
  cursor itself (E24: `next` reused as the time scratch via casts at the two
  time calls; reaches exact extent 2247 with 357 differing bytes, all from
  the same 3rd/4th home swap: cursor@0x14, slot@0x18 instead of
  slot@0x14, cursor@0x18).
- Making the slot pointer memory-resident (`volatile`) does not move it into
  the pre-pass; tiny-probe TUs never reproduce the c1-level cursor/scratch
  merge in isolation.

## Equivalent-route attempt (draft kept under layout/equivalent/)

`layout/equivalent/hint_save_0041a200.json` +
`equivalent/archive/hint_save_0041a200.cpp` (the cursor-reused-as-scratch
shape, exact 2247-byte extent). Findings:

- With WriteShared compiled as a context source (private EDX/ESI convention
  derived from the real caller), the model link places WriteShared's body
  immediately after SaveHints (no layout gaps in the equivalent link), so the
  nine `call` displacements point at the model's internal copy; relocation
  cannot redirect them to 0x44B740 and the check rejects the model.
- With WriteShared external and bound at 0x44B740, the frame loses the
  retail `sub esp,0x4c` (the private-convention call shape is what produces
  it) and the nine early call sites differ in argument-passing shape.
- Conclusion: the equivalence route needs the callee body and the retail
  call displacement simultaneously, which the equivalent model link cannot
  express; the cluster route (used here) is the right vehicle.

## 2026-10-13 second session: macro hypothesis, report route, binding mechanics

1. **Macro-spelled write blocks** (`#define WRITE_HINT_LINE(b,l){...}` with
   per-site scoped `written`): model body 2477 bytes — the nested-if guard
   shape costs ~230 bytes over the helper form. Negative.
2. **Equivalent-route binding mechanics** (from the accepted
   front_hud_update_00414900.json precedent): a context-compiled callee CAN
   be bound to its retail address via `bindings` alone (map-based, no
   linker definition). `absolute_symbols` entries additionally define the
   symbol in bindings.obj, which SHADOWS the compiled copy (the model's
   WriteShared body came out discarded) and suppresses the private-convention
   derivation entirely — never put a context-compiled function there.
3. **Tail-duplication spelling** (explicit `entry = next; if (entry) continue;
   break;` on both paths): the compiler restructured to an esp-relative frame
   (`sub esp,0x3c`), 411/741 instructions differing. Negative.
4. **Final draft measure** (E19-family source + context-compiled WriteShared
   + checker-only binding + frame_shift {deltas:[4]}): 684/741 instructions
   identical; the only unlistable difference is the nine
   `call 0x44b740` vs `call L+0x8c0` rows — the co-compiled WriteShared copy
   sits at model+2240, seven bytes inside the compared extent, so relocation
   rebases the calls into the function instead of to 0x44B740. Every spelling
   that pushes the copy past the extent (frame +8 shapes) costs more
   instructions elsewhere than the budget allows.

## 2026-10-13 third session: the call-target rebase extension (accepted draft)

`equivalence.py` gained an auditable call-target rebase, per the reviewed
conditions:

- `rebase_map(bindings, symbols, model_start, model_code, region_start,
  region_size, rebase_regions, name)`: a call target inside the compared
  function is rebased only when its model address is an explicit `bindings`
  entry whose retail address lies outside the region AND a semantic
  (maintained, byte-exact) region carries the same symbol at that address;
  a bound callee without such a verified region refuses.
- `rebase_bound_calls(rows, body, start, rebind)`: rewrites 5-byte near calls
  whose target is a rebind key; every other row is untouched.
- `relocate(..., rebind)` applies it; `verify_recovery` records the rebased
  calls in `report['rebased_calls']` (count, the named byte-exact-elsewhere
  verification, and each row), and LISTED_CLASSES gains `call-target-rebind`
  for any rebased row that does not land identical.

Result for hint_save (the cursor-reused-as-scratch equivalent source): the
nine WriteShared calls rebase to 0x44B740 (verified against semantic region
`semantic_file_write_shared_0044b740_0044b740`), 693/741 instructions
identical, and the remaining 16 hunks / 29 frame-offset instructions are
recorded with reviewed classes:

- stack-slot-order: the walk cursor and the slot pointer occupy each other's
  frame slots (0x20a, 0x7ea);
- branch-target / code-shape: the shared tail merged differently (0x20e,
  0x21d, 0x7ee, 0x236);
- evaluation-order: the deferred `add esp,8` (0x22e, 0x230);
- register-choice: the &written temp and the handle reload (0x24d, 0x261,
  0x27f);
- alignment-padding: the loop-fill nops and the model's WriteShared copy
  prologue bytes that trail the function's own ret (0x35d, 0x42d, 0x4de,
  0x509, 0x8c2).

The draft passes the gate (`not_equivalent: []`).  Note: the relocated body's
last seven bytes are the model copy's prologue (dead bytes after the
function's own `ret 8`), recorded as alignment-padding — the built executable
differs from retail there by design of the recorded differences.
