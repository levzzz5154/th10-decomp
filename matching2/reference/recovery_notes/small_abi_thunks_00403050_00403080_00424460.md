# Small ABI thunks at `0x403050`, `0x403080`, and `0x424460`

These short blocks have clear behavior, but the available ordinary C++ compiler
profiles do not reproduce the retail instruction stream. No production region or
source was changed during these trials.

## `0x403050` — bullet-manager forwarding thunk (7 bytes)

Retail bytes are `8B C1 E9 C9 F6 FF FF`: copy the incoming `ECX` value to `EAX`
and tail-jump to `0x402720`, which consumes the manager pointer in `EAX`.

A C++ `__fastcall` wrapper that calls the target declared with `regparm(1)` is
semantically faithful. The pinned Clang profile emits the right seven-byte
extent and binds the relative call/jump relocation to `0x402720`, but encodes
the register copy as `89 C8` instead of retail's `8B C1`. They have the same
effect; this is an instruction-encoding difference, so the exact-byte gate
rejects the candidate. GNU Clang's Intel-syntax output still assembles as
`89 C8`.

## `0x403080` — result normalization wrapper (11 bytes)

The containing 25-byte assembly region at `0x403077` includes nine `INT3`
bytes, this 11-byte function, and five trailing `INT3` bytes. Its body is:

```text
push eax
call 0x403850
neg eax
sbb eax, eax
ret
```

The custom entry receives its value in `EAX`; `ECX` remains the implicit
receiver for the call to the `0x403850` member routine. The return value is
`0` when that routine returns zero and `-1` otherwise.

A plain C function using `regparm(1)` and a `stdcall` declaration for the callee
produces the correct push, call, and relocation with Clang. Clang uses `ECX` as
the mask temporary, however, adding `xor ecx,ecx` and `mov eax,ecx` around the
`neg`/`sbb` sequence; its body is four bytes longer. GCC produces a 16-byte
body with extra stack/register moves. Neither candidate is suitable for
promotion.

## `0x424460` — register animation resource (15 bytes)

The wrapper calls `0x43E460` with the incoming manager in `EAX`, the string at
`0x46E0B8` in `EDX`, and stack arguments `7` and `0`. A candidate using
`regparm(1)` for the wrapper and `regparm(2), stdcall` for the callee produces
the right 15-byte extent and a relocation to `0x43E460`. Clang emits the
`mov edx,0x46e0b8` before the two constant pushes; retail pushes `0` and `7`
first, then loads `EDX`. An external data declaration also introduces a GNU
COFF `.refptr`, so the diagnostic candidate used the known address constant to
isolate the call-convention behavior. GCC's corresponding candidate is much
larger.

The sibling at `0x424470` differs only in resource ID/string, while
`0x434B80` registers the `0x46ECE8` string with ID `8`; the same Clang argument
setup ordering is likely to affect those blocks too.
