# `_strncpy` at `0x00452960`

## Ghidra evidence

Queried the `th10.exe` program through Ghidra MCP. Ghidra identifies the complete function as the Visual Studio 2003 library routine `_strncpy` and reports `char* __cdecl _strncpy(char* _Dest, char* _Source, size_t _Count)`. The body begins at `0x00452960` and ends at `0x00452A83` (292 bytes including the final `RET`). The parameters are cdecl stack arguments: destination at entry `ESP+4`, source at `ESP+8`, and the 32-bit `size_t` count at `ESP+0xC`.

The function is a leaf. Its plain `RET` leaves argument cleanup to the caller. The implementation saves and restores `EDI` on every path and also saves/restores `ESI` and `EBX` on the nonzero-count paths. Ghidra reports ten callers: `FUN_00419960`, `FUN_0041a120`, `FUN_00455bf3`, `FUN_00455fe7`, `FUN_00458efd`, `FUN_0045f259`, `FUN_0046041e`, `___lc_strtolc`, `__tzset_lk`, and `crtGetLocaleInfoA`.

## Recovered behavior

The return value is always the original destination pointer. A zero count returns it without reading either input or writing destination bytes. For a nonzero count, the routine copies source bytes up to the count or the first NUL. If it reaches the source NUL before exhausting the count, it writes NUL bytes through the full requested count. Source bytes are copied unchanged; the implementation only tests whether a byte is zero, so signed versus unsigned `char` does not affect these semantics. The optimized retail body aligns the source and uses four-byte loads with a zero-byte test, then handles the remaining bytes and padding.

`strncpy_00452960.cpp` expresses these semantics in ordinary C++, with a const-qualified source and `std::size_t` count. This preserves the pointer return and cdecl stack ABI while removing the inline assembly.
