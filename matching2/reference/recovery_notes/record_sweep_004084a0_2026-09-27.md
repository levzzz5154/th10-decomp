# 004084A0: measured record sweep residual

The maintained 370-byte assembly region is unchanged. This investigation establishes the native register convention with readable C++, corrects the legacy loop count, and measures the remaining x87 source-shape problem. No candidate was promoted.

Fresh Ghidra MCP reads from `th10.exe` retain all 370 bytes and all 126 bounded instructions in `matching2/build/experiments/record_sweep_004084a0_2026_09_27/`. Ghidra has no Function object or incoming references at this address; `missing_function.txt` and `xrefs.txt` retain those results. No Function object or custom prototype was invented.

The routine receives the owner in ECX, point in EDI, and radius at `[ESP+4]`, returns the accumulated integer in EAX via ESI, and ends in RET4. The loop immediate is `0x7D0`: **2,000** entries, despite the old source banner saying 1,000. Each entry has stride `0x7F0`. The implementation's cursor is owner+0x450. Adjacent raw routine 00408210 and the exact maintained 004065C0 re-arm routine corroborate the family table at owner+0x60, placing the cursor at record+0x3F0.

State 0 and 3 are skipped. Four corner distances are tested in left/top, left/bottom, right/bottom, right/top order. The bottom and top copies are constructed through distinct additions/subtractions of full height, preserving the separate rounded corner values rather than collapsing them into one algebraic rectangle. Distance acceptance is `!(distance_squared > radius_squared)`, which also accepts unordered x87 comparisons. Classification comparisons are ordered `<=`: descriptor float at +0x34 is compared separately to 8 and 16 (each adds 1), then 32 (adds 4), then 64 (adds 10). Missing descriptors and larger/unordered classifications add nothing.

The geometry residual therefore includes precision behavior, not merely register spelling.
