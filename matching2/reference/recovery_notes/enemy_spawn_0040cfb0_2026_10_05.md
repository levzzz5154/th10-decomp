# 0x0040CFB0 enemy creation (recovered 2026-10-05)

`src/game/enemy_spawn_0040cfb0.cpp` compiles to the retail 577 bytes (501 of
code, 3 of alignment, 73 of switch tables) in the `enemy_spawn_0040cfb0`
cluster. `make` and `make EXACT=1` pass.

* `EnemySpawn_0040cfb0::Create(manager, entry)`: description in EAX, RET 8.
  The record initialiser 0x40D830 is a stand-in constructor that keeps `this`
  across opaque calls (ESI); 0x40DC80 is an external `__stdcall`.
* The drop item swap goes through a local (`item = drop_item; ...;
  drop_item = item`); writing the member in both branches stores twice.
* The difficulty is read from the escaped run state struct (0x474C40 + 0x34),
  which keeps the flag store ahead of that load.
* Switch cases are written 0/5/15/10 (the order of the retail blocks).
* `FrameTimer::Set(2)` from `th10/math/timer.hpp` gives the timer block as is.

## Folding a switch table into the function's region

The table used to be separate records (`text_padding_0040d1a5`,
`text_data_0040d1a8`, both in `src/data/text_0040.cpp`). To promote:

1. give the cluster function the full size (code + alignment + tables);
2. replace the three region records by one `semantic` record of that size
   (the old records are kept under `previous_record` / `merged_records`);
3. delete the two arrays from `src/data/text_00xx.cpp`.

The compiler emits the same `lea ecx,[ecx+0]` alignment and tables, so the
merged region is byte-exact without help.
