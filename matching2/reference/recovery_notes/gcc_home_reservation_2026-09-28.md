The experimental `initialize_stack_home.cc` pass chooses the value about to initialize a new one-word local as the value pushed to reserve that local. It does not remove or alter the explicit volatile initialization. It requires a frame-related word push with a stack-memory barrier, an immediately preceding scratch clobber in the same basic block, and an exact nonnull CFA adjustment of SP by minus four. The next instruction must be a full-word volatile store to `[SP]`, owned by a nonstatic local `VAR_DECL` in the current function, from a hard general register. It rejects other frame notes, saved-register pushes, parameter or outgoing-argument homes, other modes and intervening instructions. GCC's target recognizer validates the changed RTL and dataflow is rescanned.

This choice preserves the physical stack reservation, flags, register values, stack barrier and CFA adjustment. The newly reserved private local is initialized to its upcoming value earlier; the original volatile store still occurs. There are no executable instructions between reservation and initialization. The pass contains no target-program symbol names, addresses, expected byte strings, inline assembly, register assembly, assembly templates or assembly-output callbacks. It never reads the executable oracle. GCC documents optimization-pass insertion through [the plugin pass manager API](https://gcc.gnu.org/onlinedocs/gccint/Plugins-pass.html). An independent rule review found and resolved a permitted null CFA-note payload before the source was frozen; the final guarded rule and full pipeline received independent PASS reviews.
