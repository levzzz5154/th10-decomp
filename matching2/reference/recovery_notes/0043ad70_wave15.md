## The lever: the anchor's live-range shape picks the caller's home

Retail's `0x0043AD70` enters with the sequencer in **EAX** (unsaved) and keeps it
in **EDI** for the whole body, and its call to `0x0043ACE0` is bare — that
callee's receiver register is not named by any declaration, so it comes from the
body the /LTCG pass can see.  Three links were built with the *same* modelled
caller, only the anchor body for `0x0043ACE0` changed:

| anchor body for `0x0043ACE0` | receiver home | emitted | differing |
| --- | --- | ---: | ---: |
| **loaded cursors + `while (track < track_table + track_count)` (landed)** | **EDI** | **167** | **0** |
| `for (index < track_count)` with `track_table`/`track_count` member accesses | EBX | 167 | 14 |
| no body at all (declared `__thiscall`, symbol bound absolutely, as `register_cluster.py` binds an opaque callee) | ESI, and the call becomes `mov ecx,esi; call` | 164 | 156 |

With the EBX-earning anchor the only difference from retail is the prologue pair
`push ebx; mov ebx,eax` and the register encoded in the four field accesses that
follow — `mov 0x138(%ebx),%eax` where retail has `mov 0x138(%edi),%eax` — i.e.
14 bytes, all of them the one register.  With no body the pass re-chooses the
whole private convention: the object arrives in ESI, is never saved, and the
callee is reached through the declared `__thiscall` ECX.  So the anchor body is
what fixes the home, and the deciding property of the landed body is that the
track cursor is a pointer *loaded* from the object and advanced inside a loop
that calls out, while the object itself stays live (it is the loop bound, and it
is written once after the loop).  The same property is what earned EDI for the
wave-14 `0x0043AE20` anchor; the wave-13-style cursor-plus-index body earns EBX
instead.

## The last 19 bytes: the reopen request must be a five-argument inlined helper

The body after `ResetTracks()` reopens the MIDI output.  Retail emits it as
`push 0x10000 / push 0 / mov [esi+4],-1 / mov ecx,[491c70] / push ecx / push -1 /
push esi / call [0x4662AC]` — the state publish sits *between* the call's two
constant pushes and the callback's load.  Every direct spelling of that sequence
(the reopen written out, a 2-argument helper, a helper whose store is its last
statement, a store-returning helper, a comma-expression store inside the argument
list, a typed slot struct, `volatile` on the global or the slot, constant locals
for the tail arguments) emits the same *instruction set* with the store sunk to
just before the call — 24 bytes.  A `_ReadWriteBarrier()` after the store pins
the store and the load ahead of the two pushes instead — 19 bytes.  What reaches
retail is passing the callback **by reference** through an inlined five-argument
helper: the caller's tail arguments (the instance word and the event flag) are
then evaluated before the inlined body's statements, which is where the two
constant pushes sit, while the callback's read stays inside the body after the
publish.  That single shape change took 19 bytes to 0; swapping the callback to a
plain value parameter, or the helper to three arguments, moved the register
allocation and made it worse (142 differing).

//
// Retail enters with the sequencer in EAX (an unsaved register argument) and
// leaves with `ret`; the object's home through the body is EDI.  That home is
// not this body's free choice: the bare `call` at 0x0043AD83 names no register,
// so the callee's body is compiled into this link as an ABI anchor (bottom of
// this file) and the whole-program pass follows whichever register that body
// earns — the loaded-cursor shape below earns EDI.

// import slot, so each declaration is bound to that slot by address (the names
// carry the slot address to keep the binding unambiguous).

__declspec(dllimport) unsigned int __stdcall timeEndPeriod_00466274(unsigned int period);

    unsigned int delay, unsigned int resolution, void* procedure,
    unsigned int user, unsigned int type);

}

// 0x20-byte sequencer track record; every member up to `cursor` fixes the
// offsets the body and the anchor reach through.
struct MidiTrack_0043ad70 {
    int active;                        // +0x00
    int next_event_time;               // +0x04
    unsigned int byte_count;           // +0x08
    unsigned char running_status;      // +0x0C
    unsigned char unknown_0d[3];
    unsigned char* data;               // +0x10
    const unsigned char* cursor;       // +0x14
    const unsigned char* loop_cursor;  // +0x18
    int saved_loop_time;               // +0x1C
};

// Only the fields this unit reaches are named.
struct MidiSequencer_0043ad70 {
    unsigned char reserved_000[4];
    unsigned int frame_timer;          // +0x04: timer identifier
    unsigned int timer_period;         // +0x08: timer resolution
    unsigned char reserved_00c[4];
    int current_file_slot;             // +0x10
    unsigned char reserved_014[0x104]; // 0x14 .. 0x117
    int track_count;                   // +0x118
    unsigned char reserved_11c[0x1C];  // 0x11C .. 0x137
    MidiTrack_0043ad70* track_table;   // +0x138
    void* midi_out;                    // +0x13C
    int midi_state;                    // +0x140

    __declspec(noinline) void ResetTracks();
    __declspec(noinline) int Restart();
};

// The reopen request is an internal five-argument helper.  The callback travels
// by reference: the caller-supplied tail arguments are then evaluated before the
// inlined body's own statements, which is where retail's two constant pushes
// sit, and the callback's read stays inside the body, after the state publish.
__forceinline int OpenMidiOut_0043ad70(void** handle, unsigned int device,
                                       unsigned int& callback, unsigned int instance,
                                       unsigned int flags) {
    if (*handle) {
        if (*(int*)(handle + 1) == (int)device) return 0;
        midiOutReset_004662a8(*handle);
        midiOutClose_004662a4(*handle);
        *handle = 0;
    }
    *(int*)(handle + 1) = (int)device;
    return midiOutOpen_004662ac(handle, device, callback, instance, flags);
}

#pragma code_seg(".text$03restart")
int MidiSequencer_0043ad70::Restart() {
    if (!track_table) return -1;
    ResetTracks();
    OpenMidiOut_0043ad70(&midi_out, 0xFFFFFFFFu, data_00491c70, 0, 0x10000u);
    if (frame_timer) timeKillEvent_00466288(frame_timer);
    timeEndPeriod_00466274(timer_period);
    frame_timer = 0;
    timeBeginPeriod_00466278(timer_period);
    frame_timer = timeSetEvent_0046628c(1, timer_period,
                                        (void*)midi_timer_callback_0043a6e0,
                                        (unsigned int)this, 1);
    return 0;
}
#pragma code_seg()

// ABI anchor for 0x0043ACE0 (MidiSequencer::ResetTracks).  This body is not
// recovered game code: the layout places it at the retail address so the bare
// `call` above bakes retail's own displacement, and export_bodies never selects
// it.  What it earns is the register the *caller* must hold its object in: a
// records object reached through a loaded local cursor that is advanced inside a
// loop that calls out, with the object still live after that loop.
#pragma code_seg(".text$02reset")
void MidiSequencer_0043ad70::ResetTracks() {
    MidiTrack_0043ad70* track = track_table;
    while (track < track_table + track_count) {
        track->cursor = track->data;
        track->loop_cursor = track->data;
        track->active = 1;
        track->next_event_time = midi_read_length_0043a730(track->cursor);
        ++track;
    }
    current_file_slot = 0;
}

## What it unblocks

* **The MIDI-track family around it**, all still assembly and all reachable from
  this landing: `0x0043AC90` (72 bytes, the asm caller that materialises
  `manager in EAX / index in ESI` for the landed `0x0043A9B0`),
  `0x0043AE20` (129 bytes, the real playback stop whose receiver is EDI
  unsaved), `0x0043AEB0` (79 bytes, the per-block release it calls with
  `mov edx,edi` and the block in ESI).  `0x0043AD70`'s own model now pins the
  object layout this family shares: `+0x04` timer id, `+0x08` timer resolution,
  `+0x118` track count, `+0x138` track table, `+0x13C` MIDI-out handle,
  `+0x140` reopen state.
* **The `0x0043A4C0` reopen family** (`0x0043A4A0`, `0x0043A4C0`, `0x0043A510`
  are the same reopen idiom out of line, with the state and the device as one
  parameter).  The inlined body contracted here —
  `if (*handle) { if (*(int*)(handle+1) == device) return 0; reset; close;
  *handle = 0; } *(int*)(handle+1) = device; midiOutOpen(...)` — is that
  family's exact shape, and the callback-by-reference wrapper is the device
  that keeps the publish between the constant pushes and the callback read.
* **The anchor recipe**, for any region whose object's home follows a bare call
  to a callee no declaration names: a loaded cursor advanced in a loop that
  calls out, with the object still live afterwards, earns **EDI**; the
  cursor-plus-index shape earns **EBX**; and with no anchor body at all the pass
  re-chooses the whole convention (ESI here, with the declared `__thiscall`
  receiver at the call).  Measured on this region: 0 / 14 / 156 differing bytes.
