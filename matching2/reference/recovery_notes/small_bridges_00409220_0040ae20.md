# Small private-register bridges: `0x00409220` and `0x0040AE20`

Live Ghidra context: `th10.exe`, image base `0x00400000`. Both addresses are
represented as 10- and 12-byte assembly regions in `matching2/msvc/regions.json`;
Ghidra has no function object at either entry, so the ABI conclusions below
come from raw instruction boundaries and the observed target/caller code.

## `0x00409220` — callback adapter into the EDI-based score routine

Ghidra disassembly confirms the exact ten bytes:

```asm
push edi
mov  edi, ecx
call 0x00408D60
pop  edi
ret
```

The `0x004089C0` initializer pushes `0x00409220` as the callback address for
`0x00449ED0`. The adapter therefore receives the object pointer in ECX, copies
it to EDI, preserves the caller's EDI, and returns with plain `ret`. The call
at `0x00409223` is a direct Ghidra xref to `FUN_00408D60`.

Although Ghidra currently prints `FUN_00408D60` as
`undefined4 __fastcall FUN_00408D60(int param_1)`, its raw entry reads the
score object through EDI, and the decompilation represents that object as
`unaff_EDI`. Ghidra's variable-storage report places `param_1` in ECX; this
adapter leaves ECX unchanged while copying the same incoming value to EDI.
The large state-machine body also calls private-register helpers. The outer
adapter's ECX-to-EDI transfer is therefore semantically clear, but a normal
C++ call cannot ensure that the existing callee receives the required EDI
state pointer. Preserve this row as assembly until the score routine and its
private helper contracts can be recovered together.

## `0x0040AE20` — indexed selection followed by a private-register tail call

Ghidra raw disassembly confirms the 12-byte sequence:

```asm
mov edx, [eax + ecx*4 + 0x3AD06C]
jmp 0x004493E0
```

The tail target's raw body immediately copies EAX into ESI, reads its list
heads from `[EAX + 0x72DAD4]` and `[EAX + 0x72DADC]`, and compares each item's
field at `+0x308` against EDX. Ghidra's current target decompilation exposes
the first input as `in_EAX` and the second as `param_2`; its printed
`__fastcall` prototype does not describe EAX as an ordinary explicit
parameter. The thunk's incoming EAX base and ECX index, followed by the EDX
selected key, form a private register bridge. A standalone typed C++ wrapper
cannot express this call without reproducing the larger target behavior or
changing the target's ABI, so retain the assembly.
