# 0x004073E0 projectile pattern spawner (recovered 2026-10-05)

`src/game/enemy_grid_scan.cpp` compiles to the retail 194 bytes in the new
cluster `layout/ltcg/enemy_grid_scan_004073e0.json` (probe EXACT, `make` and
`make EXACT=1` pass). The old header called this blocked on a "hidden EAX
input"; under LTCG an ordinary `__stdcall f(pattern, manager)` gets the pattern
in EAX by itself.

The only non-obvious part is the callee 0x004067D0, which is still assembly.
Its stand-in (`enemy_grid_scan_004073e0_anchors.cpp`) must give the same
convention as retail: pattern in EBX, manager/column/row/aim on the stack.

* Pattern in EBX: the stand-in keeps the pattern live across calls next to a
  record pointer and two counters, as the real function does.
* Manager on the stack: with a plain stand-in the pass moved the manager to
  EAX (one `push` fewer, 193 bytes). Taking the parameter's address in the
  stand-in keeps it memory-homed. Retail's entry reads it from `[esp+4]`.

The real `SoundQueue::QueuePan` body is included as the second anchor through
a one-line wrapper; `0.0f` is bound to 0x00470B04 with a constant alias.

Rig: `build/experiments/gridscan_4073e0_claude` (`run.py a`).
