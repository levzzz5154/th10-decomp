## The answer in one paragraph

The dispatcher now **emits exactly the declared 216 bytes** and its **entry
convention, guard instructions and jump-table shape are retail's** — the model
reproduces the first ten bytes, the ten comparison/branch instructions, the
table's three-byte `8d 49 00` pad and the case-body *order* (0,1,4,5,6,7,8,9,2,3).
**Five of the ten case bodies reproduce retail's marshalling instruction for
instruction** (0x00443080, 0x00443290, 0x00443F80, 0x004445C0, 0x00444760 - their
`push ecx; mov esi,eax; call` / `push ecx; call` / `push eax; push ecx; call`
sequences are exact, only the shared epilogue's pops differ), and what remains of
the 147 differing bytes is three things: the guard's rejection block is
*duplicated* instead of tail-merged (+3 bytes; first difference at `0x004451CA`),
the dispatcher's saved-register pair is `ESI/EBX` where retail's is `ESI/EDI`, and
five case bodies (0x004436C0, 0x00443910, 0x00443FB0, 0x00444580, 0x00444CE0) do
not yet get retail's incoming register assignment.

**The waiting model lands.** With this cluster's dispatcher as a *definition* in
the same `/LTCG` link, `0x00409230` compiles to retail's 50 bytes with **0
differing bytes**, both call displacements included:

## Levers that turned out to matter (all measured)

1. **The switch's case order in the source is the case-body order in the image.**
   Retail lays the bodies out as 0,1,4,5,6,7,8,9,2,3; writing the `switch` in
   exactly that order dropped the differing-byte count from 168 to 147 and put
   the ten table entries in retail's relative order (they are now only shifted by
   the +3 guard bytes). A 0..9 `switch` orders the bodies 0..9.
2. **Anchors must not carry an explicit `__cdecl`.** With `extern "C" int
   __cdecl Name(...)` the pass keeps caller-cleanup stack arguments and every
   case body gains an `add esp,4` (`83 c4 04 5e 5b c3`); with the convention left
   to `/Gz` (`extern "C" int Name(...)`, symbol `_Name@8`) each callee cleans its
   own stack argument and the case bodies shrink to retail's `… pop; pop; ret`
   shape, which took the emitted size from 244 to **216**.
3. **Taking a parameter's address forces it onto the stack.** The shape that
   earns retail's `(entity ESI, manager stack)` for cases 0/4 is two live locals
   plus one call passing `(void*)&manager`: the manager then has a memory home by
   construction, and the entity — live across the calls and dereferenced on both
   sides of them — takes ESI.
4. **A single `entry_free(entity)` keeps the entity in EAX**, which is retail's
   `(entity EAX, manager stack)` for cases 2/8, and it is what case 4's 0x30-byte
   slot can afford: `entry_free(entity); entry_free((void*)&manager); return
   (int)entity->strip_count;` is 28 bytes.
5. **Both-parameters-on-the-stack (case 7) falls out of a body whose only uses
   are calls**: `entry_free((void*)1); entry_free(entity); entry_free(manager);`
   gives retail's `push eax; push ecx; call`.
6. The recovered `DrawStrip` body as an anchor is *not* enough on its own: in
   this cluster its own callees (`Flush`, `SyncRenderState`) are opaque bindings
   with their declared member conventions, so the pass re-conventions DrawStrip to
   `(entity EDI, manager ESI)` and the call site grows `push edi; mov edi,eax;
   mov esi,ecx` in front of retail's two pushes. The exact case 9 the wave-8 note
   measured came from the *render-batch* cluster, where DrawStrip's own call graph
   is a set of definitions.

    case 2: return EntityDraw_00443290(entity, manager);
    case 3: return QuadDrawCheckedAlt_00443910(manager, entity);
    }

}

## For whoever picks this up

The five helpers are the same wall one level down: their incoming register
assignment is chosen by the pass from *their* bodies, and the two levers that
worked here are "which values are live across which calls" and "whose address is
taken". Cases 1/3 want `(manager ECX, entity EDX)` with no stack argument — a body
whose entity use ends before its first call, leaving EDX free for it. Cases 5/6
want the two saved-register homes the other way round from every body tried here.
0x00444CE0 needs its own callees (`Flush` at 0x00442F50, `SyncRenderState` at
0x004425A0) to be definitions in the same link, which is what the render-batch
cluster (`layout/ltcg/anm_batch_flush_00442f50.json`) already provides — merging
this region into that cluster, as the wave-8 note proposed, fixes case 9 at the
cost of that cluster's own `DrawStrip` depending on the merge staying stable.
