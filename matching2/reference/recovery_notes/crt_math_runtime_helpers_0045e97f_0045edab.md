## `__handle_qnan1` — `0x0045E97F` (83 bytes)

Ghidra identifies a `__cdecl` helper returning in x87 `ST(0)`. Its first
direct caller is `__floor_default` at `0x00458C8A`. The caller passes error
code `0x0B`, the input `double`, and a third stack word containing the control
word value saved earlier by `__ctrlfp`; the third parameter is read at
`[EBP+0x14]` even though Ghidra's prototype currently omits it. The helper
branches on `data_00473C90`: one path calls `__umatherr`, while the other sets
`errno` to `0x21`, restores the saved floating-point control word through
`__ctrlfp`, and loads the input into `ST(0)`. This couples math-error handling,
errno, the x87 control word, and an extended-precision return. Keep the row in
assembly until those runtime interfaces have typed semantic definitions.

## `__frnd` — `0x0045EBBA` (17 bytes)

Ghidra reports a `__cdecl` helper taking one stack `double` and returning
through x87 `ST(0)`. The body executes `FRNDINT` on that value, stores and
reloads it, and is called by `__floor_default` at `0x00458CBF`. `FRNDINT` uses
the caller's x87 rounding-control bits and updates x87 exception status; a
standard C++ rounding function does not promise the same rounding mode,
exception flags, or extended-register result. Keep the assembly.

## `__set_bexp` — `0x0045EC34` (37 bytes)

Ghidra reports a `__cdecl` helper taking a stack `double` and a short integer,
with the floating result in `ST(0)`. The body round-trips the input through
x87, then replaces the binary64 exponent field from the integer argument
while preserving the other bits. No direct caller or xref was found. A
bit-only C++ rewrite would move the first x87 load until return; for a
signaling NaN whose replacement exponent is finite, that would skip the
invalid-operation flag generated by the original initial load. Keep the
assembly to preserve that x87 behavior.

## `__sptype` — `0x0045EC59` (91 bytes)

The entry is a conventional `__cdecl` classifier: the caller at
`__floor_default` (`0x00458C6A`) passes the binary64 value as two stack words
and consumes the result in `EAX`. The body uses only integer instructions and
does not touch the x87 stack, control word, or status word. It returns `1` for
positive infinity, `2` for negative infinity, `3` for a quiet NaN, `4` for a
signaling NaN, and `0` for all other values. The replacement in
`src/unidentified/sptype_0045ec59.cpp` reads the parameter's object bytes and
performs the same masks and tests without evaluating it as floating point.
The manifest now promotes the region to semantic C++ with the prior assembly
record retained; the shared declaration reflects the two-word stack argument
and integer return. Byte-exact code generation remains unverified.

## `FUN_0045EDAB` — `0x0045EDAB` (86 bytes)

Although Ghidra currently labels the signature as `void(void)`,
`__raise_exc` calls this helper at `0x0045E668`, `0x0045E682`, and
`0x0045E6A4` after pushing masks `1`, `4`, and `8`; the caller removes each
argument itself. After saving two scratch words, the helper reads the mask
from the stack. Depending on its bits it performs x87 integer conversion,
large/tiny extended-to-double stores, division by zero, and a `FLDPI` to raise
the corresponding x87 exception status. The large and tiny constants are at
`0x00473DA8` and `0x00473DB4`; the helper also samples the x87 status into
`AX`, and `__raise_exc` subsequently reads floating-point state. These are
deliberate exception-generation operations, not ordinary numeric results, so
keep the assembly.
