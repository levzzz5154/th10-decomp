# Process spawning at `0x00436570`: rooted LTCG residual

2026-09-27. A readable typed model is retained in
`matching2/build/experiments/process_spawn/msvc/src/platform/process_spawn_00436570.cpp`,
with its unique record/import header at
`include/th10/platform/process_spawn_00436570.hpp` below that scratch project.
The complete retail region is 201 bytes; the model emits **204 bytes** under
both the normal maintained compilation profile and rooted native `/GL` +
`/LTCG`. It is not exact and must not replace the maintained assembly yet.
No maintained source or manifest was changed in this investigation.

## Established behavior and ABI

Live Ghidra MCP reads are retained as `ghidra_decompilation.txt` and
`ghidra_disassembly.txt` under the experiment. The entry is expressible by
ordinary C linkage `__fastcall`:

```cpp
int __fastcall Platform_LaunchProcess_00436570(
    void* ignored_ecx, char* command_line,
    const char* application_name, int wait_for_exit);
```

ECX is unused, EDX carries the mutable command line, the application name and
wait flag occupy entry stack offsets `+4/+8`, and the routine returns with
`RET 8`. The symbol is `@Platform_LaunchProcess_00436570@16`. Live Ghidra
reports no incoming direct references, so no grounded real caller was
available to replace the synthetic array context.

`PROCESS_INFORMATION` is an uninitialized output record of 16 bytes.
`STARTUPINFOA` is 68 bytes, with its normal x86 Win32 field offsets. The
compiler assertions in the unique header validate these two sizes. Retail
reserves exactly `0x54` bytes for both records. The startup record sets
`cb=0x44`; four geometry fields to `0x80000000`; character counts to
80 and 25; `wShowWindow=10`; and all remaining fields to zero.

The model calls the true stdcall import declarations of `CreateProcessA`
and `GetExitCodeProcess`, bound at IAT slots `0x004660E0` and `0x004660E4`.
It passes creation flags `0x20`. It returns -1 if creation fails, 0 if
creation succeeds without waiting, or the process exit code after busy
polling while the code remains `0x103`. It ignores the polling API's BOOL
result. Neither returned handle is closed in this function.

The shared `windows_types.hpp` declarations of these APIs lack `dllimport`;
MSVC rejects a later imported redeclaration as C2375. The unique header
therefore contains the two exact record layouts and imported prototypes,
without changing the shared header or introducing macro-renamed API aliases.

## Current residual

Retail schedules:

```text
lea eax,[esp+4]       ; process output record
push eax
mov eax,[esp+60h]     ; application name, loaded early
lea ecx,[esp+18h]     ; startup record
push ecx
... remaining arguments ...
push edx             ; command line
push eax             ; application name
```

The compiler delays the application-name load until its final push:

```text
... arguments ...
push edx
mov edx,[esp+80h]
push edx
```

The early retail load needs a one-byte stack displacement, whereas the late
load needs a four-byte displacement. This accounts for the entire three-byte
extent difference. Retail also loads the polling process handle into EDX and
the output pointer into ECX; the model uses ECX and EAX respectively. The
poll loop's exit-code load into EAX, comparison with `0x103`, block order,
frame layout, field-store order, import hoist, and returns otherwise have
the expected instruction shapes.

The first mismatch is at retail `0x00436590` (`+0x20`). A native comparison
of the overlapping 201 bytes finds 164 differences because all later
instructions are displaced by the longer setup. This byte count is not a
measure of semantic difference. Full source and full native bodies remain
available; no shortened prefix or masked-byte claim was used.

## Fresh experiments and retained evidence

- `plain3.json` and `final_plain_probe.json`: normal probes reject the model's
  full 204-byte contribution against the required 201 bytes.
- `native1.json`: rooted public-ABI native LTCG baseline. MAP shows a
  `0xCC`-byte `.text$01accessor` contribution, the correct selected public
  fastcall symbol, and real import bindings. Its longer contribution moves
  the declared context, so the strict layout validator correctly rejects it.
- `native1.bin`, `retail.bin`, and `measured_residual.json`: complete bodies
  and the explicit extent/byte mismatch.
- `shape_results.json`: eight normal-build variants all emit 204 bytes:
  reusing the application parameter as the exit-code output; original Win32
  `unsigned long` DWORD spelling; mutable application pointer; aggregate
  startup initializer; geometry-first assignments; address/lvalue application
  load; copied application local; and nested wait branch.
- `native_shapes.json`: three rooted LTCG variants with a force-inlined
  process-start wrapper, reversed-argument poll wrapper, or both also emit
  the same 204-byte body and 164 overlapping byte differences.
- Source/header snapshots and assembly listings are under each corresponding
  `plain_*` or `native_*` directory.

A successful future source/compiler lever must hoist the application load
before enough outgoing arguments make its displacement exceed `0x7F`, retain
EAX through the final push, and reproduce the polling call's EDX/ECX loads.
Synthetic rooted LTCG context and the tested ordinary argument wrappers did
not provide that lever. The current scratch project excludes the optional
LTCG cluster and retains the straightforward typed baseline for another pass.
