## What the region is

Retail walks the linked record list rooted at `this+0x18`, evaluates every
record that is not retired (type word at `+0x0C` == 1 is skipped) through the
virtual evaluator in vtable slot 7 (`[vtable+0x1C]`), and returns the sum.  It
first copies the caller's three-component vector into the record area at
`this+0x440` — a 12-byte aggregate copy, emitted as integer loads/stores, not
x87.

vector is live in EBX only because the callers had just passed the same vector

(`0x405B38: pop ebx; xor eax,eax` etc.), so the EAX return is only visible in the
body's own bytes.

0x10(%esp),%ebp` (float cached in EBP across the evaluator call, the same choice
retail made), `mov 0x14(%esp),%edx` per iteration (int flag reloaded from the
stack), `push %edx; push %ebp; push %ebx; call *0x1c(%eax)`, and `mov

`sha256 = 6ebb1b3a212e9167…` for both.

## The two load-bearing model details

1. **The first stack parameter must be declared `float`.**  The float is what
   makes the whole-program pass hold that parameter in the callee-saved EBP
   across the evaluator call; retail's `push ebp` is sunk into the loop guard and
   the value is loaded once at `0x41C823`.  With `int` in that position the pass
   instead caches the *other* parameter and pushes EBP in the prologue (43 bytes
   of the 76 differ, see below).  The float model is also what the callers say:
   `[ESP+4]` is a score value (an x87 result in three of the four call sites) and
   `[ESP+8]` is a 0/1 flag.
2. **The record type must itself be the polymorphic class** (vptr at `+0x00`,
   data at `+0x04`, evaluator in slot 7).  A record that *points at* a
   polymorphic vtable object compiles the call as a double indirection
   (`mov (%eax),%edx; call *0x1c(%edx)`) and costs 89 bytes.

Nothing else was needed: no roots, no externals, no constant aliases.  The only
`absolute_symbols` entry is the usual `{"symbol": "__fltused", "address":
"0x00000000", "kind": "metadata"}` that a float model requires.
