## Recovered behavior

Both trims retain the original XYZ origin, zero a 256-byte stack mask, initialize step Z before the XY-only public SetPolar call, reset initial point Z, and subsequently update all three point components. They start at six units and advance by twelve. Unlike the splitters, the initial `12 <= length` and continuation `progress + 6 <= length` tests are inclusive and ordered. The exact 12-unit case therefore samples once. The bounded maximum 3,072-unit case uses all 256 mask entries. Buffer overflow behavior beyond that domain was not tested or silently repaired.

Rectangle selection uses inclusive X/Y boundaries with the original unordered rejection behavior. Circle selection squares the radius and accepts unordered distances/radii. Item creation precedes the sample animation. Rectangle visibility executes the complete public bounds member; circle visibility uses the original four viewport comparisons. The animation uses the **line-laser script at +44A**, not the beam script at +466. The typed creator/registrar paths preserve the real hidden animation-ID result and complete object allocation, flags, bucket, offset position, script loading and tail registration.

No hits leave the laser unchanged. Selecting every sample marks the existing byte at +50 as retired and returns the hit count. Otherwise a selected prefix advances the current XYZ origin by the complete step times the prefix count, subtracts twelve times that count from length, and retires the laser if the reduced length fails the `> 18` test. A surviving prefix updates the saved creation length at +434 and traveled distance at +4C. The first surviving run shortens current length and adjusts the saved creation length; a run shorter than 18 marks the current laser retired.

Every subsequent unselected run first copies the **entire 476-byte parameter record from owner +424**, then replaces its two length fields. Only runs longer than 18 create a new laser. Their XYZ position uses the saved original origin plus the full step times the original sample index; spawn selector is zero. All other source-record bytes, including unmodeled/reserved values, are copied. This differs materially from both the zeroed records of the splitters and the archived legacy draft's live-object clone abstraction. The tested owner view spans 600 bytes so that the entire original record participates in comparison.

## Rounding correction and compiler controls

The first rectangle and circle drafts failed deterministic finite cases at the prefix position's Y word. Rectangle fixture case 215 produced `65.27652740478516` instead of retail's `65.27653503417969`; circle case 192 produced `179.00257873535156` instead of `179.0025634765625`. Initial failures are saved with complete inputs and state differences.

Staging one shared `float first` for both position multiplication and removed length let MSVC retain the Y product in x87 precision through its addition. Repeating the integer-to-float conversion in the two original arithmetic expressions restores the retail temporary spills and rounding. Both corrected maintained graphs then pass every case. The rectangle's complete emitted arithmetic and run handling now match retail, leaving only the prologue scheduling residue.

Expressing the later run comparison as `run_length > 18`, keeping the prefix survival stores in the positive branch, and returning the actual hit count from the retired prefix path also recover the rectangle's required extent, stack homes and branch layout. It progressed from 1,273 bytes / 36 groups / 288 differences to 1,269 bytes / two groups / 13 differences. Constructors, copy assignment, named vector temporaries, pointer/reference inputs, mask types, cached position references, source guard shapes, and real typed creator inlining were measured as controls. They do not improve the chosen rectangle result. Some remain much shorter/longer or fail behavior, so their existence is not success evidence.

Typed creator automatic inlining was tested with the complete real public body and regressed the circle results. Forceinline declarations without a visible definition failed linking at the real creator symbol; those controls are recorded as failures. No placeholder was introduced to satisfy them. The selected graphs keep the complete ordinary supporting routines. The full 98-byte base constructor, 203-byte script loader and 118-byte registrar match in the rectangle graph, as does the 91-byte bounds routine; those already-recovered routines receive no additional credit. Other unselected helper bodies still differ.
