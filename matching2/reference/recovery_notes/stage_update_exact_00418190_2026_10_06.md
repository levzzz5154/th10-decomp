## Complete behavior

The callback preserves the frame-zero failure exit, stage quad-script start,
fade setup, immediate reset, and frame-30 delayed reset. Both reset paths
clear bullets, reset the player, wipe the effect arena, clear enemies and the
score chain, finish the replay stage, create the initial enemy, initialize the
HUD, pause the original task groups, and queue the appropriate music and
animation changes. Required and optional task pointers retain their original
individual null checks; the third task at manager +0x37AC is required.

Fade disposal calls the existing 499-byte destructor at 0x00402440 through its
actual stack convention, followed by the existing deallocator. The destructor
owns the global-pointer clearing. The callback's separate repeated global
read and inner guard preserve the original null check before both operations.

The later paths retain context flag 4's early return, worker shutdown, result
selection, effects at frames 2940 and 3000, the full HUD update, and three
separate return-3 tests for flags 0x10, 0x20 and 0x40. Replay recording increments
the character/shot record's frame counter at stride 0x437C and offset 0x4CC,
up to 215999999. Gauge decay retains all three original prerequisites. Both
global frame counters increment before the context timer tick and return 1.

## Source decisions that resolved matching

An early complete graph emitted 1,552 bytes, with the context in EBP and an
early zero in EBX. Keeping the delayed music-command alternatives as two
ordinary conditional calls reproduced the original branch and the callback's
register allocation. This produced 1,540 bytes with only the disposal guard
missing. A repeated global read followed by an explicit guard around both
existing destruction and deallocation calls produced all 1,544 bytes.

These are source changes. No register bridges, synthetic escape calls,
compiler-output instruction edits, branch repairs, copied byte bodies, or
comparison masks were introduced.
